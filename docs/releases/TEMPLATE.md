# Шаблон выпуска

[Правила](RULES.md) · [Каталог](INDEX.md).

Создать отдельный файл с выбранным идентификатором выпуска в имени.
Этот документ — инструкция по заполнению; он не является выпуском.

## Шапка нового документа

Указать общий набор полей: id, type, status, scope, authority.
Для нового плана выбрать type release, status draft, authority supporting.
Добавить opened-on с фактической датой открытия.

## Цель

Записать конкретный результат, ради которого задачи объединены в выпуск.

## Состав

Создать таблицу «Задача | Причина включения». В первой ячейке каждой строки
поставить ссылку на существующую задачу с её полным id в тексте ссылки.
У каждой включённой задачи установить release равным id выпуска.

## Критерии выхода

Записать проверяемые критерии списком с флажками. Указать необходимые
тесты, целевое окружение и способы проверки результата. После выполнения
каждого пункта добавить подтверждение после « — ».

## Не входит

Перечислить соседние задачи и изменения, сознательно оставленные за границей.

## Результат

Заполнить после развёртывания: окружение, коммит, версии затронутых компонентов,
результаты проверок. Для закрытия установить status released и добавить
released-on и commit в метаданные.

Пересобрать оба каталога и выполнить docs-check согласно правилам.
