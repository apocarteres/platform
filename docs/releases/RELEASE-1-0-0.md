# Выпуск 1.0.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Миграция потребителя

Выпуск мажорный: обе перемены ломают потребителя, старый контракт рядом с новым
не сохраняется (`REQ-PUBLISHING-004`, `REQ-PUBLISHING-005`). Переход
выполняется одним изменением на проект.

1. Расписка о проверках — обязательство `observed-receipt`. Задача `verify`
   становится одним шагом: `conventions receipt --checks <наборы> -- <команда
   набора>`. Прежняя форма с перечнем наборов после прогона отвергается с кодом
   2 и файла не создаёт, поэтому набор упадёт громко, а не запишет расписку
   молча. Расписка теперь несёт наблюдённую команду и её код возврата, а
   закрытие выпуска отвергает расписку без этого признака.
2. Java 25 — обязательство `java-25`. Ядро собирается на Java 25 и публикует
   класс-файлы версии 69, которые сборка на Java 21 не читает. Потребитель
   поднимает версию Java в конфигурации менеджера окружения и цель компиляции в
   манифестах, а также в образах сборки и развёртывания.

Оба обязательства уровня «директива» со сроком один выпуск: при открытии
следующего выпуска потребителя они материализуются задачами, а по истечении
срока закрытие выпуска блокируется (`REQ-RELEASE-013`, `REQ-RELEASE-014`).

## Состав

Обязательств ядра к исполнению нет; состав наполняется по факту закрытия задач.

## Критерии выхода

- [ ] Набор `verify` пройден на выпускаемом коммите — расписка получена командой выпуска
- [ ] Тег выпуска создан на проверенном коммите — ставится командой выпуска
- [ ] Обязательства ядра этого выпуска закрыты или перенесены записью с причиной

## Не входит

Задачи, не закрытые к моменту закрытия выпуска: они попадут в состав следующего по факту закрытия.

## Результат

Заполняется при закрытии из расписки о проверках.
