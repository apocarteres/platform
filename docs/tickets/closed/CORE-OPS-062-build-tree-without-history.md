# Дерево сборки без истории роняет проверки непонятным отказом

## Проблема

Сборка в контейнере получает дерево исходников. Если оно приходит распакованным
архивом, проверки, читающие историю, отказывают — и отказывают непонятно: в
сообщении команда `git`, а не причина.

У потребителя так отказал сканер секретов: он читает историю, а дерево пришло
из `git archive`. Сообщение было про секреты, причина — про историю.

У ядра то же самое и проверяется мгновенно:

```
$ conventions commits
Коммиты прочитать не удалось: Command failed: git -C /tmp/noHistory log --name-only ...
```

Отказ называет команду, а не причину, и не называет выхода — то есть нарушает
`REQ-QUALITY-005` и `REQ-RELEASE-039` разом.

Второе свойство из той же обвязки: окружение прогона закрыто. Переменная
составляющей, оставленная в окружении, протекает в набор проверок. У
потребителя так упали тесты настроек агента.

## Чем подтверждено

Заявка потребителя [issue #24](https://github.com/apocarteres/platform/issues/24),
находки 5 и 6 его холодного прогона. Обе воспроизведены: первая — на дереве из
`git archive`, вторая описана им самим в обвязке.

## Что сделано

Команды ядра, читающие историю, узнают дерево без репозитория и называют
причину сами:

```
Дерево сборки не репозиторий: истории в нём нет. Проверки, читающие историю,
на таком дереве отказать обязаны, и это не их дефект. Дерево сборки
загружается репозиторием — например git bundle, — а не распакованным архивом
```

Отказ говорит три вещи, которых прежде не было ни одной: причину, что
отказавшая проверка не виновата, и выход.

`REQ-BUILD-012` записывает оба свойства сборочной обвязки. Первое — дерево
загружается средствами, переносящими историю. Второе — окружение прогона
закрыто: в него входит только общее, а переменные составляющей задаёт
вызывающий в самой команде, иначе они протекают в набор проверок и роняют то, к
чему отношения не имеют.

## Чем закреплено

Четыре проверки. Решающая утверждает **обе стороны отказа**: причина названа,
вина с проверки снята, выход указан — и команда `git` в сообщении не
показывается. Отдельная проверка убеждается, что на настоящем репозитории
признак дерева работу не подменяет.

Различающая сила подтверждена снятием признака: проверка отказала.

## Чего здесь нет

Второе свойство — закрытое окружение — проверкой не закрепляется: какие
переменные принадлежат составляющей, ядру неизвестно. Записано требованием с
обоими случаями потребителя как основанием, и это честнее, чем проверка, которая
угадывала бы.
