# Работа через pull request

Норма — [`REQ-PROJECT-PROCESS-023`](../requirements/project-process.md) и
[`REQ-TICKETS-022`](../requirements/tickets.md); здесь — порядок действий для
команды без права коммита в `main`. Идентификаторы ниже — образец.

## Участник

1. Перебазировать ветку на свежий `main`: задачи сверяются с тем, что в нём.
2. Если задача уже есть в `docs/tickets`, взять её идентификатор. Если нет —
   завести файл задачи в этом же PR со следующим свободным номером области,
   например `docs/tickets/SHOP-OPS-031-retry-export.md`, и выполнить
   `conventions tickets-index`.
3. Каждый коммит начинать с идентификатора: `SHOP-OPS-031 Retry the export on timeout`.
4. Отправить ветку в свой форк. Хук `pre-push` откажет, если названной
   задачи нет на вершине ветки, и назовёт коммит.
5. Открыть PR.

## Номер занят параллельным PR

После перебазирования на `main` проверка документации называет повторный
идентификатор. Тогда:

```sh
conventions tickets-renumber SHOP-OPS-031 --base main
git push --force-with-lease
```

Команда даёт своей задаче следующий свободный номер, правит ссылки в файлах
ветки и сообщения её коммитов и записывает перенос отдельным коммитом. Ветка
должна быть линейной и без незакоммиченного.

## Мейнтейнер

- Слияние коммитом слияния задачи не требует: её несут коммиты PR.
- При слиянии squash заголовок начинается с идентификатора задачи PR.
- При закрытии выпуска задача PR уже лежит в репозитории и входит в состав.
