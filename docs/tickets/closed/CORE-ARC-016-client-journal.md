# Журнал клиента: пакет `@apocarteres/client-journal`

## Проблема

Отказ, о котором человек пишет в поддержку, разбирают по его словам: что он
нажал, какой вызов не прошёл, какая ошибка была в клиенте — неизвестно.
Потребитель решил это сам журналом клиента: сетевые вызовы, переходы,
необработанные ошибки, маскирование до записи, предел объёма. Код почти не
связан с проектом — из проекта он берёт только часы. Второй проект с живыми
пользователями пишет такой журнал заново, и правила маскирования у каждого
свои.

## Подтверждение

Журнал потребителя разобран по коду при исследовании CORE-ARC-012
(ADR-0007): 127 строк клиента, тесты маскирования, предела и исключённых
путей. Решение владельца от 2026-09-24 — первый шаг центра поддержки.

## Последствия при сохранении текущего поведения

Каждый проект пишет журнал сам; маскирование персональных данных до записи
у кого-то есть, у кого-то нет, и сервер центра поддержки (CORE-ARC-017) не
может полагаться на одно правило с клиентом.

## Требуется

1. `provideClientJournal({ storageKey, limitBytes, skip })` — объявление
   один раз; `clientJournalInterceptor` для `withInterceptors`.
2. Записи: сетевой вызов — метод, путь, статус, длительность, код отказа
   ядра; переход — путь; необработанная ошибка — имя и сообщение.
3. Не пишутся тела, заголовки, строка запроса и фрагмент адреса.
4. Маскирование до записи: почта, маркеры от 20 знаков, телефоны. Примеры
   лежат общим файлом, чтобы сервер центра проверялся по тем же.
5. Хранилище вкладки: журнал переживает перезагрузку и стирается с закрытием
   вкладки; предел по умолчанию 128 КБ, при переполнении вытесняются самые
   старые записи; отказ хранилища не ломает клиент.
6. Журнал не покидает браузер сам: его отправляет проект, и `entries()`
   отдаёт записи для этого.
7. Время — портом часов (`REQ-TYPESCRIPT-CLOCK`).
8. Требование `REQ-CLIENT-JOURNAL`.

## Критерии приёмки

- Тесты пакета на каждое положение требования, включая общие примеры
  маскирования.
- Пробы намеренной поломкой: снятое маскирование, строка запроса в пути,
  отсутствие вытеснения, запись исключённого пути — каждую ловит тест.
- Пакет собирается и входит в локальную поставку ядра.

## Что сделано

- Пакет `@apocarteres/client-journal`: `provideClientJournal`,
  `clientJournalInterceptor`, `ClientJournal` (`entries`, `record`, `clear`),
  `JournalErrorHandler`, порт часов `JOURNAL_CLOCK`, хранилище
  `JOURNAL_STORAGE`, `masked` и `barePath`.
- Требование `REQ-CLIENT-JOURNAL-001…010`.
- Общие примеры `packages/client-journal/masking-vectors.json` — по ним
  проверяется пакет, по ним же будет проверяться сервер центра (CORE-ARC-017).
- Отличия от журнала потребителя: исключение пути по целым сегментам, а не по
  началу строки; предел работы маскирования — 4096 знаков до маскирования;
  записи чужой формы из хранилища отбрасываются; настройки проверяются при
  объявлении; код отказа читается и из ответа, и из уже разобранной ошибки
  ядра.
- Найдено тестом: текст, приклеенный к почте без пробела, маскируется вместе с
  ней. Маскируется лишнее, а не меньшее — оставлено и записано общим
  примером.
- Пакет подключён к проверке правил ядра; при этом найден пропуск девяти
  модулей (CORE-QUAL-026).

## Чем закреплено

- 21 тест пакета: общие примеры, объявление, каждый вид записи, маскирование
  в хранилище, предел и вытеснение, отказ и повреждение хранилища,
  исключённые пути, обработчик ошибок и его наследник, выдача.
- 21 проба намеренной поломкой — все пойманы: снятое маскирование и его
  предел, строка запроса и источник в пути, отсутствие вытеснения, неукороченное
  сообщение, неперехваченный отказ хранилища, чужие записи, исключение не по
  сегментам, обработчик без передачи дальше и без подмены, путь до
  перенаправления, время мимо порта, потеря кода и статуса отказа, запись
  исключённого пути, непроверенные настройки, `clear` без очистки.
- Тест положений о поведении (`REQ-QUALITY-017`) охватывает
  `REQ-CLIENT-JOURNAL`; проба — снятая ссылка на положение 009 — поймана.
  Шаблон префиксов в этом тесте был записан дважды и сведён к одному.
