# Комментарии в коде: контракт проверки

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

## Правило

1. <a id="REQ-CODE-COMMENTS-000"></a> **REQ-CODE-COMMENTS-000** — Пояснительный текст в комментарии запрещён. Комментарий допустим только как ссылка на документ: идентификатор решения, требования или задачи, при необходимости с путём к файлу.

Причина решения записывается в решение или требование, а код несёт ссылку на его идентификатор. Объяснение в комментарии стареет вместе с кодом и никем не проверяется; документ имеет идентификатор, состояние и историю, а ссылки на него проверяются автоматически.

## Что проверяется

1. <a id="REQ-CODE-COMMENTS-001"></a> **REQ-CODE-COMMENTS-001** — Проверка охватывает исходные файлы с расширениями `.java`, `.ts`, `.mjs`, `.js`. Каталоги сборки, зависимостей и сгенерированного кода исключаются; перечень исходных каталогов и исключений задаётся файлом `.conventions.json` потребителя.
2. <a id="REQ-CODE-COMMENTS-002"></a> **REQ-CODE-COMMENTS-002** — Комментарием считается строчный или блочный комментарий вне строкового литерала и вне текстового блока. Подряд идущие строчные комментарии считаются одним комментарием.

## Что допустимо

3. <a id="REQ-CODE-COMMENTS-003"></a> **REQ-CODE-COMMENTS-003** — Комментарий допустим, если после удаления идентификаторов документов и путей к документам в нём не остаётся слов, кроме связок «см.», «see», «ref». Идентификатором считается последовательность заглавных букв и цифр с дефисом: `ADR-0002`, `REQ-PERSISTENCE`, `REQ-PERSISTENCE-006`, `SEC-008`.
4. <a id="REQ-CODE-COMMENTS-004"></a> **REQ-CODE-COMMENTS-004** — Машинные директивы не являются комментариями и допустимы всегда: `noinspection`, `eslint-*`, `prettier-ignore`, `@ts-*`, `<reference`, `istanbul`, `c8`, `v8`, `language=`, `nosemgrep`, `checkstyle`, `@formatter`.
5. <a id="REQ-CODE-COMMENTS-005"></a> **REQ-CODE-COMMENTS-005** — Любой иной текст в комментарии является нарушением, включая описание параметров, возвращаемого значения и отметки `TODO`.

## Существующий код

6. <a id="REQ-CODE-COMMENTS-006"></a> **REQ-CODE-COMMENTS-006** — Существующие нарушения фиксируются храповиком в файле `.conventions/comments-baseline.json` как число нарушений на файл. Проверка отказывает, если число в файле превысило зафиксированное или нарушение появилось в файле, которого нет в храповике.
7. <a id="REQ-CODE-COMMENTS-007"></a> **REQ-CODE-COMMENTS-007** — Первичное засеивание храповика разрешено без дополнительных ключей: подключение правила не ломает сборку потребителя. Последующий подъём числа требует явного ключа `--allow-growth`.
8. <a id="REQ-CODE-COMMENTS-008"></a> **REQ-CODE-COMMENTS-008** — Снижение числа нарушений не является отказом; проверка сообщает о возможности опустить храповик.

## Блок правил в AGENTS.md

9. <a id="REQ-CODE-COMMENTS-009"></a> **REQ-CODE-COMMENTS-009** — Текст правил вписывается в `AGENTS.md` потребителя между маркерами `conventions:begin` и `conventions:end` командой `sync`; проектные правила располагаются вне маркеров.
10. <a id="REQ-CODE-COMMENTS-010"></a> **REQ-CODE-COMMENTS-010** — Проверка отказывает, если блок отсутствует, версия в маркере не совпадает с версией установленного пакета либо содержимое между маркерами изменено вручную.
