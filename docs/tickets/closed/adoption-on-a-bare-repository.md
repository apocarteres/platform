# Подключение к проекту без каталогов документации падало трассировкой

## Проблема

Порядок подключения был записан ([REQ-ADOPTION](../../requirements/adoption.md)),
но выполнить его в проекте, у которого ещё нет каталогов документации,
было нельзя: команды падали не отказом с объяснением, а трассировкой Node.

## Подтверждение

Проверено на пустом проекте (git, один файл исходников, `.conventions.json`,
`AGENTS.md`, поставка пакета в `node_modules`):

- `conventions release adopt` — `Error: ENOENT ... docs/releases/RELEASE-2026-09-1.md`;
- после создания каталога вручную — `ENOENT ... docs/tickets/closed/INDEX.md`;
- `conventions docs-check` — `ENOENT ... docs/REQUIREMENTS.md`.

Отказ трассировкой не называет ни файла, ни того, что делать: это нарушение
`REQ-QUALITY-005` в самом первом действии нового потребителя.

## Последствия при сохранении текущего поведения

Записанный порядок подключения невыполним по написанному, а первое
знакомство с ядром выглядит как сломанный инструмент. Восстанавливать
недостающую раскладку каталогов приходится по трассировкам.

## Ожидаемый результат

Принятие цикла создаёт каталоги, которые само же наполняет, и собирает их
сводки. Отсутствие сводки или входного документа каталога — названный отказ
проверки, а не исключение. После подключения `docs-check` перечисляет
оставшиеся документы каталога по одному.

## Критерии приёмки

- [x] Принятие цикла создаёт `docs/releases`, `docs/tickets`, `docs/tickets/closed` и собирает сводки задач и выпусков
- [x] Отсутствие `docs/INDEX.md` и сводок каталогов — названный отказ `docs-check`, а не трассировка
- [x] Скелет выпуска не ссылается на документы, которых у нового потребителя нет: правила названы положением `REQ-RELEASE`
- [x] Тесты: принятие цикла в репозитории без каталогов на уровне библиотеки и на уровне CLI — 75 тестов пакета проходят
- [x] Проверено измерением на пустом проекте: подключение по README доходит до `docs-check`, который называет 7 оставшихся файлов каталога
