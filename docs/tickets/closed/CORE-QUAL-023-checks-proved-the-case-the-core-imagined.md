# Проверки ядра доказывали случай, который ядро себе представило

## Проблема

Разбор заявок за 2026-09-11–22: шесть раз проверка ядра была зелёной при
неисполненном требовании. Причина каждый раз одна: проверялся тот случай,
который ядро держало в уме, а не тот, что у потребителя.

| заявка | что проверялось | что было у потребителя |
|---|---|---|
| #28 | архив классов | клиент — каталог |
| #33 | страницы значением | все страницы лениво загружаемые |
| #23 | Rust без времён жизни | время жизни ослепляло разбор |
| #25 | реестр, объявленный потребителем | реестр из автонастройки |

И всякий раз дефект находил потребитель — сверкой, а не отказом проверки.

## Решение владельца

Предложение 5 разбора принято. Решение владельца от 2026-09-23.

## Что сделано

Записано `REQ-QUALITY-016`.

Эталонный потребитель собирается в двух формах: **контейнеры** — модуль Java,
клиент, агент на Rust со временем жизни, образ; **служба на хосте** — модуль
Java, клиент, настройка веб-сервера с признаком точного совпадения у API и
описание службы, объявленные составляющими с местом и разбором. В обеих —
клиент с лениво загружаемыми страницами через порт ядра, манифест Java с
родителем ядра, вход развёртывания через разбор доводов ядром, доставленный
словарь.

Проверка перебирает все правила ядра: на чистой форме ни одно не находит
ничего; на копии формы с заложенным нарушением каждое его находит. Правило без
закладки на форме роняет проверку, если не названо, почему оно к форме не
относится. Новое правило без закладки выпуска не пройдёт.

## Что нашлось сразу

Сборка форм до первой закладки нашла две слепые зоны **самого эталона**:

- он не получал словаря, поэтому правила о терминах на нём ничего не проверяли;
- в нём не было манифеста Java, поэтому разбор Java проходил на нём впустую.

И одну — в поставке. Правило `terms-preferred` находит длинный оборот только
для толкований не длиннее трёх слов, а у словаря ядра таких толкований нет ни
одного. На поставляемом словаре правило не срабатывает ни у кого; срабатывает
оно лишь на коротких определениях самого потребителя — это и закреплено
закладкой. Поведение правила не менялось: это вопрос к словарю, а не к правилу.

Одна закладка оказалась неверной у меня: `Manager` входит в перечень
разрешённых существительных, и правило о суффиксе `-er` было право, что его
пропустило.

## Чем закреплено

Три проверки: у каждого правила есть закладка на каждой форме; форма
контейнеров чиста и каждая закладка находится; форма службы на хосте — то же.

Различающая сила проверена двумя возвратами: снятая закладка правила и
ослеплённое правило роняют проверку каждое своим утверждением.

## Откуда пришла задача

Разбор заявок потребителей за две недели, предложение 5.
