# Пропущенное поле `release` даёт лишний отказ и ссылку в никуда

## Проблема

Задача без поля `release` нарушает `REQ-TICKETS-009`, и проверка называет это
верно: «release должен быть unassigned, before-cycle или идентификатором
RELEASE-...». Но рядом шли ещё два отказа:

- «назначенный выпуск не существует», хотя выпуск не назначен вовсе;
- ссылка `../../releases/undefined.md` в сводке задач и отказ о ней.

Верный отказ тонул среди ложных: исполнитель читал «задаче нужен выпуск» и
ждал `release-open`, который ставит поле и снимает все три.

## Подтверждение

Выпуски ядра 11.4.0 и 11.4.1 (2026-09-25): задачи CORE-OPS-100 и
CORE-OPS-101 созданы без поля `release`. Причину сочли свойством цикла: верный
отказ был в выводе, но читались две последние строки, а там — ложные.
Воспроизведено 2026-09-25: четыре ошибки на одну причину.

## Последствия при сохранении текущего поведения

Одна причина — три отказа, из которых два неверны; верный теряется.

## Решение владельца

Заведено по согласию владельца от 2026-09-25.

## Требуется

1. Отказ о несуществующем выпуске — только для названного по форме
   `RELEASE-...`, но неизвестного выпуска.
2. Сводка задач не ссылается на выпуск, которого поле не называет.

## Критерии приёмки

- Тест первым: задача без `release` даёт ровно один отказ — о поле, — и
  сводка не содержит `undefined`. Тест падал до правки.

## Что сделано

- `release-model.mjs`: сверка с выпусками только для поля в форме
  идентификатора; `tickets-index.mjs`: «Не указан» вместо ссылки.
- Тест в `check-docs.test.mjs`; 3 пробы — все пойманы.

## Откуда пришла задача

Разбор выпусков ядра 11.4.0 и 11.4.1, 2026-09-25.
