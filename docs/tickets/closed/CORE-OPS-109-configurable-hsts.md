# HSTS цепочки API нельзя было настроить

## Проблема

Цепочка `/api/**` оставляла заголовки Spring Security по умолчанию и на
защищённый запрос отдавала `Strict-Transport-Security: max-age=31536000 ;
includeSubDomains`. Настройки не было. Если свой HSTS ставил прокси
проекта, браузер брал первый заголовок, то есть ядерный (RFC 6797, 8.1).

## Подтверждение

Заявка потребителя [issue #68](https://github.com/apocarteres/platform/issues/68)
(clanlog, ядро 13.2.1): nginx ставит сутки без поддоменов, а по ответам API
действовал год с поддоменами. Сверено 2026-09-30 по `platformApiSecurity`.

## Последствия при сохранении текущего поведения

Потребитель снимает заголовок ядра в прокси, мимо ядра.

## Решение владельца

Решение владельца от 2026-09-30: настройки с прежним умолчанием.

## Требуется

`REQ-AUTH-036`.

## Критерии приёмки

- Тесты первыми: по умолчанию — год с поддоменами и только на защищённый
  запрос; сутки без поддоменов по настройке; выключенный — без заголовка,
  прочие защитные заголовки на месте; настройки отвергают отрицательный срок.
  Тест настроек и тест настроенного срока падали до правки. Тест умолчания
  проходил сразу — он закрепляет прежнее поведение. Тест выключенного HSTS в
  красном прогоне не собирался (упал зависимый модуль); его красный шаг —
  проба P1.

## Что сделано

- `HstsSettings`, заголовки цепочки API; предупреждение при выключенном HSTS.
- 5 проб — все пойманы; одна сначала не собралась (Error Prone) и переписана.
- Прогоны шли на Mac через Docker в Lima `pulse`: сборочный контейнер с
  rootless Docker не работает (CORE-OPS-108).
