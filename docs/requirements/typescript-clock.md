# TypeScript: порт часов

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: TypeScript и JavaScript.** Документ задаёт средство исполнить [общее требование о времени](code-clock.md) в клиентском коде.

**Уровень требования: директива.**

## Порт

1. <a id="REQ-TYPESCRIPT-CLOCK-001"></a> **REQ-TYPESCRIPT-CLOCK-001** — Порт часов объявляется типом с методами `instant(): number` — миллисекунды эпохи — и `date(): Date`. Стандартного типа часов в языке нет, поэтому порт объявляет проект или библиотека ядра.
2. <a id="REQ-TYPESCRIPT-CLOCK-002"></a> **REQ-TYPESCRIPT-CLOCK-002** — Порт внедряется средствами приложения, а не импортируется как модуль-синглтон: подмена в тесте выполняется заменой зависимости, а не переопределением импорта.
3. <a id="REQ-TYPESCRIPT-CLOCK-003"></a> **REQ-TYPESCRIPT-CLOCK-003** — Рабочая реализация — единственный файл проекта, обращающийся к системным часам, и единственная запись в `clockAllowlist`. Пока ядро не поставляет реализацию, файл живёт в проекте; при появлении второго потребителя он переносится в ядро по [правилам доставки](rule-distribution.md).

## Тесты

4. <a id="REQ-TYPESCRIPT-CLOCK-004"></a> **REQ-TYPESCRIPT-CLOCK-004** — Тест подставляет реализацию порта с заданным значением. Подмена глобального `Date` и системного таймера запрещена: она действует на весь процесс и скрывает, какому коду время понадобилось.
5. <a id="REQ-TYPESCRIPT-CLOCK-005"></a> **REQ-TYPESCRIPT-CLOCK-005** — Значение времени в тесте задаётся из данных проверки, а не выводится из текущего момента. Выражение `новый момент минус час` возвращает зависимость от машины через арифметику.
