# Часы в Rust ядром не нормированы и не проверяются

## Проблема

Проект на Rust получает от ядра статический разбор и больше ничего. Правило
часов в Rust-код не смотрит вовсе: `SOURCE_EXTENSIONS` — это `.java`, `.ts`,
`.mjs`, `.js`, и на нём построены все правила, читающие код.

| Правило | Видит `.rs` |
|---|---|
| Часы | нет |
| Пояснительные комментарии | нет |
| Денежные величины на плавающей арифметике | нет |
| Суффикс `-er` | нет |
| Размер файла | да |

Из пяти правил, смотрящих в код, Rust видит одно, и то потому, что `.rs`
дописали в его собственный перечень расширений.

Хуже: попади `.rs` в общий перечень сейчас, `findClockCalls` применил бы к нему
набор вызовов JavaScript — там `extension === '.java' ? JAVA_CALLS :
SCRIPT_CALLS`. Правило молча проверяло бы не то.

## Ловушка, ради которой нужен отдельный документ

В Java и Rust смысл `Instant` противоположен:

| | Java | Rust |
|---|---|---|
| `Instant` | стенные часы, запрещён | монотонный счётчик, законен |
| монотонный счётчик | `System.nanoTime` | `Instant` |
| стенные часы | `Instant.now()` | `SystemTime::now()` |

Правило, перенесённое с Java механически, запретило бы законное и пропустило бы
запрещённое.

## Чем подтверждено

Проба: файл с `SystemTime::now()` даёт ноль находок у правила часов.

## Решение владельца 2026-09-17

Документ нужен. Проверка выражается настройкой clippy, а не своим разбором.

## Что сделано

Документ `rust-clock.md`, девять положений: порт типажом, передача значением, а
не из глобального состояния, перечень запрещённых вызовов, монотонный счётчик
как законное исключение, способ проверки, время в тестах и отказ нормировать
именование.

Запреты доставляются в `clippy.toml` полем `disallowed-methods` с причиной,
называющей требование. `std::time::Instant` в перечне намеренно отсутствует, и
это отсутствие объяснено в самом файле — иначе следующий читатель его «допишет».

### Почему настройкой разбора, а не своим движком

Разбор пользуется разрешением имён языка, поэтому не путает вызов с упоминанием
того же имени в строке. Своему движку ядра эта разница стоила отдельных
положений `REQ-CODE-CLOCK-006` и `REQ-CODE-CLOCK-009` и разбора литералов;
здесь она достаётся даром. Проверено на эталонном крейте:

| случай | исход |
|---|---|
| `SystemTime::now()` | ОТКАЗ с названной причиной |
| `Instant::now()` | ПРОХОД — монотонный счётчик |
| `"std::time::SystemTime::now"` в строке | ПРОХОД |

## Чем закреплено

Одна проверка на эталонном крейте, утверждающая все три случая сразу, и
отдельно — что отказ называет требование, а не только имя вызова.

Различающая сила проверена двумя пробами, и вторая важнее первой: снятие
запрета уронило проверку, но и **добавление запрета на `Instant::now`** — то
есть ровно тот механический перенос из Java, против которого написано
`REQ-RUST-CLOCK-005`, — уронило её тоже. Проверка защищает не только от
недостачи, но и от ошибки, которую этот документ существует, чтобы
предотвратить.
