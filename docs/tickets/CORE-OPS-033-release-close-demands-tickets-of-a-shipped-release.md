# Закрытие выпуска требует в состав задачи уже вышедшего выпуска

## Проблема

`release close` сканирует коммиты цикла и требует, чтобы задача каждого коммита
входила в состав закрываемого выпуска. Диапазон сканирования начинается не от
тега предыдущего выпуска, а раньше — судя по наблюдению, от коммита,
объявленного в `commitRuleSince`. В диапазон попадают коммиты, уже вышедшие в
составе закрытого выпуска, и закрытие требует указать их задачи второй раз.

Законного выхода у потребителя нет: `REQ-RELEASE-007` прямо запрещает указывать
задачу повторно — «Задача, уже отнесённая к выпуску, второй раз не указывается».
Выпуск не закрывается и не может быть закрыт штатными средствами.

## Чем подтверждено

Проект-потребитель `zavpn`, открытый выпуск `RELEASE-2026-09-11`.
`conventions release status` отказывает со строками:

```
Коммит 7af4fdfc относится к задаче ZAVPN-OPS-032 вне состава выпуска:
  «ZAVPN-OPS-032 Record the last core obligation as executed»
Коммит 16567a0f относится к задаче ZAVPN-OPS-032 вне состава выпуска:
  «ZAVPN-OPS-032 Turn on the commit-names-its-ticket rule»
```

При этом:

1. Оба коммита — предки тега `2026.09.10`:
   `git merge-base --is-ancestor 7af4fdfc 2026.09.10` истинно.
2. Задача несёт `release: RELEASE-2026-09-10` и `status: done`, то есть уже
   отнесена к выпуску и вышла в его составе.
3. `git merge-base --is-ancestor 79d85a93 7af4fdfc` истинно, а `79d85a93` — это
   значение `commitRuleSince` в `.conventions.json` потребителя. Отсюда
   предположение о диапазоне; проверяется чтением кода выбора диапазона в
   команде закрытия.

Пункт 3 — гипотеза о причине. Пункты 1 и 2 — наблюдение: закрытие требует
задачу, которую правило запрещает указывать.

## Последствия при сохранении текущего поведения

Первый же выпуск после объявления `commitRuleSince` закрыть нельзя, и дальше
каждый следующий будет тянуть за собой всё больше уже вышедших коммитов:
диапазон не сдвигается. Обход — правка состава вручную в обход правила или
подмена `commitRuleSince`, то есть потеря того самого правила, ради которого
поле введено.

## Ожидаемый результат

Диапазон коммитов цикла ограничен снизу предыдущим выпуском, а не
`commitRuleSince`. Коммит, вышедший в составе закрытого выпуска, закрытию
следующего не мешает.

Отдельно: сообщение об отказе называет, каким образом задачу полагается внести в
состав, потому что при повторно отнесённой задаче такого способа нет и
сообщение вводит в заблуждение.

## Критерии приёмки

1. Выпуск закрывается, когда в диапазоне после предыдущего выпуска нет коммитов
   задач вне состава, независимо от значения `commitRuleSince`.
2. Коммит задачи, уже отнесённой к закрытому выпуску, закрытию не мешает.
3. Тест закрепляет: два выпуска подряд при `commitRuleSince`, объявленном до
   первого из них.
