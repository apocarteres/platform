# Послабление для тестов оформляется исключением, которое некогда снять

## Проблема

`REQ-QUALITY-006` требует, чтобы исключение из проверки оформлялось задачей «с
указанием предмета, причины, компенсирующей меры и срока снятия». Для
тестового кода срока снятия не существует.

Подложный объект приходится передавать за сотрудника, которого тест не
задействует; ожидание идёт через другой держатель; подстановка `null` в тесте
часто и есть предмет проверки. Это не долг, который когда-нибудь вернут, а
постоянное свойство тестового кода. По нынешнему правилу потребитель обязан
завести задачу, которую никогда не закроет, — и правило приучает к тому, что
срок снятия пишется для вида.

Отдельная цена названа потребителем: без послаблений разбор начинает зажимать
тесты архитектурно, то есть диктовать устройство теста из соображений, к
предмету теста отношения не имеющих.

## Чем подтверждено

Заявка потребителя [issue #15](https://github.com/apocarteres/platform/issues/15),
ядро 1.19.0, задача потребителя `ZAVPN-QUAL-075`.

## Что сделано

Решение владельца 2026-09-15: `REQ-QUALITY-006` различает два предмета, которые
прежде назывались одним словом.

- **Исключение** — временное, со сроком снятия и компенсирующей мерой. Прежнее
  положение, остаётся без изменений.
- **Послабление для тестового кода** — объявленное постоянное свойство тестовой
  компиляции с записанной причиной, срока снятия не имеет.

Записаны два условия, без которых постоянное послабление было бы дырой:
объявляется один раз на набор тестовой компиляции, а не на месте употребления,
и на рабочий код не распространяется ни при каких условиях. Именно разделение
двух наборов делает его безопасным.

Названа и цена отсутствия послабления, потому что без неё положение читается как
поблажка: разбор начинает диктовать устройство теста из соображений, к предмету
теста отношения не имеющих.

Проверкой это положение не закрепляется и закрепляться не может: оно о том, что
считать дефектом постановки, а не о форме файла. Механическая его часть —
раздельная настройка рабочего и тестового наборов — проверяется в
`CORE-OPS-047`, где правило требует разбора для каждого объявленного набора
исходников.
