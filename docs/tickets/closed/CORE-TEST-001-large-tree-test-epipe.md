# Тест крупного дерева роняет verify ошибкой EPIPE

## Проблема

Вспомогательная `feed` в `large-tree.test.mjs` пишет ввод в stdin любого
процесса `git`, в том числе `git status`, который stdin не читает. Если
процесс закрыл stdin или завершился раньше записи, запись падает с `EPIPE`.
Обработчика ошибки у потока stdin нет, и необработанное исключение роняет
весь прогон.

## Подтверждение

2026-10-15, `verify` выпуска 15.5.1 на машине сборки: «not ok 200 —
незафиксированные файлы крупного репозитория читаются без отказа буфера»,
`write EPIPE`, `large-tree.test.mjs:20`. В прогонах 15.2.0–15.5.0 тест
проходил: это гонка. Детерминированно воспроизводится процессом, который
закрывает stdin и живёт дальше: `sh -c 'exec 0<&-; sleep 0.3'`.

## Последствия при сохранении текущего поведения

`verify` случайно краснеет на коде, который не менялся, и выпуск не
закрывается (`REQ-QUALITY-009`).

## Решение владельца

Нестабильный тест — дефект с задачей (`REQ-QUALITY-009`); исправляется в
выпуске, который он задержал.

## Требуется

Подача ввода выделена в `pipeTo`; `EPIPE` на stdin не роняет прогон, прочие
ошибки stdin — отказ.

## Критерии приёмки

- Тест первым: подача мегабайта процессу с закрытым stdin падала с `EPIPE`,
  после исправления отдаёт вывод процесса.
- Три прогона подряд зелёные; полный `verify` на машине сборки зелёный.

## Откуда пришла задача

Отказ `verify` выпуска 15.5.1, 2026-10-15.
