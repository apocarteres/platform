# Схема имён не знала об этапах плана функции

## Проблема

Схема имён описывала задачу, решение, требование, инструкцию, выпуск и сводку,
но не этап плана функции. Правило требовало от этапов имени вида
`<ОБЛАСТЬ>-<NNN>-<слаг>.md`, то есть предлагало заменить номер порядка в плане
на номер в области.

## Подтверждение

Переход потребителя на схему 2026-09-08: правило дало восемь расхождений на
каталоге плана регистрации пользователя, где этапы названы `01-…` … `08-…`
с идентификаторами `UR-01` … `UR-08`. Команда перехода эти документы не
переименовывала, а правило требовало переименования — то есть чистого
состояния достичь было нельзя.

## Последствия при сохранении текущего поведения

Проверка правил остаётся красной у любого проекта с планом функции, а
исполнение требования сломало бы порядок чтения плана: номер этапа в имени
файла — единственное, что задаёт последовательность в каталоге.

## Ожидаемый результат

Имя этапа — номер порядка и слаг; идентификатор — префикс плана и тот же
номер. Соответствие номера в имени файла и в идентификаторе проверяется.

## Критерии приёмки

- [x] Требование `REQ-NAMING-011` описывает каталог плана, головной документ и этапы
- [x] Правило проверяет этап по номеру порядка и сверяет его с идентификатором; область к этапам не применяется
- [x] Тест покрывает четыре случая: верное имя, имя без номера, расхождение номеров, идентификатор не по схеме плана
- [x] Проверка правил у потребителя после перехода чиста: 102 теста пакета проходят
