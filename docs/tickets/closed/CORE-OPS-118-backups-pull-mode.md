# Копии, которые забирает хранилище, не укладываются в порядок ядра

## Проблема

`REQ-BACKUPS-003…006` описывают только push: задание на хосте службы само
отправляет копию, пишет квитанцию, а `--check` идёт на рабочей среде. При
pull хост службы не знает, ушла ли копия, а квитанцию честно может написать
только хранилище. Требовать её на хосте службы — значит дать ему доступ к
хранилищу либо писать квитанцию до факта.

## Подтверждение

Заявка [apocarteres/platform#76](https://github.com/apocarteres/platform/issues/76)
проекта legacy-store (ядро 15.1.2), задача LS-OPS-017: pull выбран после
компрометации прежней рабочей среды; 2026-10-15 после переустановки хоста
службы забор копий два дня молча не работал, а дамп снимался исправно.

## Последствия при сохранении текущего поведения

Обязательство `backups` нельзя закрыть, не ослабив защиту, а отказ забора
не видит ни одна проверка.

## Решение владельца

Решение владельца от 2026-10-15: принять заявку; квитанцию пишет хранилище,
проверки делятся по сторонам.

## Требуется

1. `REQ-BACKUPS-010`: `mode: "pull"`, квитанция на хранилище со сверкой
   отпечатка `--source`, `--check` на службе — только задание,
   `--check --storage` — квитанции и восстановление. Уточнить
   `REQ-BACKUPS-009` и обязательство `backups`.
2. Инструкция `RUN-SERVICE-BACKUPS`: порядок для pull.

## Критерии приёмки

- Тест первым: режим объявляется и проверяется; служба не требует квитанции
  pull, но проверяет таймер; хранилище сверяет квитанции и восстановление и
  не проверяет таймер; несовпавший отпечаток не даёт квитанции; на
  хранилище без наборов pull проверять нечего.
- Пробы: служба требует квитанцию pull, отпечаток не сверяется, хранилище
  не проверяет восстановление, неизвестный режим принят — тесты падают.
