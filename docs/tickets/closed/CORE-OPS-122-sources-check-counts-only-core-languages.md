# Проверка источников считает только языки ядра

## Проблема

`conventions check` по `REQ-ADOPTION-009` отказывает, если в `sources` нет
файлов, к которым применяются правила. Но считает он только `.java`, `.ts`,
`.mjs`, `.js`, `.rs`, хотя правила ядра обходят те же источники и с другими
наборами: настройки `.yml`, `.yaml`, `.properties`, файлы `.py`, `.rb`,
`.html`, `.css`, `.scss`, шаблоны, а правила проекта — со своими
расширениями. Проект без языков ядра получал отказ «правила не применяются ни
к одному файлу», хотя правила к его файлам применяются.

## Подтверждение

Заявка [apocarteres/platform#79](https://github.com/apocarteres/platform/issues/79)
проекта deskpro-infra (ядро 16.2.0), задача DP-OPS-001: Ansible, shell,
Python, `stack: []`, 18 файлов `.yml` и 2 `.py` в источниках — отказ, `check` и
`verify` красные, подключение не завершить. Сверка с ядром 17.1.0:
`bin/conventions.mjs` вызывает `collectSourceFiles(root, config)` с набором по
умолчанию `SOURCE_EXTENSIONS`.

## Последствия при сохранении текущего поведения

Проект, которому нужны только правила (`REQ-ADOPTION-028`), подключиться не
может, а другой проходит проверку по совпадению — из-за случайного `.js`.

## Решение владельца

Дефект проверки: требование не менялось; поведение по заявке.

## Требуется

1. Проверка считает файлы с расширениями всех правил ядра и правил проекта.
2. Отказ называет эти расширения.
3. Уточнить `REQ-ADOPTION-009`.

## Критерии приёмки

- Тест первым: источники с одним `.yml` и `stack: []` — без отказа; источники
  только с `.sh` и `.j2` — отказ с перечнем расширений; объединение включает
  расширения правил ядра и правил проекта.
- Пробы: снова только языки ядра, настройки не в счёт, правила проекта не в
  счёт — тесты падают.
