# Смена версий компонентов ядром — обязательство полного прогона

## Проблема

Выпуск 13.2.1 поднял Jackson 3.1.5 → 3.1.7, а «Цена обновления» об этом
молчала. Потребитель узнаёт о смене версий по находке своего сканера или по
падению стенда. `verify` при подъёме ядра обязателен и так — расписка не
переносится на изменённое дерево кода, — но сканер и сценарии стенда в набор
потребителя могут не входить.

## Подтверждение

Решение владельца от 2026-09-29 после выпуска 13.2.1: «если ядро меняет
версии, записывать в обязательства — выполнить полный прогон».

## Последствия при сохранении текущего поведения

Смена версий доходит до потребителя без сигнала, полный прогон остаётся
делом памяти.

## Решение владельца

Решение владельца от 2026-09-29: видимость в цене обновления и обязательство
полного прогона.

## Требуется

`REQ-DEPS-010`.

## Критерии приёмки

- Тесты первыми: версии компонентов читаются из управления зависимостями без
  артефактов ядра; цена называет смены и полный прогон, несовместимостью их
  не считая; обязательство — полноценная запись каталога со сроком в один
  выпуск; выпуск ядра со сменой версий без обязательства не закрывается, а
  `release full-run` его объявляет. Тесты падали до правки.

## Что сделано

- Поверхность версии — `components` из корневого `pom.xml`; цена и
  `upgrade-report` — строка «Версии компонентов»; `full-run.mjs`: запись
  обязательства, отказ закрытия, объявление; подкоманда `release full-run`.
- Обязательство `full-run-13-2-1` объявлено задним числом, одной записью
  через `fullRunObligation`: команда объявляет только для открытого выпуска,
  а 13.2.1 уже вышел.
- 7 проб — все пойманы.
