# Показ состояния выпуска отказывает на обычном состоянии

## Проблема

`conventions release status` возвращает код 1, когда открытый выпуск закрыть
нельзя. Но это обычное состояние середины работы: дерево не чисто, расписки на
текущий коммит ещё нет, состав пуст. Команда своё дело выполнила — состояние
прочитала и напечатала.

Внутри одной команды поведение к тому же непоследовательно: когда открытого
выпуска нет вовсе, команда завершается кодом 0 (`REQ-RELEASE-010`), а когда
выпуск есть и не готов — кодом 1. Оба случая — удавшееся чтение.

## Чем подтверждено

Заявка потребителя `clanlog` от 2026-09-11, ядро 1.6.0, замер повторён
(впервые найдено на 0.45.0): https://github.com/apocarteres/platform/issues/2

```
Открытый выпуск: RELEASE-2026-09-5, тег при закрытии: 2026.09.5
Задач в составе: 5
Выпуск закрыть нельзя:
- Рабочее дерево не чисто: тег утверждал бы одно состояние, а помечал другое
exit=1
```

Место в коде названо заявкой верно: `releaseStatus` в
`packages/project-conventions/bin/conventions.mjs` ставит `process.exitCode = 1`,
перечислив препятствия.

## Последствия при сохранении текущего поведения

1. Показ состояния нельзя поставить в набор проверок: он будет красным всегда,
   кроме мгновения готовности к закрытию.
2. Настоящий отказ чтения — испорченный документ выпуска, отсутствующий
   каталог, неразобранные метаданные — неотличим от обычного состояния: код
   один и тот же.
3. Потребитель сознательно не вводит обходной путь, потому что тот погасил бы
   вместе с обычным состоянием и настоящий отказ.

## Ожидаемый результат

Удавшееся чтение состояния завершается кодом 0 независимо от готовности к
закрытию. Ненулевой код остаётся за случаем, когда состояние прочитать не
удалось, и сопровождается причиной.

Готовность к закрытию выражена кодом возврата у `release close` — команды,
которая от неё зависит.

## Критерии приёмки

- `release status` на открытом выпуске с препятствиями печатает их и
  завершается кодом 0.
- `release status` при невозможности прочитать состояние завершается
  ненулевым кодом с названной причиной.
- Случаи закреплены проверками пакета.

## Ход выполнения

### Шаг 1 (2026-09-11)

Показ состояния печатает препятствия обычным выводом и завершается нулём: и
когда открытого выпуска нет, и когда он есть, но не готов, и когда недостаёт
завершающего шага. Чтение, которое удалось, отказом не считается.

Ненулевой код остался за случаем, когда состояние прочитать не удалось: тело
команды обёрнуто перехватом, и отказ печатается названной причиной — например
«Открытых выпусков больше одного» вместо трассировки.

Нормативный текст: `REQ-RELEASE-038`.

### Результаты проверок (2026-09-11)

| Прогон | Результат |
| --- | --- |
| `mise run check` | 126 документов, 294 положения, правила соблюдены, Java-сборка успешна |
| Тесты пакета правил | 149 из 149 (было 147) |

Два новых теста на уровне CLI: состояние без выпуска и состояние неготового
выпуска дают код 0; два открытых документа выпуска дают код 1 с причиной.
Первый проверен на различающую силу: с прежним кодом возврата падает.
