# Команда расписки подтверждает проверки, которых не было

## Проблема

`conventions receipt` записывает расписку о пройденном наборе при любом
аргументе, включая `--help` и опечатку. Расписка утверждает прохождение
`verify` на текущем коммите, а закрытие выпуска ей доверяет: по
`REQ-RELEASE-003` при наличии расписки для коммита проверки не запускаются.
Значит случайный вызов создаёт документ, на основании которого выпускается
непроверенное состояние.

## Чем подтверждено

Опыт 2026-09-09 в пустом репозитории с одним пустым коммитом:

```
$ conventions receipt --help --root <repo>
Расписка о проверках записана: target/verify/b2a01214….json

$ cat target/verify/b2a01214….json
{ "commit": "b2a01214…", "completedAt": "2026-09-09T11:50:09Z", "checks": ["verify"] }
```

Проверок в этом репозитории не запускалось: в нём нет кода. Дефект обнаружен у
потребителя `zavpn`, где такой же вызов записал расписку на рабочем коммите;
файл был удалён до того, как им воспользовалось закрытие выпуска.

Причина в двух местах `packages/project-conventions/bin/conventions.mjs`:

1. Строка 408 отбрасывает из аргументов всё, что начинается с `--`, и передаёт
   остаток как перечень пройденных наборов. Неизвестный аргумент не отвергается,
   `--help` не обрабатывается.
2. Строка 181 при пустом перечне подставляет `['verify']`, поэтому вызов без
   осмысленных аргументов утверждает прохождение полного набора.

Третье, более глубокое: расписка фиксирует заявленное, а не наблюдённое.
Совпадение перечня с реально выполненными наборами не проверяется, хотя
`REQ-RELEASE-018` описывает расписку как свидетельство машины.

## Последствия при сохранении текущего поведения

1. Выпуск любого потребителя можно закрыть без проверок: достаточно случайного
   вызова команды расписки на нужном коммите.
2. Поддельная расписка неотличима от законной по содержимому, поэтому ошибка не
   оставляет следа.
3. Правило «зелёная проверка сама по себе корректности не доказывает» теряет
   основание: сама запись о проверке перестаёт означать, что проверка была.

## Требуется

1. Команда отвергает неизвестные аргументы и обрабатывает `--help` выводом
   справки, а не записью файла.
2. Пустой перечень наборов является ошибкой, а не полным набором по умолчанию.
3. Расписка содержит признак прогона, отличающий свидетельство машины от ручной
   записи: например, имя выполненной задачи менеджера окружения и её код
   возврата.
4. Закрытие выпуска отвергает расписку без такого признака.

## Критерии приёмки

- `conventions receipt --help` печатает справку и файлов не создаёт.
- `conventions receipt <неизвестный аргумент>` завершается ошибкой и файлов не
  создаёт.
- Расписка без явного перечня наборов не записывается.
- Закрытие выпуска отвергает расписку, не содержащую признака прогона.
- Отказ и успех обоих случаев закреплены тестами пакета.
