# Уведомления внутри приложения: колокольчик

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: служба на Spring Boot с аутентификацией ядра и её одностраничный клиент, подключившие уведомления.** Ядро поставляет колокольчик библиотекой: starter `platform-notifications` и пакет клиента `@apocarteres/notifications`. Колокольчик, как на многих сайтах, показывает число непрочитанного, а по щелчку — короткий список последних уведомлений. Как с модальными окнами, проект рисует только вид. Решение владельца от 2026-09-25 (`CORE-ARC-018`), пересмотр `ADR-0001`: отдельного сервиса уведомлений пока нет. Модуль необязателен.

**Уровень требования: директива.**

## Уведомление

1. <a id="REQ-NOTIFICATIONS-001"></a> **REQ-NOTIFICATIONS-001** — Уведомление принадлежит учётной записи ядра (`REQ-AUTH`). Таблицу проект создаёт своими переходами базы по образцу `sql/platform-notifications/create-notification.sql`; удаление учётной записи (`REQ-AUTH-024`) стирает её уведомления вместе с ней.
2. <a id="REQ-NOTIFICATIONS-002"></a> **REQ-NOTIFICATIONS-002** — Уведомление создают проект и модули ядра Java API `Notifications.notify(account, kind, params, link)`. Вид — строчные латинские буквы и цифры с точкой или дефисом, до 64 знаков, например `support.answered`; параметров — не больше 20, имя — латиница и цифры до 32 знаков, значение — строка до 200 знаков без управляющих; ссылка — путь сайта от корня, до 500 знаков, а не адрес: чужой адрес в колокольчике — открытое перенаправление. Нарушение — отказ вызова. Создание идёт в транзакции вызывающего: откатилась работа — уведомления нет.
3. <a id="REQ-NOTIFICATIONS-003"></a> **REQ-NOTIFICATIONS-003** — Ядро хранит вид, параметры и ссылку, а текст на нужном языке собирает клиент проекта по виду: у ядра нет перевода и бренда, а язык человека может смениться после уведомления. Параметры — то, чем текст собирается: номер, название, число, — а не почта, телефон и свободный текст человека: уведомление живёт отдельно от данных, к которым ведёт, и копировать в него персональные данные незачем.

## Колокольчик

4. <a id="REQ-NOTIFICATIONS-004"></a> **REQ-NOTIFICATIONS-004** — Точки под `/api/notifications` — только вошедшему и только о своих уведомлениях: число непрочитанного (`/unread`), последние свежими сверху вместе с числом (по умолчанию 20, `platform.notifications.list-size`, не больше 50), прочтение одного — повторное прочтение не ошибка, чужое — `notification-not-found`, — и прочтение всех. Правила доступа модуль объявляет `ModuleApiAccess` (`REQ-AUTH-022`).
5. <a id="REQ-NOTIFICATIONS-005"></a> **REQ-NOTIFICATIONS-005** — Клиент объявляет колокольчик один раз — `provideNotifications({ base, limit })` — и получает `NotificationBell`: сигналы `unread` и `items`, `open()` по щелчку, `read(id)` и `readAll()`. Число спрашивается при запуске и раз в минуту; без входа — ноль и пустой список. Вид колокольчика и текст по виду рисует проект. Доставка — опросом: SSE и WebSocket — позже, если понадобятся.

## Хранение

6. <a id="REQ-NOTIFICATIONS-006"></a> **REQ-NOTIFICATIONS-006** — Уведомление хранится 90 дней от создания; проект переопределяет срок `platform.notifications.keep` в обе стороны, но только положительным — бессрочного хранения нет. Стирание по сроку — явная команда `Notifications.purgeExpired()` из планировщика проекта; удаление по запросу субъекта по 152-ФЗ — `Notifications.erase(account)`.

## Модули ядра

7. <a id="REQ-NOTIFICATIONS-007"></a> **REQ-NOTIFICATIONS-007** — Модуль ядра звонит в колокольчик, когда проект подключил `platform-notifications`, и молчит без него: колокольчик — решение проекта, а модуль, требующий его всегда, навязал бы таблицу. Центр поддержки (`REQ-SUPPORT-015`) звонит автору с учётной записью — `support.answered`, и операторам — `support.arrived`.

## Контракт

8. <a id="REQ-NOTIFICATIONS-008"></a> **REQ-NOTIFICATIONS-008** — Точки описаны контрактом `platform-notifications/src/main/resources/openapi/platform-notifications.openapi.json`, копия лежит в пакете клиента, типы клиента выводятся из него; тест держит контроллер в соответствии, а цена обновления сверяет контракт между версиями (`REQ-PUBLISHING-015`).
