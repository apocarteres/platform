# Уведомления ядра не уходят за пределы приложения

## Проблема

Колокольчик ядра (`REQ-NOTIFICATIONS`) виден только в открытом приложении.
Потребители просят доставлять уведомления в Telegram; порта доставки у
модуля уведомлений нет, и проект может только дублировать каждый вызов
`notify` своей отправкой.

## Подтверждение

Просьбы потребителей, разговор с владельцем 2026-11-16. `Notifications` в
17.8.0 — `notify`, `revise`, `purgeExpired`, `erase`; каналов доставки нет.

## Последствия при сохранении текущего поведения

Каждый проект дублирует отправку рядом с `notify` и расходится с
колокольчиком: правка (`REQ-NOTIFICATIONS-010`) и стирание до Telegram не
доходят.

## Решение владельца

Решение владельца от 2026-11-16 — в `CORE-ARC-030`: этап 2 модуля
`platform-telegram`.

## Требуется

1. Порт доставки модуля уведомлений: созданное уведомление после фиксации
   транзакции попадает в очередь доставки; без модуля доставки поведение
   прежнее.
2. `platform-telegram` доставляет уведомления учётных записей со связью
   (`CORE-ARC-030`); текст по виду, параметрам и языку даёт порт проекта —
   у ядра нет текста и бренда (`REQ-NOTIFICATIONS-003`); нет текста для
   вида — в Telegram не уходит.
3. Отправка — явная команда `deliverPending()`: ядро фоновую работу не
   запускает, источник вызова выбирает проект; повтор и одновременный
   запуск не шлют дважды; пределы частоты Bot API соблюдаются.
4. Отказ отправки не откатывает работу и пишется в журнал без
   персональных данных; снятая связь и убранное уведомление не
   доставляются.

## Критерии приёмки

- Уведомление учётной записи со связью уходит один раз, без связи — не
  уходит.
- Откат транзакции `notify` — нет и доставки.
- Два одновременных `deliverPending()` не шлют одно уведомление дважды.
- `mise run verify` зелёный.

## Ход работы

- 2026-11-16 — в `platform-notifications`: порт `NotificationChannel`,
  очередь `platform_notification_delivery`, которую `notify` пишет в своей
  транзакции, команда `NotificationDelivery.deliverPending()` с захватом
  `SKIP LOCKED` и сроком захвата, исходы `Delivery` с повтором до 8 попыток
  (`REQ-NOTIFICATIONS-011`…`014`).
- В `platform-telegram`: канал `telegram-<бот>` на каждый бот при бине проекта `TelegramTexts`,
  язык связи пишется при `/start`, ответы Bot API `403`/`4xx`/`429`/`5xx`,
  не чаще раза в секунду в один чат (`REQ-TELEGRAM-014`…`017`).
- Число каналов задают настройки, поэтому в модуле уведомлений есть второй
  порт — `NotificationChannels`, источник нескольких каналов.
- Прочитанное в колокольчике до отправки в Telegram не уходит: человек его
  уже видел.
- `403` от Bot API снимает связь: чат недоступен, а его номер — персональные
  данные без цели.
