# Java: порт часов

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: Java.** Документ задаёт средство исполнить [общее требование о времени](code-clock.md) в Java-коде.

**Уровень требования: директива.**

## Порт

1. <a id="REQ-JAVA-CLOCK-001"></a> **REQ-JAVA-CLOCK-001** — Портом часов является `java.time.Clock`. Собственные интерфейсы часов не вводятся: тип входит в стандартную библиотеку, его понимают `java.time` и сторонние библиотеки, а свой интерфейс потребовал бы переходников на каждой границе.
2. <a id="REQ-JAVA-CLOCK-002"></a> **REQ-JAVA-CLOCK-002** — Рабочая реализация поставляется артефактом `platform-time`: автоконфигурация регистрирует бин `Clock` в UTC при отсутствии бина потребителя. В проекте-потребителе файла, обращающегося к системным часам, не появляется, и `clockAllowlist` в его `.conventions.json` остаётся пустым.
3. <a id="REQ-JAVA-CLOCK-003"></a> **REQ-JAVA-CLOCK-003** — Класс, которому нужно время, получает `Clock` через конструктор. Статические обращения к времени, поля-синглтоны и создание часов внутри метода запрещены: они возвращают ту же непроверяемую зависимость от машины.

## Как получают значения

4. <a id="REQ-JAVA-CLOCK-004"></a> **REQ-JAVA-CLOCK-004** — Значения выводятся из `clock.instant()` и `clock.millis()`. Дата и время в поясе получаются преобразованием: `LocalDate.ofInstant(clock.instant(), zone)`, `clock.instant().atZone(zone)`.
5. <a id="REQ-JAVA-CLOCK-005"></a> **REQ-JAVA-CLOCK-005** — Вызовы вида `X.now(...)` запрещены в любой форме, включая `LocalDate.now(zone)` и `Instant.now(clock)`. Аргумент не делает вызов проверяемым: пояс источник времени не заменяет, а различать по тексту переданные часы и переданный пояс проверка не может.
6. <a id="REQ-JAVA-CLOCK-006"></a> **REQ-JAVA-CLOCK-006** — Пояс часов рабочего кода — UTC. Пояс потребителя применяется на границе представления, а не в вычислениях.

## Тесты

7. <a id="REQ-JAVA-CLOCK-007"></a> **REQ-JAVA-CLOCK-007** — Тест задаёт время явно: `Clock.fixed` для неподвижного момента и `MutableClock` из `platform-time`, когда по ходу проверки время должно двигаться. `MutableClock.at` принимает момент или его текстовое представление, `advance` сдвигает время, `withZone` отдаёт часы того же источника в другом поясе.
8. <a id="REQ-JAVA-CLOCK-008"></a> **REQ-JAVA-CLOCK-008** — Тест, ожидающий наступления события по календарному времени, сдвигает часы, а не ждёт его. Ожидание реального времени делает тест медленным и недоказуемым.
