# Отменённая задача не даёт закрыть выпуск

## Проблема

Закрытие выпуска и проверка документов расходятся в том, что считается
составом.

`closeRelease` берёт в состав каждую задачу в терминальном статусе:
`lib/release/documents.mjs`, `compositionTickets` фильтрует по
`terminalStatuses` — это `done`, `cancelled`, `superseded`. Проверка документа
выпуска требует иного: `lib/docs/release-model.mjs:77` роняет выпущенный
документ, если у задачи состава `status` не равен `done`.

Обратная проверка замыкает круг: `lib/docs/release-model.mjs:97` требует, чтобы
задача с назначенным выпуском присутствовала в его составе. Поэтому у
отменённой задачи нет ни одного согласованного состояния:

- осталась в составе — «задача не выполнена»;
- убрана из состава, выпуск в поле задачи остался — «задача отсутствует в
  составе назначенного выпуска»;
- убрана из состава, поле возвращено в `unassigned` — документы согласованы, но
  следующее закрытие выпуска снова возьмёт её в состав.

## Чем подтверждено

Случай в проекте `zavpn` 2026-09-10, выпуск `2026.09.7`. Задача `OPS-019`
отменена: её дефект передан в ядро и закрыт там задачей `QUAL-004` выпуска
`1.0.0`. `conventions release close` поставил тег и записал `OPS-019` в состав,
после чего `conventions docs-check` отказал: «задача OPS-019 не выполнена». Тег
уже стоял и переписан быть не может (`REQ-RELEASE-005`), поэтому потребитель
правил состав руками — раздел, который по `REQ-RELEASE-022` пишет команда.

### Воспроизведено в ядре 1.1.0 (2026-09-10)

Фикстурный проект со схемой по дате: цикл принят, добавлена одна отменённая
задача `OPS-001` с `release: unassigned`, получена расписка, выпуск закрыт.

```
Выпуск RELEASE-2026-09-1 закрыт: коммит c8d2d7ce, задач в составе 1.
Тег выпуска: 2026.09.1
```

Сразу после закрытия проверка документации отказала:

```
docs/releases/RELEASE-2026-09-1.md: задача OPS-001 не выполнена
```

Порядок событий тот же, что у потребителя: отказ приходит после создания тега,
который по `REQ-RELEASE-005` не переписывается.

Третий выход из перечня проверен отдельно. Цикл записал в отменённую задачу
`release: RELEASE-2026-09-1`; после возврата поля в `unassigned` открытый
`RELEASE-2026-09-2` показывает «Состав по факту закрытия задач: 1» — та же
задача снова в составе.

Второй выход в фикстуре с единственной задачей даёт, помимо отказа обратной
проверки, ещё и «состав выпуска не может быть пустым» (`REQ-RELEASE-009`); в
выпуске с другими задачами остаётся только отказ обратной проверки.

## Последствия при сохранении текущего поведения

Первая же отменённая задача ломает закрытие выпуска, причём после создания
тега: команда оставляет репозиторий в состоянии, которое не проходит проверку
документов. Ручная правка состава выпущенного документа противоречит
`REQ-RELEASE-022`, а возврат поля `release` в `unassigned` возвращает задачу в
состав следующего выпуска — тот же отказ повторится.

## Разбор причины

Расхождение не в том, что два перечня статусов не сверены, а в том, что
`terminalStatuses` отвечает сразу на два разных вопроса:

- «задача ушла из работы» — по нему определяется размещение в `closed/`
  (`lib/docs/ticket-model.mjs:54`);
- «результат задачи вышел в выпуске» — по нему собирается состав
  (`lib/release/documents.mjs:60`).

Для `cancelled` и `superseded` первое верно, второе нет. Починка состоит в
разведении этих понятий, а не в сверке двух перечней.

Из вариантов ожидаемого результата это делает первый. У второго — принимать
отменённую задачу в составе с явной причиной включения — изъян: состав выпуска
станет содержать запись о работе, которая не выходила, и перестанет быть
записью сделанного (`REQ-RELEASE-007`).

## Ожидаемый результат

Одно определение состава на обе стороны: либо в состав идут только выполненные
задачи, а отменённые и замещённые получают своё поле-признак цикла, в котором
ушли из работы, либо проверка документа принимает их с явной причиной
включения. Отменённая задача не должна снова попадать в состав следующего
выпуска.

## Критерии приёмки

- Закрытие выпуска с отменённой задачей в терминальном статусе оставляет
  репозиторий проходящим `docs-check`.
- Отменённая задача не появляется в составе следующего выпуска.
- Правила прямо говорят, что делает цикл с задачами `cancelled` и `superseded`.
