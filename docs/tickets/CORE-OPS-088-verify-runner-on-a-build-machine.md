# Набор проверок ядра в сборочном контейнере на машине сборки

## Проблема

Модули ядра с Redis и Postgres проверяются на настоящем хранилище через
Testcontainers. На машине разработки локального Docker нет, а машина сборки
доступна контекстом Docker по ssh. Напрямую с неё Testcontainers работать не
может: контексты по ssh он не понимает, а порты контейнеров на машине сборки
намеренно открыты только на `127.0.0.1`.

## Решение владельца

Решение владельца от 2026-09-24: свой сборочный контейнер ядра на машине
сборки, по образцу потребителя; порты машины сборки остаются закрытыми.

## Требуется

1. Образ несёт только `mise` и системное; версии инструментов берутся из
   `mise.toml` ядра командой `mise install` внутри контейнера и кешируются
   томом.
2. `mise run verify-runner-prepare` собирает образ и контейнер на машине
   текущего контекста Docker.
3. `mise run verify-runner [--commit REF]` загружает репозиторий пакетом git,
   прогоняет `mise run verify` в контейнере и переносит расписку в
   `target/verify/`.
4. Testcontainers внутри контейнера обращается к сокету Docker машины и к
   опубликованным портам через `host.docker.internal`.

## Откуда пришла задача

Первые тесты на настоящем Redis (CORE-ARC-013): Testcontainers не нашёл Docker
на машине разработки.
