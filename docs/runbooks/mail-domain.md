# Почтовый домен отправителя

Норма — [`REQ-MAIL`](../requirements/mail.md); здесь — порядок действий и
шаблон инструкции проекта по своему почтовому сервису. Имена ниже — образец.

## Объявление

```json
{
  "mail": {
    "domain": "shop.example.test",
    "dkim": ["provider"],
    "returnPath": "send.shop.example.test"
  }
}
```

Селекторы DKIM и домен адреса возврата называет кабинет почтового сервиса,
когда домен добавляют в него.

## Ключ почтового сервиса

Ключ API лежит в окружении хоста рядом с прочими секретами службы
(`REQ-SECRETS`), в репозиторий и в `.conventions.json` не попадает. Ключ —
с правом только на отправку, если сервис так умеет.

## Записи DNS

| Запись | Имя | Значение |
|---|---|---|
| DKIM | `<селектор>._domainkey.<домен>` | TXT или CNAME — как выдал сервис |
| SPF | `<адрес возврата>` | одна TXT-запись `v=spf1 include:<сервис> ~all` |
| MX | `<адрес возврата>` | как выдал сервис: сюда возвращаются отказы доставки |
| DMARC | `_dmarc.<домен>` | TXT `v=DMARC1; p=none; rua=mailto:<ящик сводок>` |

Записей `v=spf1` у одного имени — одна: две получатель считает ошибкой и
отвергает обе. Если на том же имени уже есть SPF другого отправителя, его
`include` добавляется в ту же запись.

## Ужесточение DMARC

1. Начать с `p=none` и адресом сводок `rua`.
2. Через одну–две недели сводок убедиться, что все свои письма проходят DKIM
   или SPF с совпадением домена.
3. Перейти на `p=quarantine`, затем на `p=reject`.

Письма отправителя, которого сводки показали непроходящим, сначала
подписываются, и только потом политика ужесточается.

## Проверка

```sh
conventions mail --check
```

Проверка спрашивает авторитетные серверы зоны: исправленная запись видна
сразу. На `p=none` проверка советует ужесточить, но не отказывает.

## Шаблон инструкции проекта

Инструкция проекта по своему почтовому сервису называет:

- какой сервис и с какого адреса уходят письма;
- где лежит ключ и как его сменить без остановки отправки;
- какие записи DNS заведены и где их правят;
- что делать по кодам отказа сервиса: неверный ключ, домен не подтверждён,
  превышен предел отправки, адрес в списке отказов;
- как проверить доставку: письмо входа на свой ящик после развёртывания,
  заголовки `Authentication-Results` показывают `dkim=pass`, `spf=pass`,
  `dmarc=pass`.
