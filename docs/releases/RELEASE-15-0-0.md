# Выпуск 15.0.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Несовместимые изменения

- Обязательство ядра `telemetry` (`REQ-TELEMETRY-006`): проект со своими узлами объявляет их и проходит `conventions telemetry --check` на рабочей среде в срок 3 выпусков; по истечении срока закрытие выпуска отказывает.

## Проверка видит больше

- Правило `telemetry` (`REQ-TELEMETRY-001`) называет изъяны объявленного раздела `telemetry`: имя узла не из строчных букв, цифр и дефиса, повтор имени, адрес приёмника не http или https, поле, похожее на учётные данные, срок не срок. Пока раздела нет, правило молчит.

## Миграция

1. Открытие выпуска заведёт задачу обязательства `telemetry`. Проекту без своих узлов — закрыть её задачей, которая это называет (`REQ-RELEASE-019`).
2. Объявить раздел `telemetry`: имена узлов с именем проекта впереди, адреса Prometheus и Loki, при нужде `logsWithin`. Образец — [RUN-TELEMETRY-NODES](../runbooks/telemetry-nodes.md).
3. Поставить метку `node` с объявленным именем на цель опроса каждого узла и на потоки его журнала (`REQ-TELEMETRY-002`).
4. Напечатать правила `conventions telemetry --alerts prometheus` и `--alerts loki` и передать владельцу хоста наблюдения своей частью (`REQ-TELEMETRY-004`, `REQ-TELEMETRY-005`).
5. После развёртывания рабочей среды — `conventions telemetry --check`.
