# У Rust нет средства засева, хотя правило его разрешает

## Проблема

`REQ-QUALITY-007` разрешает засеять существующие находки ограничителем и с
1.20.0 знает вторую единицу — множество объявленных послаблений. Для Java и
TypeScript ядро даёт средство засева файлом. Для Rust средства нет: у clippy
ограничителя не существует, а ядро своего не предложило.

Потребитель остаётся перед выбором: одномоментно править существующий код либо
отойти от поставленной настройки. Ни то ни другое не входило в замысел.

## Чем подтверждено

Заявка потребителя [issue #21](https://github.com/apocarteres/platform/issues/21).
Порог числа аргументов, приезжающий поставкой, дал на агенте потребителя
**тринадцать находок, двенадцать из которых к часам отношения не имеют**:
подписи были такими до переноса настройки. Потребитель порог не оспаривает и
прямо пишет, что он поставлен не зря.

## Что делать

Правило ядра собирает объявленные в коде послабления clippy и ведёт их
ограничителем единицей множества, которая для этого и введена
(`REQ-QUALITY-007`). Множество засеивается один раз и может только убывать;
новое послабление без подъёма ограничителя роняет проверку.

Так у Rust появляется то же средство, что у Java и TypeScript, и работа идёт
снятием послаблений, а не правкой порога.
