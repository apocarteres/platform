# Список оператора отбирает только по одному состоянию и только по дате создания

## Проблема

Список обращений оператора (`REQ-SUPPORT-012`) принимает одно состояние и
упорядочен только по дате создания. Отбор «ждут ответа» — `NEW` и
`IN_PROGRESS` вместе — и порядок по последней активности проект собрать не
может, а числа по состояниям получает отдельным запросом на каждое.

## Подтверждение

Заявка потребителя от 2026-11-16: экран поддержки со списком рядом с
открытым обращением и кнопками отбора с числами. `GET
/api/support/operator/requests?state=…` и `SupportOperator.list(state)` в
13.2.1–17.7.1 принимают одно состояние; порядок —
`created_at DESC, number DESC`; числа потребитель берёт четырьмя запросами
`size=1`.

## Последствия при сохранении текущего поведения

Потребитель склеивает страницы двух запросов на клиенте, ломая постраничность,
не может поднять наверх обращение, где автор только что ответил, и делает
лишние запросы ради чисел.

## Решение владельца

Решение владельца от 2026-11-16: взять в ядро отбор по нескольким
состояниям, порядок по последней активности и числа по состояниям одним
запросом. Поиск по номеру, тексту и почте и почта автора в строке списка в
задачу не входят.

## Требуется

1. Повторяемый параметр `state` и параметр `order` (`CREATED`, `ACTIVITY`) у
   списка оператора; без параметров — прежнее поведение.
2. Точка `/api/support/operator/counts` — число обращений в каждом
   состоянии.
3. `SupportOperator.list(states, page, size, order)` и
   `SupportOperator.counts()` в клиенте; вызов с одним состоянием работает,
   как прежде.
4. Требование `REQ-SUPPORT-016`, контракт OpenAPI и типы клиента.

## Критерии приёмки

- Отбор по двум состояниям отдаёт обращения обоих, `total` — их число.
- `ACTIVITY` поднимает обращение с последним сообщением или сменой
  состояния; при равном времени порядок устойчив между страницами.
- Числа называют все состояния, пустое — нулём; точка только для
  оператора.
- `mise run verify` зелёный.

## Ход работы

- 2026-11-16 — `state IN (:states)` и порядок `CASE WHEN :activity THEN
  updated_at ELSE created_at END DESC, number DESC` в `request-page-all`,
  `request-count-by-state`; тест `OperatorListTest`, контракт —
  `RequestOrder`, `Count`, `Counts`; клиент — `list(states, page, size,
  order)` и `counts()`.
- Значения порядка — заглавными, как и состояния: `order=ACTIVITY`.

## Вне задачи

Поиск по номеру, тексту и почте и почта автора в строке списка — отдельной
заявкой.
