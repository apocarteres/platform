# Колокольчик уведомлений: сервер и служебная часть клиента

## Проблема

Проекту нужно сообщать вошедшему, что произошло без него: пришёл ответ
поддержки, изменилось состояние, случилось событие проекта. Каждый проект
пишет это сам — хранение, счёт непрочитанного, отметку прочтения, опрос —
а у ядра ничего нет. Отдельный сервис уведомлений (CORE-ARC-001) владелец
отложил ради простого пути.

## Подтверждение

Решение владельца от 2026-09-25: ядро даёт сервер и служебную часть клиента
для виджета «колокольчик». Виджет, как на многих сайтах, показывает число
непрочитанных, а по щелчку — короткий список последних уведомлений. Как с
модальными окнами, проект рисует только вид.

## Последствия при сохранении текущего поведения

Каждый проект строит уведомления сам; сроки хранения и удаление по запросу
субъекта решаются в каждом по-разному.

## Решения владельца

Решения владельца от 2026-09-25:

1. Делается после выпуска центра поддержки (CORE-ARC-017).
2. Уведомления создают проект — Java API вида
   `Notifications.notify(account, kind, params, link)` — и модули ядра:
   центр поддержки сообщает «пришёл ответ» автору и «новое обращение»
   оператору.
3. Ядро хранит вид уведомления, параметры и ссылку; текст на нужном языке
   собирает клиент проекта. Перевода и бренда у ядра нет.
4. Доставка — опрос раз в минуту; SSE и WebSocket — позже, если понадобятся.
5. Хранение — 90 дней по умолчанию, проект переопределяет; есть «прочитать
   всё».
6. Отдельный сервис писем и рассылок не делается: исследование CORE-ARC-001
   закрыто колокольчиком.

## Требуется

1. Starter `platform-notifications` поверх аутентификации ядра: уведомление
   принадлежит учётной записи; Java API создания; точки — число
   непрочитанного, последние уведомления, прочитать одно, прочитать всё.
2. Пакет клиента `@apocarteres/notifications`: счётчик и список сигналами,
   опрос, отметка прочтения; вид колокольчика и текст по виду — проект.
3. Сроки хранения явной командой, удаление по запросу субъекта (152-ФЗ);
   параметры уведомления не несут лишнего — требование называет это.
4. Центр поддержки подключается к колокольчику.
5. Требование, контракт OpenAPI, инструкция подключения.

## Критерии приёмки

- Тесты полного цикла на настоящих Postgres и Redis, тесты клиента.
- Пробы намеренной поломкой на каждое положение требования.
- Контракт сверяется с контроллером тестом.
