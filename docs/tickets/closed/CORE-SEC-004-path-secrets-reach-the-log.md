# Секрет из переменной пути попадает в журнал службы

## Проблема

`ApiErrorAdvice` при отказе без объявленного кода (`REQ-API-010`) пишет в
журнал `ERROR` метод и фактический путь запроса — `getRequestURI()`. Если
переменная пути — секрет, он попадает в журнал службы и во всё, что журнал
собирает. Кто читает журнал, получает доступ, который давала ссылка.

## Подтверждение

Заявка [apocarteres/platform#71](https://github.com/apocarteres/platform/issues/71)
проекта ZAVPN (ядро 13.7.0): ссылка подписки клиента вида
`/api/client-configs/{app}/{id}/{secret}`. Сверка с ядром 15.0.0:
`ApiErrorAdvice.java:80` пишет `servlet.getRequestURI()`; рядом `ErrorMetrics`
уже берёт шаблон пути из `BEST_MATCHING_PATTERN_ATTRIBUTE`. Тест: отказ на
`/links/s3cr3t-subscription-key` оставлял секрет в записи журнала.

## Последствия при сохранении текущего поведения

Каждый потребитель с секретом в пути отдаёт его журналу. ZAVPN закрыл это
маскированием в своём шаблоне журнала, скопированном из умолчаний Spring Boot;
шаблон разойдётся с ними при обновлении.

## Решение владельца

Решение владельца от 2026-10-08: в журнал — шаблон пути обработчика,
фактический путь — только без шаблона. Поле `instance` остаётся фактическим
путём: его получает только приславший запрос, а шаблон с `{}` — не URI.

## Требуется

1. Положение `REQ-API-012`.
2. Запись журнала `REQ-API-010` берёт шаблон пути; без шаблона — фактический
   путь.

## Критерии приёмки

- Тест первым: секрет из переменной пути не попадает в запись журнала, в ней
  шаблон; запрос без шаблона пишется фактическим путём; `instance` прежний.
- Пробы: фактический путь вместо шаблона, отказ от пути без шаблона — тесты
  падают.
