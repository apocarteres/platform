# Документ открытого выпуска приходится править руками

## Проблема

Проверка документов требовала от документа открытого выпуска того, что команда
цикла записывает только при закрытии, — и оба требования обходились лишь ручной
правкой таблицы, которую правило запрещает править руками.

Два лица одного и того же:

1. Задача выполнена — её файл переезжает в `closed/` (`REQ-TICKETS-013`), ссылка
   в составе перестаёт разрешаться, и принадлежность выпуску теряется: проверка
   устанавливала её **по пути**, а не по идентификатору.
2. Задача, выполненная при открытом выпуске, получает поле `release`, и проверка
   немедленно требовала строку состава — хотя состав пишется при закрытии
   (`REQ-RELEASE-007`, `REQ-RELEASE-031`).

## Чем подтверждено

Заявка потребителя [issue #5](https://github.com/apocarteres/platform/issues/5),
ядро 1.7.0, задача `CL-OPS-043`. Выпуск `RELEASE-2026-09-6`: открыт с пятью
задачами, закрыт с двенадцатью, документ выпуска правился руками одиннадцать раз
— девять правок пути и две дописанные строки состава. Набор `check` между
правками красный, а хук перед отправкой выполняет `check`: закрытая по правилам
задача останавливала отправку изменений.

## Ожидаемый результат

Закрытие названной задачи и отнесение задачи к открытому выпуску не требуют
правки документа выпуска руками.

## Что сделано

Принят вариант A из заявки — принадлежность читается из метаданных задачи, а
ссылка остаётся навигацией:

1. Задача состава ищется по идентификатору. Устаревший путь до закрытия выпуска
   отказом не считается: его чинит `mise run releases-index` тем же порядком,
   каким потребитель уже обновляет сводки задач.
2. Строка состава требуется только у выпущенного выпуска. До закрытия состав
   ещё не записан, и требовать его — значит требовать результата работы команды
   до того, как команда выполнена.
3. Ремонт ссылок распространён и на закрытые выпуски (`REQ-RELEASE-026`):
   переименование задачи миграцией имён больше не оставляет в них битой ссылки,
   которую нечем починить. Перечень работ при этом не меняется — правится только
   адрес файла.

У выпущенного выпуска обе проверки сохранены: и соответствие ссылки задаче, и
наличие строки состава.

Закреплено четырьмя тестами: переезд задачи в `closed` при открытом выпуске,
задача открытого выпуска без строки состава, сохранение обоих отказов у
выпущенного выпуска, ремонт ссылки в закрытом выпуске без изменения причины
включения.
