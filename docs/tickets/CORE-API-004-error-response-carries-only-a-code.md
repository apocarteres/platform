# Ответ об ошибке несёт только код: ни заголовков, ни собственных полей

## Проблема

`ApiErrorAdvice` возвращает `ProblemDetail` — то есть только тело — и ставит в
него ровно одно расширение, `code`. Двух вещей контракт не выражает.

**Заголовки.** Ответ об ошибке не может нести `Retry-After`, `WWW-Authenticate`
и прочие заголовки, без которых статус неполон: `429` без `Retry-After`
сообщает об отказе, но не о том, когда повторять.

**Собственные поля.** Отказ, у которого есть подробности — доступное
количество против запрошенного, перечень занятых строк, — не может их отдать.
RFC 9457 расширения допускает; ядро отдаёт только `code`.

В обоих случаях потребителю приходится оставлять локальный обработчик, хотя
общий отказ он в статус не отображает.

## Чем подтверждено

Заявка потребителя `clanlog` от 2026-09-11, ядро 1.6.0:
https://github.com/apocarteres/platform/issues/1

Потребитель исполнил обязательство `web-errors` полностью: убраны 50 локальных
обработчиков и 22 собственных типа тела ошибки, коды сверяются проверкой в
наборе. Остались два обработчика — оба из-за названных пробелов.

Проверено по коду ядра: `HttpHeaders` и `ResponseEntity` в
`platform-web-errors` не упоминаются ни разу; расширение ставится одно,
`ApiErrorAdvice` строка 38.

## Последствия при сохранении текущего поведения

1. Часть ответов сервиса остаётся вне контракта, и клиент разбирает два
   формата вместо одного — ровно то, ради чего контракт вводился.
2. Потребитель, исполнивший обязательство, формально остаётся нарушителем
   `REQ-API-005`: положение читается как запрет любого локального обработчика.
3. Каждый следующий потребитель напишет свои два обработчика заново.

## Ожидаемый результат

Ответ об ошибке несёт заголовки и собственные поля расширения, не требуя
локального обработчика. Формулировка `REQ-API-005` отделяет обработчик,
отображающий общее исключение в статус, от обработчика, который добавляет к
ответу то, чего контракт пока не выражает.

Предложение заявителя принято за основу: отказ, уже являющийся `ErrorResponse`
платформы приложений, пропускается со своими заголовками и дополняется
расширением `code`; собственные поля даёт порт проекта. Проверить при разборе:
покрывает ли пропуск `ErrorResponse` случай заявителя — его исключение
ограничителя частоты может этого интерфейса не реализовывать, и тогда
заголовки должен уметь отдавать порт.

## Критерии приёмки

- Ответ об ошибке может нести заголовки; случай `429` с `Retry-After`
  закреплён тестом на собранном конвейере.
- Отказ может нести собственные поля расширения рядом с `code`; без объявленного
  порта поведение прежнее.
- Клиентский разбор лишние поля не теряет.
- `REQ-API-005` различает два вида локальных обработчиков.
