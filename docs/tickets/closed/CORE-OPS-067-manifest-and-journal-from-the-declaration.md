# Манифест и журнал развёртывания написаны дважды

## Проблема

`REQ-DEPLOYMENT-002` требует записывать собранную ревизию манифестом рядом с
артефактами. Требование есть, поставки нет — оба потребителя написали манифест
сами, каждый на своих путях и со своими полями.

Журнал развёртывания есть у одного и отсутствует у второго, хотя вопрос «что и
когда сюда ставили» одинаков у обоих.

## Решение владельца 2026-09-21

За основу берётся устройство zavpn. Построчная сверка со вторым потребителем не
выполняется: остальным переход на формат ядра вменяется обязательством.

## Что берётся из zavpn

| Из манифеста | Как ложится в ядро |
|---|---|
| среда, коммит, тег выпуска, причина отсутствия тега, время | как есть |
| контрольная сумма каждой составляющей | из объявления `deployment` (`REQ-DEPLOYMENT-015`), а не из имён в коде |
| перечень целей агента | частное: покрывается общим перечнем составляющих |

Журнал — строка на развёртывание: время, коммит, тег или причина его
отсутствия, что именно ставили. Живёт **вне каталога исходников**, чтобы
переживать повторную выкладку.

## Что сделано

Команда `conventions manifest --env <среда>` пишет манифест **по объявленным
составляющим**, а не по именам в коде: перечень берётся из раздела `deployment`
(`REQ-DEPLOYMENT-015`), суммы считаются по объявленным артефактам.

```
conventions manifest --env prod --journal ../deploy-journal.log
```

Устройство взято у zavpn: среда, коммит, тег, причина отсутствия тега, время,
сумма каждой составляющей. Частное, чего в ядре нет, — перечень целей агента:
он покрывается общим перечнем составляющих.

Непомеченный коммит **требует названной причины**, а не проходит молча. Журнал —
строка на развёртывание, и живёт он вне каталога исходников, чтобы переживать
повторную выкладку.

Объявлено обязательство `deployment-interface` со сроком в три выпуска: остальные
потребители переходят на формат ядра. Построчной сверки со вторым потребителем
не делалось — решение владельца.

## Что нашлось по дороге

Свой же пункт обязательства я написал с полем `evidence` вместо `acceptance`. Это
обрушило `release open` **трассировкой**:

```
TypeError: Cannot read properties of undefined (reading 'map')
```

Каталог обязательств едет потребителям, то есть негодная запись уронила бы
открытие выпуска у каждого. Теперь каталог проверяется при загрузке и негодная
запись называется отказом с указанием обязательства и недостающего поля.

Ошибку сделал исполнитель ядра, и она же показала, что ядро не проверяло того,
что раздаёт.

## Чем закреплено

Шесть проверок манифеста: сбор по объявлению, требование причины у непомеченного
коммита, отказ на неизвестной среде, неизвестной составляющей и несобранном
артефакте, запись файла и дополнение журнала, различение тега и причины.

Отдельная проверка на каталог обязательств: полный образец принят, каждое
недостающее поле названо, пустое обязательство названо по всем полям сразу,
негодный каталог роняет загрузку отказом, а не трассировкой.

Различающая сила подтверждена снятием требования причины у непомеченного
коммита.
