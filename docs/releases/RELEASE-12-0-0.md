## Несовместимые изменения

- `conventions jvm-args` требует имени среды ключом `--env` и сверяет его с `deployment.environments` (`REQ-DEPLOYMENT-030`): прежний вызов `jvm-args --archive <путь>` отказывает, и служба не получает ключей запуска.

## Проверка видит больше

- `conventions commits --range` — шлагбаум `pre-push` — отказывает, пока файлы состояния выпуска в `.conventions/` изменены или созданы и не закоммичены (`REQ-RELEASE-048`).

## Миграция

1. В скрипте развёртывания передать имя среды в вызов ключей запуска: `conventions jvm-args --env "$env" --archive <путь>` (или `--aot <путь>`). Имя среды — то же, что `scripts/deploy.sh --env`; его печатает `conventions deploy-args` строкой `env=`.
2. Для среды `production` ключи запуска теперь несут `-Dspring.profiles.include=production`: профиль добавляется к профилям проекта, а не заменяет их. Если служба рабочей среды уже запускалась с профилем `production`, ничего не меняется. Если нет — с этим профилем служба отказывает при множителе пределов стенда (`platform.rate-limit.scale` больше 1) и при `http`-ссылках писем вне `localhost`: такие настройки рабочей среде не положены (`REQ-AUTH-010`, `REQ-AUTH-027`).
3. После закрытия выпуска файлы `.conventions/` входят в коммит закрытия вместе с `docs/`: `release finish` их называет.
