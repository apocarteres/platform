# Коммит слияния удерживает выпуск

## Проблема

Проверка принадлежности коммитов (`REQ-RELEASE-036`) требовала, чтобы каждый
коммит диапазона называл задачу. Коммит слияния задачи не называет — его
сообщение пишет `git`, — и закрытие выпуска отказывало.

## Чем подтверждено

Открытие выпуска 1.11.0 в самом ядре 2026-09-12:

```
- Коммит 59133216 не называет задачу: «Merge remote-tracking branch 'origin/main'
  into claude/gracious-wing-0cc7b0»
```

Слияние понадобилось, потому что в `main` приехала работа из другой ветки.
Обойти отказ было нечем: переписывать опубликованную историю нельзя, а
называть слияние задачей неправда — оно не вносит работы.

## Последствия при сохранении текущего поведения

Любой проект, у которого работа идёт больше чем в одной ветке, не может закрыть
выпуск после первого же слияния. Правило, введённое ради честного состава,
запрещало обычный порядок работы с ветками.

## Что сделано

Коммит слияния проверкой не рассматривается: он не вносит работы, а сводит уже
внесённую — она названа теми коммитами, которые он сводит. Признак берётся из
числа родителей, а не из текста сообщения, поэтому подделать его формулировкой
нельзя.

`REQ-RELEASE-036` дополнено этим случаем рядом с коммитом цикла.

Закреплено тестом: ветка с работой по задаче состава, слияние без ускоренной
перемотки, закрытие проходит. Различающая сила проверена возвратом правки —
тест отказывает.

## Критерии приёмки

- Выпуск закрывается при наличии коммита слияния в диапазоне.
- Коммит с одним родителем по-прежнему обязан называть задачу.

## Откуда пришла задача

Открытие выпуска 1.11.0: собственная проверка ядра остановила его же выпуск.
