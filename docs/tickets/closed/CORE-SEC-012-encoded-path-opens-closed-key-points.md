# Закодированный путь обходит проверки ключа доступа и приёма обращений

## Проблема

`AccessKeyGuard` сверял точки ядра (`/api/auth/**`) с сырым адресом
запроса (`getRequestURI()`), а Spring выбирает обработчик по
декодированному пути. Порт проекта `KeyAccess` получал тот же сырой адрес.
Адрес с закодированной латиницей (`/api/%61uth/keys`) проверку проходил
как «не точка ядра», а обработчик получал `/api/auth/keys`
(`REQ-AUTH-031`).

Так же фильтр центра поддержки `IntakeGuard` узнавал точку приёма
по сырому адресу: `POST /api/support/%72equests` обходил предел тела и
ограничитель частоты по адресу сети (`REQ-SUPPORT-003`).

## Подтверждение

У потребителя (задача TR-87) порт `KeyAccess` закрывал ключу
`/api/admin/**` сверкой сырого адреса по началу пути: ключом администратора
`GET /api/admin/people` — 403, `GET /api/%61dmin/people` — 200.
`StrictHttpFirewall` отвергает «;», «//», «.», «..», закодированные «/»,
«.», «\» и «%», но не закодированную латиницу.

## Последствия при сохранении текущего поведения

Ключ доступа выходит в точки, закрытые ему ядром и проектом: выпуск
ключей, смена пароля и почты, администрирование проекта. Невошедший
отправляет обращения без предела тела и частоты.

## Требуется

1. Точки ядра — по декодированному пути без учёта регистра, в том числе за
   префиксом сервлета.
2. Порт проекта получает запрос с декодированным путём в `getRequestURI()`.
3. Неоднозначный адрес (знаки структуры, «.», «..», «//», битая кодировка)
   по ключу закрыт целиком.
4. Фильтр приёма обращений стоит на шаблоне точки с учётом префикса
   сервлета; сопоставляет его контейнер по декодированному пути.

## Критерии приёмки

- `/api/%61uth/**`, `/api/AUTH/**` по ключу — `key-closed`.
- Порт проекта с запрещающим перечнем по началу сырого пути не обходится
  закодированной латиницей.
- Закодированные не-ASCII знаки в сегменте ключу не мешают.
- `POST /api/support/%72equests` с телом больше предела — `body-too-large`.

## Ход работы

- 2026-11-17 — `KeyPath`: путь внутри приложения после декодирования,
  неоднозначный адрес — пусто; `AccessKeyGuard` закрывает ключу пустой
  путь и точки ядра по нему и по `pathInfo`, порт получает декодированный
  адрес; `REQ-AUTH-031` дополнено; тесты `KeyPathTest` и
  `AccessKeyFlowTest`. Закодированная латиница не закрывается, а
  декодируется: прежние ответы законным клиентам не меняются. Для порта
  `KeyAccess` изменился вид `getRequestURI()`: пробел и не-ASCII приходят
  декодированными — в документ выпуска.
- 2026-11-17 — `IntakeGuard` больше не сверяет сырой адрес: шаблон
  фильтра учитывает `spring.mvc.servlet.path`, отбор — только по методу; `REQ-SUPPORT-003`
  дополнено; закодированные адреса приёма — в `SupportFlowTest` (у
  потребителя — задача TR-88).
