# Сверка коммитов срабатывала после отправки, а не до

## Проблема

Сверка коммитов живёт в закрытии выпуска и запускается только им. Хук
`pre-push`, который ядро ставит по `REQ-QUALITY-004`, выполняет `mise run
check`, а сверки коммитов в этом наборе нет.

Поэтому забытая строка признака цикла становится известна, когда коммит уже
общий, — и вопрос об исправлении встаёт в самой неудобной форме
(`CORE-OPS-053`).

## Чем подтверждено

Заявка потребителя [issue #19](https://github.com/apocarteres/platform/issues/19).
Состояние ядра проверено: хук выполняет `mise run check`, отдельной команды
сверки коммитов нет.

## Что сделано

Команда `conventions commits [--range]` сверяет коммиты диапазона отдельно от
закрытия выпуска, и хук `pre-push` вызывает её на **отправляемом диапазоне**,
который получает от системы контроля версий.

`REQ-QUALITY-004` дополнено: сверяется диапазон, а не вся история. Основание
названо в самом требовании, потому что оно неочевидно и важно: сверка истории
целиком не дала бы отправить ничего проекту, у которого такой коммит уже
отправлен, — то есть наказывала бы за прошлое, которое этим правилом уже не
исправить.

Отказ команды называет оба случая: до отправки правится сообщение, после —
коммит учитывается в выпуске.

## Чем закреплено

Проверка утверждает обе стороны: по всей истории коммит без задачи назван, по
диапазону из одного названного коммита — нет. Различающая сила подтверждена
снятием разбора диапазона: проверка отказала.
