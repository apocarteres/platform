# Правило вложенных модулей было псевдонимом соседнего

## Проблема

`submodulesAreFreeOfCycles` состояло из одного вызова `modulesAreFreeOfCycles`:
имя обещало проверку вложенности, а проверялся тот же верхний уровень.
`REQ-JAVA-MODULES-006` требует, чтобы граф оставался ациклическим на каждом
уровне, и предупреждает: «кольцо, спрятанное на уровень ниже, проверка верхнего
уровня не видит». Правило воспроизводило ровно этот дефект.

## Чем подтверждено

Заявка потребителя [issue #11](https://github.com/apocarteres/platform/issues/11),
ядро 1.17.0, задача `CL-ARC-051`. Тело метода в опубликованном артефакте —
`invokestatic modulesAreFreeOfCycles`, `areturn`. Потребитель поймал это
пробой: кольцо из трёх пакетов уровнем ниже; вызов с корнем приложения его не
находил.

Своими тестами ядро этого не видело, и причина поучительна. У правила были оба
случая, которых требует `REQ-PUBLISHING-014`, — и на отказ, и на проход, — но
оба звали правило с корнем **модуля**, где псевдоним ведёт себя как оригинал.
Два случая не защищают от правила, которое ничего своего не делает.

## Что сделано

Решение владельца 2026-09-13: правило обходит уровни само. Оно принимает корень
приложения и проверяет каждый уровень вложенности до листьев — глубина
выводится из самих классов, а не задаётся числом. Имя и подпись сохранены,
поэтому переход потребителю ничего не стоит.

Следствие названо прямо: проверка начнёт находить кольца, которые прежде
пропускала, и зелёная сборка потребителя может стать красной. Это и есть смысл
исправления.

Закреплено тестом по пробе потребителя: кольцо `alpha → beta → gamma → alpha`
двумя уровнями ниже указанного корня. Различающая сила проверена возвратом
псевдонима — тест отказывает.
