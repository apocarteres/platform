## Назначение репозитория

Репозиторий `platform` содержит общее ядро проектов zavpn и clanlog: библиотеки
Java (Spring Boot starters) и Angular, пакет процессных правил и инструментов
документации. Потребители ядра — отдельные репозитории; ядро не знает об их
предметных областях.

## Порядок ведения проекта

- Перед работой в каталоге читать его `RULES.md`, если он существует. Правила действуют на вложенные каталоги; ближайший файл уточняет порядок работы. Правила задач: [docs/tickets/RULES.md](docs/tickets/RULES.md), правила выпусков: [docs/releases/RULES.md](docs/releases/RULES.md).
- Каждую подтверждённую побочную проблему фиксировать задачей с доказательствами, включая ошибки тестов и окружения. Сначала искать существующую задачу; гипотезы явно отделять от фактов.
- Конфликты требований разрешать до реализации. Блокирующие вопросы и ответы сохранять в задаче; при `questions: open` работу по задаче не начинать, независимую часть выделять отдельной задачей с явными границами.
- Не отключать тесты без уведомления пользователя и не менять их так, чтобы они скрывали дефект.
- Проверки запускать задачами `mise`, а не голыми командами. Не запускать одновременно прогоны, использующие один каталог сборки или кеш.
- После изменения задач или выпусков выполнять `mise run tickets-index`, `mise run releases-index` и `mise run docs-check`.
- Для операций с репозиторием использовать обычный CLI `git`; `gh` не требовать и не использовать.

## Общие требования к ядру

- Источник требований: каталог `docs`. Новая функциональность не считается завершённой без отражения в требованиях и без тестов либо явного указания, почему тест не добавлен.
- Ядро не содержит доменных понятий потребителей: ни VPN, ни кланов, ни их сущностей. Расширение выполняется через порты (интерфейсы), которые реализует проект-потребитель.
- Ядро не навязывает планировщик и не запускает фоновую работу само. Периодические операции экспортируются как явные команды (`drain()`, `retain()`), а источник вызова выбирает потребитель: один из проектов запрещает `@Scheduled` и автономные триггеры.
- Read-only методы (`list`, `find`, `get`, `fetch`, `search`, `load` и аналогичные) не имеют побочных эффектов ни в каком виде.
- Обратная совместимость внутри ядра не поддерживается неявно: compatibility adapters, fallback-ветки и dual-read/dual-write запрещены. Несовместимое изменение — новая мажорная версия с описанной миграцией потребителя.
- Deprecated API не использовать ни в production-коде, ни в тестах, ни в примерах.
- Деньги и балансы только через `BigDecimal`.
- Проза документации на русском языке; английские имена остаются для технологий, идентификаторов, API и команд.
