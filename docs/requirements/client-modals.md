# Клиент: модальные окна

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: одностраничный клиент на Angular.** Поведение модальных окон — не оформление: разметка, классы, макет, кнопки и анимация остаются проекту. Решение о границе — `ADR-0004`.

**Уровень требования: директива.**

## Решение об Escape

1. <a id="REQ-CLIENT-MODAL-001"></a> **REQ-CLIENT-MODAL-001** — Каждое модальное окно объявляет, что оно делает по нажатию `Escape`. Решение обязательно, а не подразумевается: окно объявляется директивой `apoModal` из пакета `@apocarteres/modal`, и вход `[apoModalEscape]` у неё обязателен. Сборка со строгой проверкой шаблонов отказывает окну без решения, при запуске директива отказывает тоже — на случай сборки без строгой проверки. Основание — наблюдение владельца 2026-09-24: `Escape` почти никто не обрабатывает, и это не решение, а его отсутствие; молчаливое окно неотличимо от окна, которое решили не закрывать.
2. <a id="REQ-CLIENT-MODAL-002"></a> **REQ-CLIENT-MODAL-002** — Окно, которое по `Escape` не закрывается, говорит это явно: обработчиком `ESCAPE_IGNORED`, а не пустой функцией. Именованное решение видно в шаблоне и находится поиском, пустая функция — нет. Закрывает окно обработчик проекта: ядро передаёт намерение и не решает за приложение, можно ли закрыть окно с несохранёнными изменениями.
3. <a id="REQ-CLIENT-MODAL-003"></a> **REQ-CLIENT-MODAL-003** — `Escape` решает только верхнее из открытых окон. Открытые окна ведёт сервис уровня приложения; нажатие вызывает обработчик верхнего и дальше не распространяется — ни к окну под ним, ни к обработчикам страницы. Окно, решившее `Escape` игнорировать, нажатие тоже поглощает: решение принадлежит ему. Без открытых окон ядро нажатия не трогает.

## Проверка

4. <a id="REQ-CLIENT-MODAL-004"></a> **REQ-CLIENT-MODAL-004** — Проект объявляет, чем размечает свои модальные окна, в `.conventions.json`: `"modal": {"selector": ".modal-card"}` — класс, атрибут вида `[appModal]` или имя элемента. Правило `modal-escape` находит в шаблонах каждый элемент с этим признаком — в файлах `.html` и во встроенных шаблонах `.ts` — и требует на нём `apoModal`. Имя признака выбирает проект, а не ядро: ядро не диктует имён классов (`ADR-0004`), оно проверяет, что каждое окно, названное самим проектом, приняло решение. Правило читает шаблоны текстом и поэтому не видит признака, навешенного динамической привязкой — `[class.modal-card]`, `[ngClass]`: такое окно правилом не находится, и это ограничение записано здесь, а не умолчано. Собственная реализация модального окна (`REQ-ADOPTION-021`) остаётся законной и этим правилом не проверяется, пока проект не отнёс её к своему признаку.
