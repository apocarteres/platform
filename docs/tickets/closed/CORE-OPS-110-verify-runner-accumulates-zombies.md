# Сборочный контейнер копит зомби-процессы

## Проблема

`scripts/verify-runner/runner.sh` создаёт контейнер без `--init`, и PID 1 в
нём — `sleep infinity` из `CMD` образа. Команды идут через `docker exec`.
Процесс, осиротевший после такой команды, переходит к PID 1, а `sleep`
дочерние процессы не собирает. Процесс остаётся в состоянии `Z`.

## Подтверждение

2026-10-06, `platform-verify-runner` на машине сборки `mini`:
`HostConfig.Init` пуст, PID 1 — `sleep`. Три команды
`docker exec … bash -c '(sleep 3 &); exit 0'` оставили три процесса `Z`
с родителем 1. `docker top` их не показывает, видно только по
`/proc/*/stat` внутри контейнера.

## Последствия при сохранении текущего поведения

`verify` перезапускает контейнер перед каждым прогоном, поэтому зомби
копятся внутри сессии: циклы проб, `--run`, оборванные прогоны. Заняты номера
процессов, а не память, но при долгой сессии предел номеров достижим.

## Решение владельца

Решение владельца от 2026-10-06: контейнер создаётся с `--init`.

## Требуется

1. `prepare` создаёт контейнер с `--init`: PID 1 — `docker-init`, он собирает
   осиротевшие процессы.
2. `verify` отказывает, если контейнер создан без init, и называет
   `mise run verify-runner-prepare`. Иначе контейнеры, созданные до
   исправления, остались бы прежними.

## Критерии приёмки

- Тест первым, с подменённым `docker`: `create` получает `--init`; контейнер
  без init (`false`, `<nil>`) — отказ до перезапуска и до `exec`; контейнер
  с init — прогон идёт.
- Проверка на `mini`: после пересоздания PID 1 — `docker-init`, осиротевшие
  процессы собраны, `Z` нет.
- Пробы: снятый `--init`, нефатальная проверка init — тест падает.

## Откуда пришла задача

Сообщение владельца 2026-10-06 со снимком экрана о зомби-процессах в
сборочных контейнерах без `--init`.
