# Прежний идентификатор оставался внутри нового имени файла

## Проблема

Слаг нового имени брался из текущего имени файла целиком. Если прежнее имя
начиналось с идентификатора — а по схеме оно с него и начинается, — старый
идентификатор оставался внутри нового.

## Подтверждение

План перехода в третьем репозитории 2026-09-09 предлагал
`ARC-044-des-004-resend-call-written-twice.md` и
`TEST-026-rel-001-fix-failing-frontend-test.md`: идентификатор дважды, старый
внутри нового. В первом переведённом репозитории дефект не проявился, потому
что там имена файлов идентификатора не содержали вовсе.

## Последствия при сохранении текущего поведения

Имя файла перестаёт читаться и вводит в заблуждение: в нём два
идентификатора, из которых действует один. Каждый следующий перевод
репозитория, уже жившего по схеме, удваивал бы идентификатор снова.

## Ожидаемый результат

Ведущий идентификатор отбрасывается вместе с датой: слаг остаётся описанием
работы. Прежний идентификатор сохраняется там, где он и должен быть — в поле
`legacy-id`.

## Критерии приёмки

- [x] Слаг отбрасывает ведущий `<БУКВЫ>-<ЦИФРЫ>-` наравне с концевой датой — `lib/naming-migration.mjs`
- [x] Тест покрывает три вида прежних имён: с датой, с областью и номером, с идентификатором решения
- [x] Замер: план перехода в третьем репозитории даёт `QUAL-018-auction-final-pool-disagrees-with-budgets.md` вместо удвоенного идентификатора
