# Rust: работа со временем

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: код на Rust любого крейта.** Общий запрет — [REQ-CODE-CLOCK-000](code-clock.md); здесь — как он выражается в этом языке.

**Уровень требования: директива.**

## Порт

1. <a id="REQ-RUST-CLOCK-001"></a> **REQ-RUST-CLOCK-001** — Порт часов объявляется типажом с единственным методом, возвращающим момент стенных часов. Стандартного типажа часов в языке нет, поэтому порт объявляет проект или библиотека ядра. Типаж, а не функция: подмена выполняется передачей другой реализации, а не переопределением символа.
2. <a id="REQ-RUST-CLOCK-002"></a> **REQ-RUST-CLOCK-002** — Порт передаётся значением или ссылкой тому, кому время нужно, а не берётся из глобального состояния. Глобальные часы, доступные откуда угодно, делают неразличимыми код, которому время нужно, и код, которому оно досталось.
3. <a id="REQ-RUST-CLOCK-003"></a> **REQ-RUST-CLOCK-003** — Рабочая реализация — единственный модуль крейта, обращающийся к системным часам, и единственное место с объявленным послаблением на запрет. Пока ядро не поставляет реализацию, модуль живёт в проекте; при появлении второго потребителя он переносится в ядро по [правилам доставки](rule-distribution.md).

## Что запрещено и что законно

4. <a id="REQ-RUST-CLOCK-004"></a> **REQ-RUST-CLOCK-004** — Запрещены обращения к стенным часам мимо порта: `std::time::SystemTime::now`, `chrono::Utc::now`, `chrono::Local::now`, `time::OffsetDateTime::now_utc`, `time::OffsetDateTime::now_local`. Перечень доставляется настройкой разбора и растёт по мере появления в проектах новых источников времени.
5. <a id="REQ-RUST-CLOCK-005"></a> **REQ-RUST-CLOCK-005** — `std::time::Instant` запретом не покрыт: в Rust это монотонный счётчик, а не часы. Он не связан с календарём, может идти назад относительно стенных часов и годится ровно для измерения длительности — то же положение, что `REQ-CODE-CLOCK-008` устанавливает для `System.nanoTime`. Названо это отдельно потому, что смысл имени в Java и Rust противоположен: в Java `Instant` — стенные часы и запрещён, в Rust `Instant` — счётчик и законен, а стенные часы зовутся `SystemTime`. Правило, перенесённое из Java по имени типа, запретило бы законное и пропустило бы запрещённое.
6. <a id="REQ-RUST-CLOCK-006"></a> **REQ-RUST-CLOCK-006** — Запрет проверяется настройкой разбора, а не своим разбором текста: запрещённые пути объявляются в `clippy.toml` полем `disallowed-methods` с причиной. Основание — точность: разбор пользуется разрешением имён языка, поэтому не путает вызов с упоминанием того же имени в строке или в комментарии. Своему движку ядра эта разница стоила отдельных положений (`REQ-CODE-CLOCK-006`, `REQ-CODE-CLOCK-009`) и разбора литералов; здесь она достаётся даром. Проверено: вызов ловится с указанной причиной, `Instant::now` и то же имя внутри строкового литерала — нет.

## Тесты

7. <a id="REQ-RUST-CLOCK-007"></a> **REQ-RUST-CLOCK-007** — Тест подставляет реализацию порта с заданным значением. Значение задаётся из данных проверки, а не выводится из текущего момента: выражение «текущий момент минус час» возвращает зависимость от машины через арифметику.
8. <a id="REQ-RUST-CLOCK-008"></a> **REQ-RUST-CLOCK-008** — Ожидание наступления события по календарному времени выражается подвижной реализацией порта, а не задержкой потока. Задержка делает исход теста зависимым от загрузки машины, что запрещено `REQ-QUALITY-009`.

## Именование

9. <a id="REQ-RUST-CLOCK-009"></a> **REQ-RUST-CLOCK-009** — Именование в Rust ядро отдельно не нормирует. Положение переехало в [REQ-RUST-NAMING](rust-naming.md), где ему место; идентификатор сохранён, потому что он вышел в 1.23.0 и на него могли сослаться. Оказалось оно здесь по удобству, а не по смыслу, и это исправлено выпуском 1.24.0.
