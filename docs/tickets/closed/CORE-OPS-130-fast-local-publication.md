# Локальная публикация ядра занимает почти две минуты

## Проблема

Завершающий шаг выпуска ядра — `mise run install-local` — занимает больше
времени, чем проверки, которые ему предшествуют: после `CORE-OPS-129` выпуск
упирается в публикацию, а не в набор `verify`.

## Подтверждение

Выпуск 17.6.0, 2026-11-11: `mise run release` — 98 с при перенесённой
расписке. Трассировка `scripts/install-local.sh`: 57 с уходит на архив пакета
правил. Его `prepack` собирает историю изменений, читая поверхность ядра на
каждом из 163 тегов по очереди — десятки вызовов `git show` на тег. Остальное:
сборка Java-модулей — 14 с, сборка npm-пакетов — 11 с, упаковка десяти
пакетов по очереди — около 10 с; шаги идут подряд.

## Последствия при сохранении текущего поведения

Время публикации растёт с каждым выпуском ядра: тегов становится больше, и
история читается всё дольше.

## Решение владельца

Решение владельца от 2026-11-11: публикацию ускорить, чтобы выпуск ядра
укладывался в минуту.

## Требуется

1. Поверхность ядра на коммите читается один раз и запоминается; теги
   читаются одновременно.
2. Сборка Java-модулей и публикация npm-пакетов идут одновременно, пакеты
   упаковываются одновременно.

## Критерии приёмки

- История изменений до и после правки совпадает побайтно.
- Перенесённый тег читается по своему коммиту, а не по имени.
- Отказ сборки Java-модулей или упаковки пакета — отказ публикации с
  журналом.
- Замер: `mise run install-local` на прогретом дереве — не больше 20 с.
- `mise run verify` зелёный.

## Ход работы

- 2026-11-11 — поверхность ядра на коммите запоминается в `target/surface/<отпечаток кода чтения>/<коммит>.json`, теги читаются по восемь одновременно (`lib/release/surface.mjs`, `lib/release/changes.mjs`). Отпечаток кода чтения в пути обесценивает запомненное при правке самого чтения.
- `scripts/install-local.sh`: сборка Java-модулей идёт одновременно с публикацией npm-пакетов, пакеты упаковываются одновременно; журнал Maven печатается при отказе.
- Замеры 2026-11-11: история изменений — 57 с → 8 с при пустом запомненном и 0,4 с при заполненном, результат совпал побайтно; `mise run install-local` на прогретом дереве — 116 с → 13 с.
- `mvnw clean` из корня убирает корневой `target/` вместе с запомненным и отпечатками зависимостей: первый запуск после него идёт дольше.

## Вне задачи

Пропуск сборки npm-пакетов, когда их исходники не менялись.
