# Рабочая среда запускается с профилем `production`

## Проблема

Две защиты ядра держатся на активном профиле Spring `production`: множитель
пределов частоты стенда (`REQ-AUTH-027`) и `http`-ссылки писем
(`REQ-AUTH-010`) с этим профилем останавливают запуск. Но ядро нигде не
требует, чтобы служба рабочей среды запускалась с профилем `production`:
поднятая без него, она примет увеличенные пределы и `http`-ссылки молча.

## Подтверждение

Разбор заявки [issue #56](https://github.com/apocarteres/platform/issues/56)
2026-09-25: требования о профиле нет ни в `REQ-DEPLOYMENT`, ни в поставке
ключей запуска (`REQ-DEPLOYMENT-011`).

## Последствия при сохранении текущего поведения

Защита, объявленная для рабочей среды, зависит от настройки, которой никто
не проверяет.

## Решение владельца

Заведено по согласию владельца от 2026-09-25. Решение владельца от
2026-09-25: профиль поставляет ядро ключами запуска, имя среды у поставки
обязательно — несовместимо, старшая версия. Явный признак стенда вместо
профиля рассмотрен и не принят.

## Требуется

1. Требование: служба рабочей среды запускается с активным профилем Spring
   `production`, ключ поставляет ядро.
2. `conventions jvm-args --env <среда>`: для `production` —
   `-Dspring.profiles.include=production`; среда обязательна и сверяется с
   объявленными.

## Критерии приёмки

- Тест первым: `jvm-args` для `production` поставляет профиль, для прочих —
  нет; без среды и с необъявленной средой — отказ с перечнем объявленных.
  Тесты падали до правки (ключа `--env` не было).
- Тест Java: поставленный ключ включает профиль `production`, профили проекта
  остаются, множитель пределов стенда отвергается.

## Что сделано

- `REQ-DEPLOYMENT-030`; `REQ-DEPLOYMENT-011`, `REQ-AUTH-010`, `REQ-AUTH-027`
  ссылаются на него.
- `jvm.mjs`: `profileKeys`, сверка среды; `jvm-args` читает объявленные среды.
- `jvm-launch.test.mjs`, сценарии отказа в `way-out.test.mjs`,
  `ProductionProfileKeyTest`. Тест Java проходил сразу: он закрепляет
  поведение Spring, на которое опирается поставка, а не новый код.
- Пробы: 5 на Node (без профиля, `active` вместо `include`, необъявленная
  среда, среда необязательна, профиль всем средам) и 1 на Java (снятая
  проверка профиля) — все пойманы.

## Миграция потребителя

В вызов `conventions jvm-args` скрипта развёртывания добавить имя среды:
`conventions jvm-args --env "$env" --archive <путь>` (или `--aot <путь>`).
Ключи вывода передаются запуску службы, как и прежде.
