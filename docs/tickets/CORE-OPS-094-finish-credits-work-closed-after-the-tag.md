# Завершающий шаг засчитывает обязательство задаче, закрытой после тега

## Проблема

`release close` записывает задачам состава `release: <выпуск>` и ставит тег.
`release finish` после раската заново собирал состав из рабочего дерева и
добавлял в него всякую выполненную задачу с `release: unassigned`. Задача,
закрытая в `main` между тегом и завершающим шагом, засчитывала обязательство
выпуску, в котором её кода нет.

## Подтверждение

Заявка потребителя [issue #47](https://github.com/apocarteres/platform/issues/47)
(zavpn, ядро 9.1.0): обязательство `core-auth` засчитано выпуску без работы,
запись снята у потребителя вручную. Сверено с кодом 2026-09-25:
`finishability` брал `compositionTickets`, а тот включает выполненные
задачи без выпуска.

## Последствия при сохранении текущего поведения

Обязательство числится выполненным раньше, чем работа дошла до рабочей
среды; потребитель исправляет состояние руками.

## Требуется

Завершающий шаг берёт состав, записанный при закрытии: задачи с `release`
этого выпуска.

## Критерии приёмки

- Тест повторяет случай заявки: закрытие, затем задача обязательства
  выполнена, затем завершающий шаг — обязательство не засчитано.

## Что сделано

- `finishability` берёт `releasedTickets` — задачи с `release` выпуска.
- `REQ-RELEASE-019` называет, что выход в выпуске — состав закрытия.
- Тест `задача, закрытая после тега, …` падал до исправления и проходит после;
  54 теста цикла выпуска проходят.
