# tickets-renumber переписывает ссылки основы на её задачу

## Проблема

`conventions tickets-renumber` заменял идентификатор по всему тексту каждого
файла, изменённого веткой. Перенумерация нужна, когда в основе уже есть
другая задача с тем же номером, и ссылки на неё в общих файлах выглядят так
же: команда переписывала и их. То же — в теле сообщений коммитов.

## Подтверждение

Заявка [apocarteres/platform#78](https://github.com/apocarteres/platform/issues/78)
проекта legacy-store (ядро 16.0.0), задачи LS-OPS-087 и LS-OPS-089: комментарий
из `main` в `deploy/ansible/group_vars/all.yml` со ссылкой на задачу основы
стал ссылкой на перенумерованную задачу ветки, при повторной коллизии — ещё
раз. Нашли только на ревью: идентификатор в строке существующий. Сверка с
ядром 16.2.0: `renumberTicket` берёт `git diff --name-only` и заменяет по всему
тексту.

## Последствия при сохранении текущего поведения

Команда молча искажает ссылки основы; проверка этого не видит.

## Решение владельца

Дефект команды из CORE-OPS-119; поведение по заявке.

## Требуется

1. В файлах задачи ветки — все вхождения; в прочих изменённых файлах — только
   строки, добавленные или изменённые веткой (`git diff -U0`).
2. В сообщениях — только идентификатор в начале; прочие упоминания не
   трогать.
3. Нетронутые места напечатать с подсказкой проверить.
4. Уточнить `REQ-TICKETS-022` и `RUN-PULL-REQUESTS`.

## Критерии приёмки

- Тест первым по сценарию заявки: основа ссылается на свою задачу N в файле,
  ветка заводит свою N и меняет другую строку того же файла; после
  перенумерации ссылка основы осталась N, строка ветки — новый номер, место
  основы и упоминание в теле названы.
- Пробы: строки основы снова переписываются, тело сообщения снова
  переписывается, нетронутое не названо — тесты падают.
