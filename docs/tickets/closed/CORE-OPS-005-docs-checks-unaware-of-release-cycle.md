# Проверки документации не знали о собственных данных цикла выпусков

## Проблема

Цикл выпусков сам создаёт метаданные и документы, которые проверка
документации считала ошибками: поле `obligation` в задаче обязательства,
значение `release: before-cycle` у задач, выпущенных до цикла, и строку
состава, ссылающуюся на задачу, которая после выполнения переехала
в `docs/tickets/closed/`.

## Подтверждение

После принятия цикла в zavpn 2026-09-07 `conventions docs-check` дал 102
ошибки на документах, которые сам же цикл и записал: 92 задачи с
`before-cycle` («назначенный выпуск не существует»), задача обязательства
с неизвестным полем `obligation` и строка состава выпуска с адресом
задачи до переезда в `closed/`.

## Последствия при сохранении текущего поведения

Принять цикл нельзя: обязательный набор проверок падает сразу после
принятия, а привести документы в порядок можно только правкой руками,
которую следующая же команда цикла отменит.

## Ожидаемый результат

Проверка документации принимает данные цикла: поле `obligation`, значение
`before-cycle` без документа выпуска и состав, ссылки которого приводит
в соответствие команда сводок.

## Критерии приёмки

- [x] Поле `obligation` допустимо в метаданных задачи — `lib/docs/check-docs.mjs`
- [x] `release: before-cycle` не требует документа выпуска и попадает в сводку как «До цикла выпусков» — `lib/docs/release-model.mjs`, `lib/docs/tickets-index.mjs`
- [x] Команда `releases-index` обновляет ссылки состава открытого выпуска, а `docs-check` сообщает об устаревших ссылках — `lib/docs/releases-index.mjs`, `refreshCompositionLinks`
- [x] Тесты: задача до цикла с обязательством проходит проверку, устаревшая ссылка состава замечается и исправляется — 70 тестов пакета проходят
