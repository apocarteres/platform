# Java: имена типов и суффикс -er

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: Java.** Правило опирается на объявления типов языка и на его словарь имён.

**Уровень требования: рекомендация.** Нарушение сообщается проверкой и не роняет её. Смысл уровня — в [правилах о правилах](project-rules.md).

## Правило

1. <a id="REQ-JAVA-NAMING-001"></a> **REQ-JAVA-NAMING-001** — Тип не называется по действию, которое он совершает: `PriceCalculator`, `ReportMaker`, `DataFetcher`. Такой тип обычно — процедура, переодетая в объект: у него нет собственного состояния, а есть один метод, и поведение просится в тот тип, над которым оно совершается. Запрещён исполнитель, а не окончание: существительное предметной области, которое оканчивается на `-er`, — `Joker`, `Ledger`, `Player` — нарушением не является. Проверка узнаёт исполнителя по окончанию `-er` и пропускает имена из перечней ниже и из перечня проекта (`REQ-JAVA-NAMING-007`). Уточнено 2026-10-15: правило читалось буквально, и каждое существительное проекта приходилось добавлять в ядро заявкой.

## Имена образцов

2. <a id="REQ-JAVA-NAMING-002"></a> **REQ-JAVA-NAMING-002** — Разрешены имена классических образцов проектирования, где суффикс называет роль в известной схеме, а не действие: `Adapter`, `Builder`, `Compiler`, `Consumer`, `Controller`, `Decoder`, `Encoder`, `Filter`, `Forwarder`, `Handler`, `Initializer`, `Listener`, `Loader`, `Mapper`, `Parser`, `Producer`, `Provider`, `Publisher`, `Reader`, `Resolver`, `Router`, `Runner`, `Scheduler`, `Serializer`, `Subscriber`, `Validator`, `Verifier`, `Worker`, `Writer`.

## Доменные существительные

3. <a id="REQ-JAVA-NAMING-003"></a> **REQ-JAVA-NAMING-003** — Разрешены существительные, которые оканчиваются на `-er` по строению языка, а не потому, что называют исполнителя: `Buffer`, `Character`, `Cipher`, `Cluster`, `Container`, `Counter`, `Folder`, `Header`, `Layer`, `Ledger`, `Letter`, `Manager`, `Marker`, `Member`, `Number`, `Offer`, `Order`, `Owner`, `Parameter`, `Peer`, `Player`, `Register`, `Server`, `Trigger`, `User`, `Ver`, `Wrapper`. `Player`, `Character` и `Ledger` добавлены 2026-09-25 по заявке потребителя, `Letter` — по тому же основанию из кода ядра.
4. <a id="REQ-JAVA-NAMING-004"></a> **REQ-JAVA-NAMING-004** — Перечни раздельны намеренно: они разрешают имена по разным причинам, и расширять их следует по соответствующей причине, а не одним списком исключений.
7. <a id="REQ-JAVA-NAMING-007"></a> **REQ-JAVA-NAMING-007** — Существительные своей предметной области проект перечисляет сам в `.conventions.json`: `"javaNaming": { "nouns": ["Joker", "Lier"] }`. Имя типа, оканчивающееся на такое существительное, проходит; заявка в ядро для этого не нужна. Запись перечня — имя с заглавной буквы на `-er`; иную правило называет. Перечень — для существительных, а не для исполнителей: имя действия в нём отменяет правило, а не уточняет его.

## Что проверяется

5. <a id="REQ-JAVA-NAMING-005"></a> **REQ-JAVA-NAMING-005** — Проверка охватывает объявления `class` и `interface` в файлах `.java`. `record` и `enum` не проверяются: это данные, а не действие, и имя на `-er` у них — существительное. Имя сверяется с объединением перечней по окончанию.
6. <a id="REQ-JAVA-NAMING-006"></a> **REQ-JAVA-NAMING-006** — Существующие имена фиксируются ограничителем и могут только убывать: переименование типа затрагивает всех его потребителей, поэтому выполняется по мере работы с ними, а не разом.
