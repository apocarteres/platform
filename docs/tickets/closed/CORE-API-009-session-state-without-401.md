# Проверка входа при запуске отвечает гостю отказом 401

## Проблема

`AuthSession.ready()` при запуске спрашивал `GET /api/auth/me`, и гостю
точка отвечала `401`. Браузер пишет каждый ответ 401 ошибкой консоли, и
замер качества страницы отказывал из-за вызова, который делает ядро и
который проект обойти не может.

## Подтверждение

Заявка потребителя [issue #64](https://github.com/apocarteres/platform/issues/64)
(clanlog, ядро 13.0.0), замер Lighthouse гостевого экрана. Сверено
2026-09-28 по цепочке `platform-auth` и `AuthSession.load`.

## Последствия при сохранении текущего поведения

Гостевой экран любого проекта ядра не проходит проверку ошибок консоли.

## Решение владельца

Решение владельца от 2026-09-28: новая точка `/api/auth/session`, `/me` без
изменений — совместимо.

## Требуется

`REQ-AUTH-035`.

## Критерии приёмки

- Тест первым: клиент при запуске спрашивает `/session` и не спрашивает
  `/me`; гость — `account()` = `null`; генератор типов понимает `oneOf`.
  Клиентские тесты падали до правки. Java-тест точки написан до правки, но
  отдельного красного прогона не было: его роль сыграла проба «точка закрыта»,
  при которой тест падает с `401`.

## Что сделано

- `GET /api/auth/session`, открыта всем; контракт; `AuthSession` читает
  состояние по ней; генератор типов — `oneOf`.
- Пробы: 2 на Java и 2 на клиенте — все пойманы.
