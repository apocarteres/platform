# Страница уведомлений и панель только с непрочитанными

## Проблема

Колокольчик отдавал только последние уведомления, не больше 50: всё старше
человек не видел никогда, хотя уведомление хранится 90 дней. Точки для
страницы «Все уведомления» не было. Панель смешивала прочитанное с
непрочитанным.

## Подтверждение

Заявка потребителя [issue #63](https://github.com/apocarteres/platform/issues/63)
(clanlog, ядро 12.3.0). Сверено 2026-09-28 по `NotificationController` и
`NotificationBell`.

## Последствия при сохранении текущего поведения

Уведомления старше последних 50 недоступны; каждый проект пишет свою точку
чтения мимо ядра.

## Решение владельца

Решение владельца от 2026-09-28: панель у всех — только непрочитанные
(несовместимо, старшая версия); постраничность — по номеру страницы с числом
всего.

## Требуется

`REQ-NOTIFICATIONS-009` — `GET /api/notifications/page`; `REQ-NOTIFICATIONS-004`,
`005` — панель и `items` только с непрочитанными, `NotificationBell.page()`.

## Критерии приёмки

- Тесты первыми: страница — все свои свежими сверху с числом всего, отбор
  непрочитанных, пределы страницы, чужих нет; колокольчик — только
  непрочитанные; клиент — `page()` с параметрами, `read()` убирает из
  панели, прочтение на странице перечитывает число. Тесты падали до правки.

## Что сделано

- `platform-notifications`: точка `/page`, код `notification-page-rejected`,
  непрочитанные в списке колокольчика; контракт.
- `@apocarteres/notifications`: `page()`, `read()` и `readAll()` чистят панель.
- Требования и инструкция колокольчика.
- Пробы: 7 на Java и 5 на клиенте — все пойманы.
