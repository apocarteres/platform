# Повторный номер выпуска перезаписывал закрытый документ

## Проблема

`REQ-RELEASE-005` запрещает переиспользовать номер выпуска, но открытие
следующего выпуска номер на занятость не проверяло. Ошибка в аргументе
команды приводила к записи документа поверх только что закрытого.

## Подтверждение

Наблюдение 2026-09-07: при закрытии выпуска `RELEASE-0-29-0` номер следующего
был задан тем же — `0.29.0`. Команда сообщила «Тег выпуска: v0.29.0» и сразу
«Открыт выпуск RELEASE-0-29-0», а на диске остался черновик: состав, результат
и отмеченные критерии закрытого выпуска были затёрты. Тег при этом уже
существовал, поэтому повторное закрытие было невозможно.

Потеря была небольшой только потому, что документ не был зафиксирован в
истории: восстановление свелось к возврату рабочего дерева и снятию тега.

## Последствия при сохранении текущего поведения

Опечатка в номере уничтожает запись о выпуске — то самое свидетельство, ради
которого цикл существует. Тег остаётся, документ теряется, и состояние
репозитория противоречит `REQ-RELEASE-006` о неизменности закрытого выпуска.

## Ожидаемый результат

Открытие выпуска с занятым номером отказывает и ничего не пишет. Закрытый
документ остаётся на месте, а команда называет причину и просит следующий
номер.

## Критерии приёмки

- [x] Открытие выпуска отказывает, если документ с таким номером уже есть — `lib/release/cycle.mjs`
- [x] Тест проверяет, что закрытый документ после отказа не изменился; обратный опыт: без проверки падает ровно один тест из 13
