# Клиент: кнопка удалённого действия

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: одностраничный клиент на Angular.** Кнопка, ждущая удалённого вызова, живёт не только в модальном окне, поэтому её поведение записано отдельно от окон. Решение — `ADR-0005`. Оформление ожидания — указатель, текст, иконка — остаётся проекту.

**Уровень требования: директива.**

## Запуск

1. <a id="REQ-CLIENT-ACTION-001"></a> **REQ-CLIENT-ACTION-001** — Удалённое действие кнопки запускает ядро, а не вызывающий код. Кнопка объявляется директивой `apcrAction` из пакета `@apocarteres/action`: вход `[apcrAction]` — само действие, функция, возвращающая обещание или поток; вход `[apcrActionFailure]` — куда идёт отказ. Оба входа обязательны: сборка со строгой проверкой шаблонов отказывает кнопке без них, при запуске директива отказывает тоже. Успех приходит событием `(apcrActionDone)` с результатом. Цена названа в `ADR-0005`: потребитель отдаёт ядру запуск вызова.

## Ожидание

2. <a id="REQ-CLIENT-ACTION-002"></a> **REQ-CLIENT-ACTION-002** — Ожидание ведёт ядро. Признак ожидания снимается при любом исходе — успехе, отказе, исключении, брошенном самим действием; признак, не снятый при отказе, выключил бы кнопку навсегда, и такую ошибку не видит ни одна проверка. Ожидание отменяется при уничтожении кнопки: поздний ответ никуда не доходит. На время ожидания у кнопки стоит `aria-busy`. Признак читается шаблоном — `#act="apcrAction"`, `act.pending()` — и совмещается с собственными условиями проекта; свойство `disabled` директива не трогает, чтобы не спорить с привязкой проекта.
3. <a id="REQ-CLIENT-ACTION-003"></a> **REQ-CLIENT-ACTION-003** — Повторный запуск во время ожидания не выполняется, откуда бы ни пришло нажатие: щелчком, клавишей или отправкой формы. Нажатие на кнопку действия форму не отправляет: путь к действию один, и второй путь через отправку формы дал бы второй запрос.

## Отказ

4. <a id="REQ-CLIENT-ACTION-004"></a> **REQ-CLIENT-ACTION-004** — Отказ не поглощается: он доходит до обработчика `[apcrActionFailure]` таким, каким пришёл, — с перехватчиком ядра это `ApiFailure` (`REQ-API-001`). Ядро не толкует действие: не разбирает результат, не повторяет вызов и не показывает сообщений.
