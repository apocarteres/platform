# Ядро навязывает Java и Angular проекту, которому нужны только правила

## Проблема

Подключение заводит задачами все действующие обязательства ядра
(`REQ-ADOPTION-013`, `REQ-RELEASE-013`). Из 28 обязательств около 15 касаются
только Java, Spring или Angular. Проекту без этих стеков приходится закрывать
каждое руками командой `release satisfy` с причиной «не относится». README и
описание репозитория ставят на первое место модули Java и Angular, а пакет
правил — третьим пунктом.

## Подтверждение

Наблюдение владельца от 2026-10-15: потребитель legacy-store хочет только
правила управления проектом. Сверка с ядром 15.3.0: в каталоге обязательств
нет признака стека; `loadObligations` отдаёт все обязательства любому
проекту.

## Последствия при сохранении текущего поведения

Подключение только правил стоит десятка ручных закрытий, и ядро выглядит
стеком, а не порядком ведения проекта.

## Решение владельца

Решение владельца от 2026-10-15: проект объявляет стек, объявление
сверяется с файлами сборки; акцент — на пакете правил и удобстве для
AI-агентов.

## Требуется

1. `REQ-ADOPTION-028`: поле `stack`, разметка обязательств стеком, сверка с
   файлами сборки; уточнить `REQ-ADOPTION-013`, `REQ-RELEASE-013` и
   `AGENTS.md`.
2. Каталог обязательств размечен; обязательство полного прогона — `java`.
3. README и описание репозитория начинаются с пакета правил и удобства для
   агентов; библиотеки Java и Angular — по желанию.

## Критерии приёмки

- Тест первым: неизвестный стек назван; найденный файл сборки
  необъявленного стека — отказ `check`; обязательство чужого стека не
  относится к проекту и показано `obligations`; без `stack` относятся все.
- Пробы: снятый фильтр, снятая сверка, `node_modules` в сверке — тесты
  падают.

## Откуда пришла задача

Разговор с владельцем 2026-10-15 об открытии проекта.
