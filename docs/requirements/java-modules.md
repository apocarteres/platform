# Java: модульность и граф связей

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: Java-код любого сервиса и библиотеки.** Требования не зависят от предметной области.

**Уровень требования: директива.** Модульность не предлагается к выбору: это условие, при котором остальные правила ядра исполнимы.

## Модуль

1. <a id="REQ-JAVA-MODULES-001"></a> **REQ-JAVA-MODULES-001** — Java-код разделён на модули. Модуль экспортирует контракты корневым пакетом; реализация лежит во внутренних подпакетах и снаружи не используется. Модуль — единица, которую можно прочитать, проверить и заменить целиком, не читая остального; без этой границы «общий код» означает лишь общий каталог. Решение владельца от 2026-09-12.
2. <a id="REQ-JAVA-MODULES-002"></a> **REQ-JAVA-MODULES-002** — Межмодульные зависимости объявлены явно и читаются как перечень, а не восстанавливаются чтением импортов. Зависимость, о которой знает только компилятор, не обсуждается при изменении и потому растёт незаметно.

## Граф связей

3. <a id="REQ-JAVA-MODULES-003"></a> **REQ-JAVA-MODULES-003** — Граф связей модулей — направленный ациклический. Он читается слева направо и сверху вниз: у каждой связи есть направление, и обратных нет. Циклические зависимости запрещены категорически — и явные, когда два модуля называют друг друга, и косвенные, когда путь замыкается через третий. Цикл отменяет смысл границы: модуль в цикле нельзя ни собрать, ни проверить, ни заменить отдельно, а его тест тянет за собой всё кольцо. Косвенный цикл опаснее явного: в объявлениях он не виден и обнаруживается только обходом графа. Решение владельца от 2026-09-12.
4. <a id="REQ-JAVA-MODULES-004"></a> **REQ-JAVA-MODULES-004** — Цикл снимается изменением устройства, а не исключением из правила: общая часть выносится в третий модуль, от которого зависят оба, либо обратная связь обращается портом — потребитель объявляет интерфейс, поставщик его реализует. Временное исключение не вводится: цикл, объявленный временным, переживает и того, кто его объявил, и причину, по которой он понадобился.

## Проверка

5. <a id="REQ-JAVA-MODULES-005"></a> **REQ-JAVA-MODULES-005** — Соответствие проверяется структурной проверкой в наборе `check` (`REQ-QUALITY-001`), а не чтением глазами: граф связей растёт при каждом изменении, и отсутствие цикла — утверждение о всём графе, а не о правке. Штатный путь — проверка модульной модели и правил доступа средствами платформы приложений и библиотеки архитектурных тестов; собственная реализация, утверждающая то же самое, ей равноценна (`REQ-ADOPTION-021`).
