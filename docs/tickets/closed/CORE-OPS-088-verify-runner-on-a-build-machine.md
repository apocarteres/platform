# Набор проверок ядра в сборочном контейнере на машине сборки

## Проблема

Модули ядра с Redis и Postgres проверяются на настоящем хранилище через
Testcontainers. На машине разработки локального Docker нет, а машина сборки
доступна контекстом Docker по ssh. Напрямую с неё Testcontainers работать не
может: контексты по ssh он не понимает, а порты контейнеров на машине сборки
намеренно открыты только на `127.0.0.1`.

## Решение владельца

Решение владельца от 2026-09-24: свой сборочный контейнер ядра на машине
сборки, по образцу потребителя; порты машины сборки остаются закрытыми.

## Требуется

1. Образ несёт только `mise` и системное; версии инструментов берутся из
   `mise.toml` ядра командой `mise install` внутри контейнера и кешируются
   томом.
2. `mise run verify-runner-prepare` собирает образ и контейнер на машине
   текущего контекста Docker.
3. `mise run verify-runner [--commit REF]` загружает репозиторий пакетом git,
   прогоняет `mise run verify` в контейнере и переносит расписку в
   `target/verify/`.
4. Testcontainers внутри контейнера обращается к сокету Docker машины и к
   опубликованным портам через `host.docker.internal`.

## Что сделано

- `scripts/verify-runner/`: образ с `mise`, `git` и системным; инструменты из
  `mise.toml` ставит `mise install` в том домашнего каталога.
- `mise run verify-runner-prepare`, `mise run verify-runner [--commit REF]`,
  `--run "<команда>"` для точечного прогона без расписки.
- Хук `pre-push` требует расписку на отправляемое дерево кода —
  `conventions attested` (`REQ-QUALITY-004` уточнено: второй вид шлагбаума);
  корень хука — рабочее дерево отправки, а не место ссылки на хук.
- `mise run release` набор не гоняет, `install-local` публикует без повторного
  прогона тестов.
- Первый прогон на чистом дереве нашёл дефект `scripts/web.sh`: зависимости
  пакета ставились, когда до него доходила очередь, а разбор всех пакетов
  берёт общую настройку `project-conventions`. Теперь зависимости ставятся
  всем пакетам до первого сценария.

## Чем закреплено

- Полный `verify` ядра пройден в контейнере на машине сборки, расписка
  перенесена.
- Тест `attested`: расписка по дереву кода переносится через правку
  документов и не переносится через правку кода; расписка без нужного набора и
  расписка неудачного прогона не принимаются. Три пробы намеренной поломкой.
