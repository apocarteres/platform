# Созданное уведомление нельзя поправить

## Проблема

Колокольчик ядра (`REQ-NOTIFICATIONS`) умеет только создать уведомление,
стереть его по сроку и стереть все уведомления учётной записи. Когда в
источнике исправили то, из чего собраны параметры уведомления, прежние
параметры остаются в колокольчике до конца срока хранения — 90 дней.

## Подтверждение

Заявка потребителя от 2026-11-13: данные, по которым собраны параметры
уведомления, исправлены или удалены в источнике, а в колокольчике у всех, кого
уведомили, остаются прежние параметры. `Notifications` в 17.6.1 — `notify`,
`purgeExpired`, `erase`: поправить или убрать одно уведомление проект не может,
кроме SQL в таблицу ядра в обход его API.

## Последствия при сохранении текущего поведения

Исправленное в источнике остаётся видно в колокольчике; потребитель либо
мирится с этим, либо пишет в таблицу ядра сам и привязывается к её
устройству.

## Решение владельца

Решение владельца от 2026-11-13: доработать ядро — API правки или удаления
уведомления; потребитель переходит на него.

## Требуется

1. `Notifications.revise(kind, link, change)`: уведомления вида `kind` со
   ссылкой `link` у всех учётных записей проходят через `change`; новые
   параметры — по правилам создания, `null` убирает уведомление, те же
   параметры уведомление не трогают.
2. Прочитанность и время создания не меняются; правка — в транзакции
   вызывающего.
3. Требование `REQ-NOTIFICATIONS-010`, индекс по ссылке и виду.

## Критерии приёмки

- Правка меняет параметры только у уведомлений названного вида и ссылки,
  у всех учётных записей; прочитанное остаётся прочитанным.
- `null` убирает уведомление; те же параметры не считаются правкой.
- Параметры правки проверяются как при создании; нарушение — отказ, без
  частичной правки.
- Откат транзакции вызывающего откатывает правку.
- `mise run check` зелёный.

## Ход работы

- 2026-11-13 — `Notifications.revise`, `REQ-NOTIFICATIONS-010`, журнал
  `002-notification-link` (индекс `platform_notification (link, kind)`),
  тесты `NotificationFlowTest.reviseChangesTheKindAndLink` и
  `reviseValidatesAndJoinsTheTransaction`.
- 2026-11-13 — по ревью: требование называет обязательную ссылку, чистую
  функцию `change` и неатомарность вне транзакции; `CoreChangelogTest`
  сверяет и индексы образцов с журналами.
- 2026-11-13 — для документа выпуска: новый метод интерфейса `Notifications`
  (потребитель, реализующий его сам, добавит метод); индекс строится без
  `CONCURRENTLY` — запись в таблицу ждёт построения; база, созданная по
  образцу до этого выпуска и принимающая журналы ядра `changelogSync` уже с
  ним, сначала создаёт индекс `platform_notification_link` сама.
