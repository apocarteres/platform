# Версионирование и публикация артефактов ядра

[Карта требований](../REQUIREMENTS.md) · [Инструкция по GitHub Packages](../runbooks/local-publishing.md)

## Координаты

1. <a id="REQ-PUBLISHING-001"></a> **REQ-PUBLISHING-001** — Java-артефакты публикуются с groupId `io.github.apocarteres.platform`, npm-пакеты в scope `@apocarteres`. Координаты не зависят от registry и не меняются при его смене.
2. <a id="REQ-PUBLISHING-002"></a> **REQ-PUBLISHING-002** — Версия артефактов задаётся тегом `vX.Y.Z` в репозитории ядра и совпадает с ним без префикса. Все артефакты одного тега имеют одну версию; в POM версия не хранится и подставляется при сборке.
3. <a id="REQ-PUBLISHING-003"></a> **REQ-PUBLISHING-003** — Публикуются только версии из тега. Версии с суффиксом `-SNAPSHOT` и зависимости на такие версии отклоняются публикацией.

## Совместимость

4. <a id="REQ-PUBLISHING-004"></a> **REQ-PUBLISHING-004** — Версии следуют semver: patch и minor не ломают потребителя, major означает несовместимое изменение. Несовместимое изменение не сопровождается сохранением старого контракта рядом с новым.
5. <a id="REQ-PUBLISHING-005"></a> **REQ-PUBLISHING-005** — Каждая major-версия сопровождается описанием миграции потребителя в документе выпуска. Потребитель переходит на неё одним изменением, без переходного периода с двумя контрактами.

## Состав публикации

6. <a id="REQ-PUBLISHING-006"></a> **REQ-PUBLISHING-006** — `platform-bom` перечисляет все публикуемые Java-артефакты ядра одной версии. Потребитель импортирует BOM и подключает артефакты без указания версий.
7. <a id="REQ-PUBLISHING-007"></a> **REQ-PUBLISHING-007** — Артефакты публикуются локально, а не в удалённый registry: Java-артефакты устанавливаются в локальный репозиторий Maven, npm-пакет собирается архивом. Решение владельца от 2026-09-07: GitHub остаётся хранилищем репозитория, и сборка не зависит от учётных данных registry ни на машине разработчика, ни на машине сборки.
8. <a id="REQ-PUBLISHING-010"></a> **REQ-PUBLISHING-010** — Потребитель фиксирует версию ядра ссылкой на его коммит или тег и получает артефакты, собрав ядро из этого состояния. Публикация и потребление выполняются одной командой у каждой стороны; сборка на любой машине воспроизводима без сети, кроме первичного получения зависимостей.

## Ветвление

9. <a id="REQ-PUBLISHING-008"></a> **REQ-PUBLISHING-008** — Работа ведётся в ветке `main`; тег выпуска ставится на её коммит, прошедший проверки. Релизных веток нет: исправление в опубликованной версии выходит следующей patch-версией из `main`.
10. <a id="REQ-PUBLISHING-009"></a> **REQ-PUBLISHING-009** — Опубликованная версия неизменна. Ошибочный выпуск не перепубликуется под тем же номером и не удаляется из registry; вместо этого выпускается следующая версия.
