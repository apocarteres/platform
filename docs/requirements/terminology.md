# Терминология

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: документы проекта.** Код под это требование не подпадает: прозы в комментариях нет по `REQ-CODE-COMMENTS-000`.

**Уровень требования: смешанный, назван в каждом положении.**

## Источник слов

1. <a id="REQ-TERMS-001"></a> **REQ-TERMS-001** — Слова, которыми написаны правила, задаёт ядро каталогом `docs/terms`. В каталоге два файла: `DEFINITIONS.md` — толкование терминов, `ALIAS.md` — подстановки. Порядок работы описывает `RULES.md` каталога (`REQ-PROJECT-PROCESS-004`). Правило, написанное словами, которых никто не определил, исполняется каждым по-своему, и расхождение обнаруживается на разборе, а не на проверке. Решение владельца от 2026-09-12.
2. <a id="REQ-TERMS-002"></a> **REQ-TERMS-002** — Потребитель словарь ядра не изменяет: он объявляет собственный каталог `docs/terms` по тем же правилам и добавляет в него свои термины. Замена слова ядра его же именем означала бы, что одно слово значит разное в ядре и у потребителя, — то есть ровно то, против чего словарь введён. Решение владельца от 2026-09-13.
3. <a id="REQ-TERMS-003"></a> **REQ-TERMS-003** — Слово, определённое и ядром, и потребителем с разными толкованиями, называется проверкой. Имя, занятое потребителем, ядро молча не отбирает: расхождение видно обеим сторонам, решение остаётся за потребителем.

## Уровни

4. <a id="REQ-TERMS-004"></a> **REQ-TERMS-004** — `DEFINITIONS.md` — рекомендация: длинный оборот вместо термина ошибкой не считается, но проверка его называет. `ALIAS.md` — директива: слово из левого столбца в текстах проекта не употребляется. Разный уровень у файлов одного каталога назван прямо, иначе его выведут неверно.
5. <a id="REQ-TERMS-005"></a> **REQ-TERMS-005** — Запись `ALIAS.md` несёт причину запрета. Запрет без причины переживает своё основание: через полгода слово запрещено, а почему — не помнит никто, и снять запрет так же нельзя, как обосновать.
6. <a id="REQ-TERMS-006"></a> **REQ-TERMS-006** — Запись вносится, когда непонимание или разнобой уже стоили чего-то: есть случай, ссылка на задачу или заявку. Словарь «про запас» не читают, а читают короткий.

## Охват проверки

7. <a id="REQ-TERMS-007"></a> **REQ-TERMS-007** — Проверка читает документы проекта. Существующий текст не правится: прежние вхождения засеиваются ограничителем один раз и дальше могут только убывать (`REQ-QUALITY-007`, `REQ-ADOPTION-011`). Решение владельца от 2026-09-13.
8. <a id="REQ-TERMS-008"></a> **REQ-TERMS-008** — Сообщения фиксаций проверкой не читаются. Опубликованная история не переписывается, поэтому нарушение в сообщении неисправимо, а отказ, которого нечем удовлетворить, подталкивает к обходу правила вместо его исполнения (`REQ-RELEASE-039`).
9. <a id="REQ-TERMS-009"></a> **REQ-TERMS-009** — Подстановка не применяется к цитатам: блоки кода, код внутри строки и цитаты через `>` пропускаются. Заявка потребителя, приведённая в задаче, остаётся его словами; исправленная цитата перестаёт быть цитатой.
10. <a id="REQ-TERMS-010"></a> **REQ-TERMS-010** — Сам каталог словаря из проверки исключён: иначе запрещённое слово нельзя было бы назвать в записи, которая его запрещает.
