# web.sh не переставляет зависимости пакета при устаревшем node_modules

## Проблема

`scripts/web.sh` ставит зависимости пакета (`npm ci`), только когда каталога `node_modules` нет (строка 22). Если каталог есть, но собран по прежнему файлу блокировки, установка пропускается, и шаг падает на отсутствующем инструменте.

## Подтверждение

2026-10-15, клон ядра отставал на 165 коммитов: `mise run verify` упал на `web-lint` — `sh: eslint: command not found` в `packages/http` (каталог `node_modules` был, `node_modules/.bin/eslint` не было). Обход вручную: `npm ci` во всех пакетах, после чего набор прошёл (`verify-runner`, расписка на `eee5c22`).

## Последствия при сохранении текущего поведения

Набор на долго не обновлявшемся клоне падает с отказом, не называющим причину; исполнитель чинит окружение руками.

## Требуется

1. Установка по состоянию файла блокировки, а не по наличию каталога — например `conventions deps --dir <пакет>` (`REQ-DEPS`), как для зависимостей пакета правил.

## Критерии приёмки

- Тест: пакет с `node_modules` от прежнего файла блокировки — `web.sh` переставляет зависимости, шаг проходит.
