# Выпуск 16.0.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Несовместимые изменения

- Проверка коммитов (`conventions commits`, шлагбаум `pre-push`) и закрытие выпуска отказывают на коммите, который называет задачу, отсутствующую в `docs/tickets` на вершине изменения (`REQ-PROJECT-PROCESS-023`, `REQ-RELEASE-036`). Прежде проверялась только форма идентификатора.

## Миграция

1. Перед обновлением выполнить `conventions release status`: коммиты открытого выпуска, которые называют незаведённую задачу, после обновления удержат закрытие.
2. Для каждого такого коммита: завести задачу с этим идентификатором либо учесть коммит командой `release account <хеш> --reason "<причина>"`. Уже отправленную историю не переписывать.
3. Командам, которые работают через pull request, передать порядок из [RUN-PULL-REQUESTS](../runbooks/pull-requests.md): задача — в том же PR, коммиты начинаются с её идентификатора, занятый номер переносится `conventions tickets-renumber <ИД> --base main`.
4. При слиянии squash заголовок начинать с идентификатора задачи PR.
