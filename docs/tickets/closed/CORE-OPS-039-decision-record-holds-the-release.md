# Запись решения по незавершённой задаче удерживает закрытие выпуска

## Проблема

Коммит, фиксирующий ответ владельца на открытый вопрос задачи, называет эту
задачу (`REQ-PROJECT-PROCESS-023`), но работы по ней не завершает: задача ждёт
внешнего условия. Проверка принадлежности считала такой коммит работой вне
состава и роняла закрытие.

Оба выхода, которые называет `REQ-RELEASE-039`, для записи решения не годятся:
довести задачу до выполненного состояния нельзя — она ждёт не нас; отменить
коммит значит стереть ответ владельца из единственного места, где он записан.

## Чем подтверждено

Заявка потребителя [issue #7](https://github.com/apocarteres/platform/issues/7),
ядро 1.11.0, задача `ZAVPN-OPS-039`. Выпуск `RELEASE-2026-09-12` не закрывается
из-за двух коммитов, записавших ответы владельца по `ZAVPN-OPS-021` и
`ZAVPN-FEAT-009`.

Находка воспроизводится сама на себе: коммит, заводящий задачу о ней, называет
эту задачу, задача остаётся открытой до ответа ядра, и закрытие упирается уже в
неё.

Тот же тупик ядро прошло у себя 2026-09-12 при выпуске 1.9.0: пять
исследовательских задач удерживали закрытие своими записями. Тогда владелец
решил не ослаблять правило, и работа была доведена до конца — но это был выбор
там, где он был возможен. У записи решения выбора нет.

## Что сделано

Принят третий из названных потребителем вариантов — сверка по содержимому.
Коммит, изменивший только документы задач, считается записью о ходе работы:
задачу в состав он не втягивает и закрытие не роняет. Коммит, тронувший хоть
один файл вне каталога задач, — работа со всеми последствиями.

Почему не метка в сообщении (вариант 1): запись о задаче отличается от работы
по ней именно содержимым, и объявление словами подделывалось бы легче, чем
метка отмены. Почему не внесение задачи в состав открытого выпуска (вариант 2):
оно возвращает к тому же тупику — снятая с причиной задача удерживает выпуск,
пока её коммиты в диапазоне (`REQ-RELEASE-036`).

`REQ-RELEASE-040` записывает это положение и прямо называет его единственным
местом, где проверка смотрит на изменения, а не на сообщение.

Закреплено тестом в обе стороны: запись решения в документе задачи закрытие не
удерживает, работа по той же задаче — удерживает. Два прежних теста, где работа
изображалась правкой документа задачи, переписаны на правку исходников: они
проверяли не то, что заявляли.

## Критерии приёмки

- Коммит, изменивший только документы задач, закрытие не роняет.
- Коммит той же задачи, тронувший исходники, роняет закрытие по-прежнему.
- Задача, по которой есть только запись, в состав выпуска не попадает.
