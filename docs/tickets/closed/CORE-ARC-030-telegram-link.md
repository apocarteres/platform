# Учётную запись ядра нельзя связать с Telegram

## Проблема

Потребители просят вход и уведомления через Telegram, а у ядра нет связи
учётной записи с человеком в Telegram. Каждый проект пишет свой бот, свой
webhook и своё хранение `chat_id`, а без связи нельзя ни доставить
уведомление, ни пустить человека по Telegram.

## Подтверждение

Просьбы потребителей о входе и уведомлениях через Telegram, разговор с
владельцем 2026-11-16. Внешняя личность Telegram есть только у Mini App и
только на один запрос (`REQ-AUTH-037`), без связи с учётной записью.

## Последствия при сохранении текущего поведения

Связь, проверка webhook и хранение `chat_id` — персональных данных —
повторяются в каждом проекте и расходятся по копиям.

## Решение владельца

Решение владельца от 2026-11-16: Telegram — подключаемый модуль ядра
`platform-telegram`, по этапам: связь, затем уведомления, затем вход Mini
App, затем вход на сайт и второй шаг. Учётных записей без почты не
заводить: почта обязательна (`REQ-AUTH-001`).

## Требуется

1. Модуль `platform-telegram`: токен бота из окружения, клиент Bot API;
   webhook на своём пути под `/api/**` сверяет секретный заголовок
   `X-Telegram-Bot-Api-Secret-Token` постоянным сравнением.
2. Связь: вошедший получает одноразовую ссылку `t.me/<бот>?start=<токен>`
   с коротким сроком; `/start <токен>` записывает связь учётной записи с
   `chat_id`; повтор и чужой токен — отказ; одна связь на учётную запись.
3. Связь видна и снимается её владельцем; стирание учётной записи
   (`REQ-AUTH-024`) стирает связь; `chat_id` и идентификатор Telegram —
   персональные данные, в журналы и метрики не попадают (`REQ-AUTH-040`).
4. Клиент: `TelegramLink` в Angular — ссылка, состояние, снятие; экраны
   рисует проект.
5. Требования нового документа, контракт OpenAPI, журнал Liquibase.

## Критерии приёмки

- Связь появляется только по действующему токену своего владельца;
  истёкший, повторный и чужой токен отклоняются.
- Webhook без верного секрета отвечает отказом и ничего не меняет.
- Стирание учётной записи стирает связь.
- `mise run verify` зелёный.

## Ход работы

- 2026-11-16 — требования `REQ-TELEGRAM-001`…`013`; модуль
  `platform-telegram`: настройки бота, webhook через порт
  `RequestAuthenticator` (`REQ-AUTH-037`) — отдельной цепочки безопасности
  нет (`REQ-AUTH-022`); таблицы `platform_telegram_link` и
  `platform_telegram_invite` с каскадом от `platform_account`; `TelegramLinks`,
  `TelegramBot`, `TelegramReplies`; клиент `@apocarteres/telegram` —
  `TelegramLink`.
- «Чужой токен» понят так: токен, которого ядро не выдавало, и токен,
  предъявленный человеком Telegram, уже связанным с другой учётной записью.
  Токен — одноразовая ссылка: кто её получил, тот и связывает; поэтому срок
  короткий, 10 минут.
- Ответ в чат на `/start` — телом ответа webhook, текст даёт проект портом
  `TelegramReplies`; без порта бот молчит.
