# Команда расписки подтверждает проверки, которых не было

## Проблема

`conventions receipt` записывает расписку о пройденном наборе при любом
аргументе, включая `--help` и опечатку. Расписка утверждает прохождение
`verify` на текущем коммите, а закрытие выпуска ей доверяет: по
`REQ-RELEASE-003` при наличии расписки для коммита проверки не запускаются.
Значит случайный вызов создаёт документ, на основании которого выпускается
непроверенное состояние.

## Чем подтверждено

Опыт 2026-09-09 в пустом репозитории с одним пустым коммитом:

```
$ conventions receipt --help --root <repo>
Расписка о проверках записана: target/verify/b2a01214….json

$ cat target/verify/b2a01214….json
{ "commit": "b2a01214…", "completedAt": "2026-09-09T11:50:09Z", "checks": ["verify"] }
```

Проверок в этом репозитории не запускалось: в нём нет кода. Дефект обнаружен у
потребителя `zavpn`, где такой же вызов записал расписку на рабочем коммите;
файл был удалён до того, как им воспользовалось закрытие выпуска.

Причина в двух местах `packages/project-conventions/bin/conventions.mjs`:

1. Строка 408 отбрасывает из аргументов всё, что начинается с `--`, и передаёт
   остаток как перечень пройденных наборов. Неизвестный аргумент не отвергается,
   `--help` не обрабатывается.
2. Строка 181 при пустом перечне подставляет `['verify']`, поэтому вызов без
   осмысленных аргументов утверждает прохождение полного набора.

Третье, более глубокое: расписка фиксирует заявленное, а не наблюдённое.
Совпадение перечня с реально выполненными наборами не проверяется, хотя
`REQ-RELEASE-018` описывает расписку как свидетельство машины.

## Последствия при сохранении текущего поведения

1. Выпуск любого потребителя можно закрыть без проверок: достаточно случайного
   вызова команды расписки на нужном коммите.
2. Поддельная расписка неотличима от законной по содержимому, поэтому ошибка не
   оставляет следа.
3. Правило «зелёная проверка сама по себе корректности не доказывает» теряет
   основание: сама запись о проверке перестаёт означать, что проверка была.

## Требуется

1. Команда отвергает неизвестные аргументы и обрабатывает `--help` выводом
   справки, а не записью файла.
2. Пустой перечень наборов является ошибкой, а не полным набором по умолчанию.
3. Расписка содержит признак прогона, отличающий свидетельство машины от ручной
   записи: например, имя выполненной задачи менеджера окружения и её код
   возврата.
4. Закрытие выпуска отвергает расписку без такого признака.

## Критерии приёмки

- `conventions receipt --help` печатает справку и файлов не создаёт.
- `conventions receipt <неизвестный аргумент>` завершается ошибкой и файлов не
  создаёт.
- Расписка без явного перечня наборов не записывается.
- Закрытие выпуска отвергает расписку, не содержащую признака прогона.
- Отказ и успех обоих случаев закреплены тестами пакета.

## Ход выполнения

### Взято в работу (2026-09-09)

Задача взята в работу с расчётом выйти в ближайшем выпуске. Поле `release`
остаётся `unassigned`: по `REQ-RELEASE-007` состав выпуска — запись сделанного,
и задача попадёт в состав закрываемого выпуска автоматически при закрытии, если к этому
моменту перейдёт в терминальный статус. Заранее назначать выпуск не требуется,
а состав документа выпуска заполняет команда цикла (`REQ-RELEASE-022`).

Порядок работы соответствует разделу «Требуется»: разбор аргументов команды
расписки, отказ при пустом перечне наборов, признак прогона в расписке и
отклонение расписки без признака при закрытии выпуска. Ни один пункт пока не
выполнен.

### Шаг 1 (2026-09-09)

Разбор аргументов команды расписки заменён строгим: перечень наборов задаётся
ключом `--checks`, команда набора перечисляется после `--`. Любой иной аргумент
отвергается с кодом 2, `--help` печатает справку, пустой перечень наборов —
отказ. Подстановки полного набора по умолчанию больше нет.

Признак прогона сделан сильнее, чем предполагал пункт 3 требований: вместо имени
задачи менеджера окружения из переменной среды команда расписки сама выполняет
команду набора и записывает её вместе с наблюдённым кодом возврата
(`run.command`, `run.exitCode`). При ненулевом коде расписка не пишется вовсе.
Имя задачи из переменной среды осталось бы заявлением: его подставляет тот же
вызов, который заявляет наборы, тогда как наблюдённый код возврата подставить
нельзя, не выполнив прогон.

Закрытие выпуска отвергает расписку без признака прогона: `closability`
сообщает `не содержит признака прогона` и тег не ставит.

Задача `verify` в `mise.toml` стала одним шагом:
`conventions receipt --checks check,verify -- mise run check`.

Нормативный текст: `REQ-RELEASE-027` (расписку пишет наблюдавший прогон) и
`REQ-RELEASE-028` (отказ по аргументам и отказ закрытия без признака прогона).
Потребителям объявлено обязательство `observed-receipt` (директива, срок 1
выпуск, начиная с 1.0.0): их задача `verify` вызывает старую форму и после
обновления ядра откажет громко, а не запишет расписку молча.

## Как закрыта

Критерии приёмки проверены на прогонах и закреплены тестами пакета:

- `conventions receipt --help` печатает справку, код 0, файлов не создаёт.
- `conventions receipt check verify` (прежняя форма) отвечает
  `неизвестный аргумент: check` с кодом 2 и файлов не создаёт.
- Расписка без явного перечня наборов не записывается: `--checks` обязателен,
  пустое значение — отказ.
- Закрытие выпуска отвергает расписку без `run`.
- Тесты: два случая в `test/cli.test.mjs` (отказы и наблюдённый прогон) и
  проверка отказа закрытия в `test/release-cycle.test.mjs`.

Прогон `mise run verify` на коммите `882880b` записал расписку с
`run.command: mise run check` и `run.exitCode: 0`; исходный дефект не
воспроизводится.
