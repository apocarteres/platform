# Работа исполнителя над кодом

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

## Диагностика по фактам

1. <a id="REQ-AGENT-WORK-001"></a> **REQ-AGENT-WORK-001** — Менять код на основании неподтверждённой гипотезы запрещено. Сначала собираются факты и выполняется минимальный проверочный опыт, изолирующий предполагаемую причину.
2. <a id="REQ-AGENT-WORK-002"></a> **REQ-AGENT-WORK-002** — Проверочный опыт обратим: временное изменение параметра, точечный счётчик, журнал или запись трафика, сетевая проба, временный контейнер с нужным клиентом. Постоянное состояние рабочих узлов при этом не изменяется.
3. <a id="REQ-AGENT-WORK-003"></a> **REQ-AGENT-WORK-003** — Правка кода допустима только после того, как проверка подтвердила причину, либо после явного разрешения владельца на экспериментальное изменение.
4. <a id="REQ-AGENT-WORK-004"></a> **REQ-AGENT-WORK-004** — В итоговом сообщении разделяются доказанные факты, гипотезы и внесённые изменения.
5. <a id="REQ-AGENT-WORK-005"></a> **REQ-AGENT-WORK-005** — Правка, признанная исправлением, подтверждается обратным опытом: до неё отказ воспроизводится, после неё нет. Совпадение зелёной проверки с правкой доказательством не является.

## Запущенные процессы

6. <a id="REQ-AGENT-WORK-012"></a> **REQ-AGENT-WORK-012** — Процесс, запущенный исполнителем, имеет предел времени. Запуск без предела запрещён: исполнитель не отличает «идёт долго» от «повисло», и ожидание съедает работу целиком.
7. <a id="REQ-AGENT-WORK-013"></a> **REQ-AGENT-WORK-013** — Пределов два: общий и по бездействию. Признак движения — новые строки вывода, а не истекшее время: сборка законно идёт долго, но молчание дольше предела означает зависание.
8. <a id="REQ-AGENT-WORK-014"></a> **REQ-AGENT-WORK-014** — По исчерпании предела процесс завершается: сначала штатным сигналом, затем принудительно, если не завершился за отведённое время. Завершается вся группа процессов, иначе занятый порт, каталог сборки или контейнер остаются за потомком, и следующий запуск отказывает по чужой причине.
9. <a id="REQ-AGENT-WORK-015"></a> **REQ-AGENT-WORK-015** — Завершение по пределу — факт для записи: называется исчерпанный предел, прошедшее время и последние строки вывода. Молча перезапустить процесс нельзя: без записи зависание выглядит случайной задержкой.
10. <a id="REQ-AGENT-WORK-016"></a> **REQ-AGENT-WORK-016** — Пределы по умолчанию: общий 30 минут, по бездействию 5 минут. Задача, которая законно превышает их, задаёт свои значения явно и в задаче объясняет, чем они обоснованы.
11. <a id="REQ-AGENT-WORK-017"></a> **REQ-AGENT-WORK-017** — Повторное зависание — дефект с задачей (`REQ-QUALITY-009`), а не повод поднять предел. Предел поднимается, когда измерением показано, что процесс идёт: движение в выводе есть, а работы больше, чем отведено.
12. <a id="REQ-AGENT-WORK-018"></a> **REQ-AGENT-WORK-018** — Запуск с пределами предоставляет ядро командой пакета: `conventions run --limit <с> --idle <с> -- <команда>`. Обвязка из `sleep` и `kill` в каждом репозитории заново не пишется. Код возврата: собственный код процесса, `124` при исчерпании общего предела, `125` при бездействии.

## Команды оболочки

13. <a id="REQ-AGENT-WORK-006"></a> **REQ-AGENT-WORK-006** — Кавычки выбираются по целевой оболочке, многоуровневого экранирования следует избегать.
14. <a id="REQ-AGENT-WORK-007"></a> **REQ-AGENT-WORK-007** — Для `bash`, `zsh` и других POSIX-оболочек: одинарные кавычки только для литералов без вложенных одинарных; двойные — когда нужны подстановки, с экранированием `$`, `` ` ``, `\` и `"` при передаче через внешнюю оболочку.
15. <a id="REQ-AGENT-WORK-008"></a> **REQ-AGENT-WORK-008** — Сложные удалённые команды, SQL, JSON и фрагменты кода передаются через quoted heredoc или временный файл сценария, а не вложенными одинарными кавычками внутри `ssh '...'`.
16. <a id="REQ-AGENT-WORK-009"></a> **REQ-AGENT-WORK-009** — Для PowerShell: одинарные кавычки для литералов, двойные для подстановки, многострочный текст через here-string. Для `cmd.exe`: двойные кавычки и экранирование `^`, но предпочтительнее PowerShell.
17. <a id="REQ-AGENT-WORK-010"></a> **REQ-AGENT-WORK-010** — Перед изменяющей удалённой командой со сложным экранированием её синтаксис проверяется способом только для чтения либо команда заменяется сценарием или heredoc.
18. <a id="REQ-AGENT-WORK-011"></a> **REQ-AGENT-WORK-011** — Код возврата проверки читается напрямую, а не через конвейер: конвейер возвращает код последней команды и скрывает отказ проверки.
