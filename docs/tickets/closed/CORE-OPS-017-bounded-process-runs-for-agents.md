# Процесс, запущенный исполнителем, мог висеть без предела

## Проблема

Правила ничего не говорили о пределе времени для процесса, который запускает
исполнитель. Зависший запуск выглядит так же, как долгий: вывода нет, кода
возврата нет, и отличить одно от другого нельзя ничем, кроме догадки.

## Подтверждение

В этой же сессии зависание процессов встречалось трижды и каждый раз стоило
работы: ожидание сборки, у которой давно не было вывода; интеграционные тесты,
державшие порт после прерванного прогона; ожидание удалённой команды без
предела. Ни в одном случае завершение не было автоматическим — процесс
останавливали руками, обнаружив тишину.

## Последствия при сохранении текущего поведения

Зависание расходует работу целиком, а не долю: исполнитель ждёт молчащий
процесс, пока ждёт. Потомки зависшего процесса продолжают держать порты и
каталоги сборки, и следующий запуск отказывает по чужой причине, уводя разбор
в сторону.

## Решение владельца от 2026-09-08

Для исполнителей потребителя зафиксировать правило: у запущенной задачи есть
предел; если процесс висит и в журнале нет движения дольше предела, процесс
завершается.

## Ожидаемый результат

Два предела вместо одного: общий и по бездействию, где движением считается
новый вывод, а не истекшее время. Завершается вся группа процессов. Причина
завершения записывается. Средство запуска даёт ядро, а не каждый репозиторий
своей обвязкой из `sleep` и `kill`.

## Критерии приёмки

- [x] Требование [REQ-AGENT-WORK-012…018](../../requirements/agent-work.md#REQ-AGENT-WORK-012) задаёт оба предела, порядок завершения группы процессов, обязательность записи, значения по умолчанию (30 минут и 5 минут) и запрет поднимать предел вместо разбора повторного зависания
- [x] Команда `conventions run --limit <с> --idle <с> -- <команда>` передаёт вывод наружу, сбрасывает предел бездействия на каждой строке, завершает группу штатным сигналом и принудительно через 5 секунд
- [x] Код возврата: собственный код процесса, `124` при общем пределе, `125` при бездействии — проверено измерением на четырёх случаях
- [x] Потомки завершаются вместе с процессом: замер `pgrep` после завершения по бездействию даёт ноль живых
- [x] Отчёт называет исчерпанный предел, прошедшее время и последние строки вывода; при отсутствии вывода говорит об этом прямо
- [x] Семь тестов на запуск; обратный опыт: без сброса предела по выводу падает ровно один из них. Всего в пакете 109 тестов
- [x] Правила ядра поймали собственный новый код дважды и оба раза исправлены по существу: пояснительный комментарий убран, обращение к системным часам вынесено в порт `lib/now.mjs`
