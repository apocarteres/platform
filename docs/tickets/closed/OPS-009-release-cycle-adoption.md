# Принятие цикла выпусков репозиторием с историей

## Проблема

Цикл выпусков наполняет состав закрываемого выпуска по факту: задача,
перешедшая в терминальный статус после предыдущего выпуска, включается
автоматически ([REQ-RELEASE-007](../../requirements/release-cycle.md#REQ-RELEASE-007)).
В репозитории, который принимает цикл после начала работы, предыдущего
выпуска нет, поэтому «после предыдущего» означает «за всю историю».

## Подтверждение

Команда `release open` в zavpn 2026-09-07 открыла первый выпуск и показала
состав из 92 задач. Результат каждой из них давно развёрнут в проде: первый
выпуск объявил бы своим содержимым то, что выпущено до его существования.

## Последствия при сохранении текущего поведения

Первый выпуск любого действующего сервиса содержит ложную запись: тег
утверждает, что в нём выпущено всё, что когда-либо делалось. Состав выпуска
перестаёт быть свидетельством и становится выгрузкой каталога задач,
а значит теряет смысл и для развёртывания, и для разбора инцидентов.

## Ожидаемый результат

Отдельный шаг принятия цикла: уже закрытые задачи помечаются как выпущенные
до цикла, после чего открывается первый выпуск. Состав первого выпуска
наполняется только теми задачами, которые закрыты после принятия.

- [x] Значение `before-cycle` допускается моделью задачи наравне с `unassigned` и идентификатором выпуска — `lib/docs/ticket-model.mjs`
- [x] Команда `conventions release adopt` помечает закрытые задачи и открывает первый выпуск — `lib/release/cycle.mjs`, `bin/conventions.mjs`
