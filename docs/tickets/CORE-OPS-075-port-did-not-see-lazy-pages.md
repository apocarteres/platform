# Порт неизвестного адреса не видел лениво загружаемых страниц

## Проблема

Третий отказ порта — «объявленная страница совпадает с рабочей страницей
проекта» — сравнивал поле значения маршрута. У маршрута, объявленного
загрузчиком, это поле не заполнено никогда, поэтому сравнение не находило
совпадения ни при каком содержимом.

Ленивая загрузка страниц — умолчание современного клиента, а не редкость.

## Чем подтверждено

Заявка потребителя [issue #33](https://github.com/apocarteres/platform/issues/33),
ядро 1.44.0, задача потребителя `CL-QUAL-065`. Замер против поставленного пакета:
два вызова подряд, при значении порт отказывает, при загрузчике пропускает.

## Что это говорит о самой проверке

Дефект, ради которого требование написано, был **на лениво загружаемом
маршруте**: у потребителя маршрут неизвестного пути вёл в лобби через загрузчик.
Требование само называет этот случай своим основанием — и поставка его не
покрывала.

То есть проверка была написана для случая, которого не видела. Пробы на форме,
в которой дефект существовал, не было: заготовки пользовались только значениями.

## Что сделано

Страница «не найдено» объявляется тем же видом, каким объявлены остальные:
значением в поле `notFound` либо загрузчиком в поле `loadNotFound`. Оба вида
сразу и ни одного — отказ.

Совпадение ищется по тому, чем страница объявлена:

- у значений сравниваются сами страницы;
- у загрузчиков сравнивается сначала загрузчик, затем адрес модуля, прочитанный
  из текста функции. Без второго `loadNotFound`, написанный рядом с маршрутом
  лобби теми же словами, остался бы незамеченным — потребитель это и предвидел,
  предлагая сравнение только по ссылке.

Точная часть — совпадение загрузчика; сравнение по адресу модуля читает исходный
текст и потому вспомогательно. Проверено на настоящих загрузчиках, прошедших
преобразование сборщика: он переименовывает вызов, и первая редакция разбора его
не узнавала.

Разрешать загрузчики при сборке маршрутов ядро не станет: это втянуло бы все
страницы в начальный пакет, то есть вылечило бы хуже болезни. Так же рассудил и
потребитель.

**Сверх предложенного: отказ, когда сравнивать не с чем** — страница объявлена
значением, а все маршруты загрузчиком, или наоборот. Без него порт молча ничего
не проверял бы, а это и был нынешний дефект.

## Несовместимость названа

Проект, у которого все маршруты ленивые, а страница объявлена значением,
получит отказ при запуске там, где прежде была тишина. Это намеренно: тишина
означала непроверенное. Миграция — одна строка: `notFound` меняется на
`loadNotFound`. Мажорной версии не заведено, потому что отказ приходит ровно на
той форме, которую требование и запрещает, и единственный проект в этой форме —
тот, что прислал заявку и уже перешёл.

## Чем закреплено

Десять проверок пакета, из них четыре новые: тот же загрузчик; тот же модуль,
объявленный рядом; чужой загрузчик из другого модуля пропускается; отказ, когда
сравнивать не с чем, — в обе стороны.

Различающая сила проверена тремя возвратами прежнего поведения.
