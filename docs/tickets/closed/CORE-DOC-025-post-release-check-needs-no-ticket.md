# Проверка после выпуска требует отдельной задачи-проверки

## Проблема

`REQ-TICKETS-021` выносит критерий, видимый только после завершающего шага
выпуска, в отдельную задачу-проверку, которую закрывает наблюдение после
выпуска. Задача-проверка повторяет критерии приёмки рабочей задачи и вводит
действие после выпуска, которого порядок иначе не требует: критерии приёмки
задача несёт и так (`REQ-TICKETS-001`), а результат после выпуска может
проверить сам автор задачи.

## Подтверждение

Заявка [apocarteres/platform#81](https://github.com/apocarteres/platform/issues/81)
проекта legacy-store: за месяц накопилось 47 открытых задач-проверок, 39 из них
ждут владельца. Не закрываются они потому, что результат после выпуска видит
автор запроса, а не исполнитель и не владелец. Сверка с ядром 17.2.0: правило
записано только текстом, ни одна проверка файла задачи-проверки не требует.

## Последствия при сохранении текущего поведения

Бэклог потребителя растёт задачами, которые никто не закрывает, и за ними не
видно настоящей работы. Каждая выполненная задача с таким критерием рождает
вторую с теми же критериями.

## Решение владельца

Решение владельца от 2026-11-05: критерии приёмки, по которым задача считается
выполненной, в задаче есть всегда; автор задачи после выпуска проверяет
результат сам, и отдельных действий после выпуска это не требует.

## Требуется

1. `REQ-TICKETS-021`: критерий, видимый только после выпуска, остаётся в
   критериях приёмки самой задачи; задача выполнена, когда её результат вошёл
   в выпуск; отдельная задача-проверка и действия после выпуска не требуются;
   опровергнутый результат — новая задача.

## Критерии приёмки

- `REQ-TICKETS-021` не требует задачи-проверки и действий после выпуска.
- Ни одна проверка ядра не требует файла задачи-проверки.
- `mise run docs-check` и `mise run conventions-check` зелёные.

## Ход работы

- `REQ-TICKETS-021` переписано: задача выполнена, когда результат вошёл в
  выпуск; проверяемое до выпуска исполнитель проверяет (`REQ-TICKETS-015`), а
  видимое только после выпуска называет непроверенным (`REQ-TICKETS-003`);
  автор вправе проверить результат после выпуска сам; опровержение — новая
  задача.
- Проверка кода: `git grep` по пакету `project-conventions` не находит ни
  требования `REQ-TICKETS-021`, ни разбора задачи-проверки — проверки менять
  не нужно, тест не пишется: поведения кода изменение не касается.
