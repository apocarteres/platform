# Аутентификация ядра не покрывает то, что у потребителя уже работает

## Проблема

Потребитель, разбирая обязательство `core-auth`, сверил перенос своей
аутентификации с `platform-auth` 7.0.0 и нашёл пять мест, где обойти ядро можно
только записью в его таблицы мимо API или возвратом своих точек:

1. открытые точки `/api/auth/*` регистрируются раньше правил проекта, и
   закрыть их проект не может;
2. в `Accounts` нет создания учётной записи, назначения пароля и поиска, а
   пользователь не может сменить свой пароль;
3. нет действия после подтверждения почты;
4. первый администратор создаётся мимо `RegistrationHook`, без доменного
   профиля;
5. `purgeUnverified` одним удалением падает на первой записи, которую держит
   внешний ключ профиля, и останавливает всю очистку.

## Решение владельца

Решение владельца от 2026-09-24:

1. порт `EntryAccess` с явной заглушкой `EntryAccess.OPEN` — решает, открыты
   ли точки аутентификации для запроса;
2. `Accounts.create`, `Accounts.setPassword`, `Accounts.search`; точка смены
   своего пароля; соединение таблиц проекта с `platform_account` для чтения
   разрешено, запись — только через API;
3. событие `AccountVerified` после фиксации транзакции;
4. одно место создания учётной записи, всегда с хуком; профиль первого
   администратора — из `platform.auth.admin.profile.*`;
5. очистка по одной записи: удержанная внешним ключом запись пропускается и
   считается;
6. в требование — прокси и адрес сети, точка `GET /api/auth/policy`, переход
   завершает все сессии.

Выпуск — старшая версия: новый обязательный порт и хук у первого
администратора.

## Что сделано

- Порт `EntryAccess` (`REQ-AUTH-016`), отказ `entry-closed` 403; токен CSRF и
  правило пароля открыты.
- `Accounts.create`, `setPassword`, `search`, `count`; `POST /api/auth/password`
  и `AuthSession.changePassword` (`REQ-AUTH-009`, `REQ-AUTH-019`).
- Событие `AccountVerified` после фиксации (`REQ-AUTH-017`).
- `AccountCreation` — единственное место создания учётной записи, хук всегда;
  профиль первого администратора из `platform.auth.admin.profile.*`.
- `purgeUnverified` по одной записи, итог `Purged(removed, held)`
  (`REQ-AUTH-013`); выбор `CASCADE`/`RESTRICT` и чтение через соединение —
  в `REQ-AUTH-001`.
- `GET /api/auth/policy` и `AuthSession.policy()` (`REQ-AUTH-018`); прокси и
  адрес сети — в `REQ-AUTH-011`.

## Чем закреплено

- Восемь новых тестов полного цикла на Postgres и Redis, в том числе с
  таблицей профиля под `ON DELETE RESTRICT`; тест клиента на правило пароля.
- Одиннадцать проб намеренной поломкой, каждая роняет тест. Одна проба была
  сломана сама — Error Prone отверг неиспользованный `hashCode()` — и
  пересобрана.
