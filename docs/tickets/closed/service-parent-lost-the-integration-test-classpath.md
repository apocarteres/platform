# Родитель сервиса терял классы проекта в интеграционных тестах

## Проблема

`platform-service-parent` воспроизводил поведение родителя платформы
приложений по перечню: фильтрация настроек, сборка исполняемого артефакта,
версии плагинов. Одна настройка была пропущена — каталог классов для набора
интеграционных тестов, — и набор перестал видеть классы самого проекта.

## Подтверждение

Первый прогон `verify` в потребителе после перевода на родителя ядра:
779 модульных тестов пройдены, затем

```
Failed to execute goal maven-failsafe-plugin:3.5.4:verify (default) on project zavpn:
    Source: ClassSource [className = 'ru.zavpn.traffic.TrafficServiceIT']
    Cause: java.lang.NoClassDefFoundError: ru/zavpn/topology/Topology
```

Причина: сборка исполняемого артефакта заменяет `jar` проекта на исполняемый,
внутри которого классы лежат в `BOOT-INF/classes`. Набор интеграционных тестов
выполняется после сборки артефакта, поэтому на его пути оказывался исполняемый
артефакт вместо каталога классов. Родитель платформы приложений задаёт для
этого набора `classesDirectory`; при воспроизведении настройка была пропущена.

## Последствия при сохранении текущего поведения

Интеграционные тесты у любого потребителя на родителе ядра падают на загрузке
классов проекта, то есть набор `verify` из `REQ-QUALITY-003` не выполняется
вовсе — а именно он даёт расписку для выпуска.

## Ожидаемый результат

Родитель сервиса задаёт каталог классов для набора интеграционных тестов, и
набор работает с классами проекта, а не с исполняемым артефактом.

## Критерии приёмки

- [x] `classesDirectory` задан для набора интеграционных тестов — `platform-service-parent/pom.xml`
- [x] Исходники сервиса не упаковываются отдельным артефактом: библиотечная привязка `attach-sources` в родителе сервиса снята
- [x] `verify` потребителя пройден целиком на этом родителе
