# Сборка

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: сборка любого сервиса.** Требования не зависят от языка и применяются и к ядру, и к потребителям.

**Уровень требования: директива.**

## Где выполняется сборка

1. <a id="REQ-BUILD-001"></a> **REQ-BUILD-001** — Сборка выполняется локально: на машине разработчика и на машине развёртывания. Внешний сервер сборки не используется; основание — [ADR-0003](../decisions/ADR-0003-local-artifact-publishing.md).
2. <a id="REQ-BUILD-002"></a> **REQ-BUILD-002** — Сборка не требует учётных данных. Артефакты общего ядра получаются его сборкой из закреплённой версии, а не чтением из registry: `REQ-PUBLISHING-010`. Секрет, без которого сборка невозможна, считается дефектом сборки.
3. <a id="REQ-BUILD-003"></a> **REQ-BUILD-003** — Единственный вход в сборку и проверки — задачи менеджера окружения. Голая команда инструмента в инструкции, скрипте или задаче CI запрещена: ключи и переменные живут в задаче, а не в памяти запускающего.

## Инструменты

4. <a id="REQ-BUILD-004"></a> **REQ-BUILD-004** — Версии инструментов закреплены в конфигурации менеджера окружения и одинаковы на всех машинах. Сборка и проверки выполняются закреплённой версией, а не той, что оказалась в `PATH`.
5. <a id="REQ-BUILD-005"></a> **REQ-BUILD-005** — Особенности конкретной машины задаются локальным файлом настроек, который не попадает в репозиторий. Обход, нужный одной машине, в общие задачи не вписывается.
6. <a id="REQ-BUILD-006"></a> **REQ-BUILD-006** — Инструмент, которого нет в закреплённом наборе, запускается контейнером с явно указанной версией образа. Установка на хост не требуется, кеш инструмента живёт в томе контейнера.

7. <a id="REQ-BUILD-010"></a> **REQ-BUILD-010** — Версия инструмента объявляется в `mise.toml`, а любое её отражение в других файлах обязано с ним сходиться: `.nvmrc`, `.node-version`, `.tool-versions` — точным значением, `engines.node` в манифестах npm — диапазоном, включающим это значение, `<java.version>` в `pom.xml` — старшей частью. Расхождение отражений — отказ проверки правил, а не расхождение мнений.

## Версия общего ядра

8. <a id="REQ-BUILD-007"></a> **REQ-BUILD-007** — Потребитель закрепляет версию ядра одним файлом с тегом и получает артефакты одной командой. Версия в файле и версия, указанная в описании зависимостей, совпадают; расхождение роняет сборку на этапе разрешения зависимостей.
9. <a id="REQ-BUILD-008"></a> **REQ-BUILD-008** — Обновление версии ядра — отдельное изменение: файл с версией, файлы блокировки зависимостей и результат прогона проверок фиксируются вместе.

## Одновременность

10. <a id="REQ-BUILD-009"></a> **REQ-BUILD-009** — Задачи, использующие один каталог сборки или кеш, не запускаются одновременно. Составная задача выполняет шаги последовательно; параллельность допускается только между задачами с раздельными каталогами.
