# Положения о поведении при работе писались раньше запуска

## Проблема

Положения о развёртывании и о контракте ошибок выходили без проверки и без
записи о том, почему проверки нет. Два положения о запуске виртуальной машины
были написаны по описанию механизма и взаимно исключали друг друга: проект,
исполнивший их буквально, не запускался вовсе (#22).

## Чем подтверждено

Сверка двух документов: из положений о развёртывании и контракте ошибок
четырнадцать не подкреплены ни одной проверкой. Девять из них описывают скрипт,
машину и данные потребителя — ядро их не запускает, и это законно, но нигде не
было записано. Два — о контракте ошибок — проверялись, но проверка на них не
ссылалась. Три — `REQ-DEPLOYMENT-011…013`, ключи запуска — ядро предписывает
само, и запуска под ними не было.

## Что нашлось при первом запуске

`REQ-DEPLOYMENT-011` обещал: «перечень ключей запуска — часть поставки». Ключей в
поставке не было нигде — только в тексте требования. Положение обещало поставку,
которой не было, и заметить это можно было только одним способом — попытаться
ею воспользоваться.

## Решение владельца

Предложение 7 разбора принято. Решение владельца от 2026-09-23.

## Что сделано

Записано `REQ-QUALITY-017`.

**Проверка положений.** Каждое положение о развёртывании и о контракте ошибок
либо подкреплено проверкой, которая на него ссылается, либо внесено в перечень
положений, которые ядро не запускает, с причиной по существу. Положение без
того и другого роняет проверку ядра; причина, записанная для положения, у
которого проверка уже есть, — тоже, чтобы перечень не устаревал молча.

**Поставка ключей запуска.** Команда `conventions jvm-args --archive <путь> |
--aot <путь>` печатает ключи по одному в строке и сама отвергает сочетание
архива классов с кешем AOT. `REQ-DEPLOYMENT-011` называет поставку.

**Проверка запуском.** Проверка собирает крошечную службу и запускает
закреплённый JDK с поставленными ключами: служба поднимается, первый запуск
записывает архив классов, второй открывает его. Сочетание архива с кешем AOT
виртуальная машина отвергает тем самым сообщением, что пришло в #22.

Проверки контракта ошибок, которые поднимали совет по ошибкам и проверяли его
отсутствие вне веб-приложения, теперь ссылаются на положения, которые проверяют.

## Чем закреплено

Три проверки: положения выходят с проверкой либо с причиной; поставленные ключи
запускают службу и записывают архив, второй запуск им пользуется; архив и кеш
AOT несовместимы — отвергает и виртуальная машина, и поставка.

Различающая сила проверена тремя возвратами: снятый ключ записи архива,
снятая причина и устаревшая причина роняют проверки каждый своим утверждением.

Там, где JDK нет, проверка запуском пропускается с названной причиной, а не
молча.

## Откуда пришла задача

Разбор заявок потребителей за две недели, предложение 7.
