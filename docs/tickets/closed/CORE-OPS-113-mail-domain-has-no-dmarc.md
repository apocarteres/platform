# Почтовый домен отправителя живёт без DMARC, и этого никто не видит

## Проблема

Письма отправляет каждый потребитель с `platform-auth` (порт `AuthLetters`),
а записи DNS домена отправителя проект настраивает сам, по подсказкам
почтового сервиса. Сервис требует DKIM и SPF адреса возврата, DMARC — нет.
В ядре о почтовом домене нет ничего: ни перечня записей, ни проверки, ни
инструкции.

## Подтверждение

Заявка [apocarteres/platform#72](https://github.com/apocarteres/platform/issues/72)
проекта ZAVPN (ядро 13.7.0), задача ZAVPN-OPS-113: записи `_dmarc` не было с
начала работы сервиса. Сверка с ядром 15.0.0: DKIM, SPF и DMARC не упоминаются
ни в требованиях, ни в пакете правил.

## Последствия при сохранении текущего поведения

Письма входа строже оцениваются получателями и чаще попадают в спам; подделка
писем от имени домена не отсекается. Отсутствие записи видно только по
последствиям.

## Решение владельца

Решение владельца от 2026-10-08: рекомендация и проверка, без обязательства.

## Требуется

1. Нормативный документ `REQ-MAIL`, доставляемый пакетом, уровня
   рекомендации: раздел `mail`, проверка, ужесточение DMARC.
2. Правило `mail` уровня рекомендации: изъяны объявления.
3. `conventions mail --check` по авторитетным серверам зоны.
4. Инструкция `RUN-MAIL-DOMAIN` с шаблоном инструкции проекта.

## Критерии приёмки

- Тест первым: полный домен проходит; отсутствующий или отозванный DKIM, две
  записи SPF, нет MX адреса возврата, нет DMARC — названы; `p=none` — совет,
  а не отказ; отказ DNS назван причиной.
- Настоящие авторитетные серверы отвечают на публичных доменах, ключ DKIM за
  CNAME находится по цели.
- Пробы: снятая проверка DMARC, две записи SPF приняты, отказ DNS стал
  отсутствием записи — тесты падают.
