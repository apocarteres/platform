# Внедрение статического разбора

[Инструкции](INDEX.md) · [Проверки качества](../requirements/quality-checks.md)

Инструкция собирает эксплуатационные подробности, которые стоили потребителю
трёх поломок и нескольких тупиков ([заявка #15](https://github.com/apocarteres/platform/issues/15)).
Нормативная часть — `REQ-QUALITY`; здесь только то, что нужно знать при
настройке и о чём инструменты молчат.

## Как подключить доставленное

### Java

Настройка приходит наследованием: `platform-service-parent` наследует
`platform-parent`, где объявлены `-Xlint:all`, `-Werror` и разбор исходников.
Отдельных действий не требуется, кроме одного — файла `.mvn/jvm.config` в корне
проекта: Java 25 требует открыть внутренности компилятора, и наследованием файл
не передаётся.

### TypeScript и JavaScript

Настройка приезжает пакетом правил. В `eslint.config.mjs` проекта:

```js
import globals from 'globals';
import typescriptEslint from 'typescript-eslint';
import { javascript, typescript } from '@apocarteres/project-conventions/configs/eslint';

export default typescriptEslint.config(
  ...javascript({ globals: globals.node }),
  ...typescript(typescriptEslint, { globals: globals.browser }),
);
```

Ядро пользуется этой же настройкой для собственных пакетов: раздаваемое и
проверяемое — один файл.

### Rust

У Cargo нет наследования настройки из удалённого родителя, как у Maven, поэтому
настройка приезжает файлом. Раздел из
`@apocarteres/project-conventions/configs/cargo-lints` вносится в `Cargo.toml`
крейта или рабочего пространства, а `configs/clippy.toml` кладётся рядом.

Запреты объявлены уровнем `deny`, а не `forbid`: `forbid` не оставляет
законного способа объявить единичное послабление по месту, и обоснованный
`unsafe` — обработчик сигнала, которому нет безопасной обёртки, — становится
непроходимым. Требование этим не ослаблено: `unsafe` роняет сборку, пока
послабление не объявлено, а объявление остаётся на виду в коде.

Набор — пол, а не потолок. `pedantic` в него намеренно не входит: вместе с
`warnings = "deny"` он делает отказом обычный код, например требует `#[must_use]`
у всякой чистой функции. Проект волен включить его сверх набора, засеяв находки
ограничителем.

### Разбор байт-кода

Ядром он не предписан. Проекту, который добавил его сверх набора, ядро раздаёт
файл исключений `@apocarteres/project-conventions/configs/spotbugs-exclude`: он
снимает сообщения о внедрении SQL на вызовах свода запросов — вид кода,
предписанный `REQ-DATA-ACCESS`.

## Автоматическая правка не применяется без разбора

Автоправка разбора — предложение, а не исправление. Из трёх семейств, где
потребитель её применял, все три дали неверную правку:

- переписывание на стороннюю библиотеку, которой в проекте нет;
- удаление поля, внедряемого подстановкой в тесте;
- удаление оператора **вместе с побочным действием**, на котором держалось
  следующее утверждение.

Последнее не поймали модульные тесты: дефект жил в интеграционном. Инструмент
рассуждает о чтении значения и не рассуждает о побочном действии.

## Разбор необязательности внедряется по пакетам, а не сразу

В режиме сплошной разметки правки не уменьшают счёт, а сдвигают его наружу:
разметка одного типа убрала из него 15 находок и породила ровно столько же у
вызывающих. Объявляя поле необязательным, вы сообщаете это всем вызывающим.

Пригодный для постепенного внедрения режим — разбор только помеченных пакетов:
непомеченный пакет не разбирается и на соседей не влияет, а множество помеченных
устойчиво и может только расти. Ограничитель в этом случае держит множество
пакетов, а не счёт находок (`REQ-QUALITY-007`).

## Доля шума различается на порядок

Измерено на 46 829 строках Java и фронтенде на Angular:

| разбор | находок | чем заняты |
|---|---|---|
| разбор исходников Java | 118 | исправляются сразу |
| разбор байт-кода | 1103 | 97% — один шаблон об утечке представления |
| разбор TypeScript | 414 | 146 — доступность, то есть отдельная работа |

Отсюда право на засев: без него отказ на предупреждениях неисполним.

## Чем засевать находки в Rust

У Rust нет файла подавлений, как у разбора TypeScript или байт-кода, и это не
повод расставлять `#[allow]` по пятидесяти местам: такой засев не убывает, он
размазывается.

Единица засева здесь та же, что у разбора необязательности в Java, — множество
объявленных послаблений (`REQ-QUALITY-007`). Послабление объявляется на модуль
целиком, `#![allow(clippy::expect_used)]` в его начале, и множество пар «модуль
и правило» засеивается один раз. Работа идёт снятием послабления с модуля, а не
правкой по месту: модуль либо вычищен, либо нет, и это видно.

Крейт целиком тоже годится как первый шаг, но множество из одной записи не
показывает продвижения: снять его можно только разом.

## Разбор не знает устройства проекта

Разбор байт-кода сообщает о внедрении SQL на вызовах вида
`jdbc.query(sql.get("имя"), …)`: он видит переменную вместо литерала и не знает,
что она пришла из свода запросов. Этот вид кода предписан `REQ-DATA-ACCESS`,
поэтому исключение раздаёт ядро, а не каждый потребитель заново.

## Версии и настройка

- Разбор байт-кода до 4.10 не читает байт-код Java 25 и падает с
  `Unsupported class file major version 69`.
- Java 25 требует открыть внутренности компилятора: `.mvn/jvm.config` со
  строками `--add-exports` и `--add-opens`.
- Разбор необязательности, оказавшийся на пути обработчиков без своей
  настройки, роняет компиляцию сообщением о неверной настройке: настройку
  приходится повторять в каждом исполнении компилятора.

## Цена по времени

Компиляция с тестами: 24 с без разбора исходников, 36 с с ним. Это укладывается
в требование `REQ-QUALITY-002` о минутах, но запас не бесконечен: разбор
байт-кода и разбор TypeScript в `check` измеряются отдельно.
