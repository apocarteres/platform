# Ответы входа выдают почту временем, у сессии нет предельного срока

## Проблема

1. Письма входа уходят в потоке запроса после фиксации
   (`AuthService.afterCommit`): регистрация, повторное письмо и запрос сброса
   для существующей почты отвечают на время отправки письма дольше, чем для
   неизвестной. Отказ почтового сервиса проекта долетает до ответа — ответ
   отличается и по коду.
2. Регистрация новой почты считает хеш BCrypt, повторная — нет: разница во
   времени ответа порядка самого хеша.
3. `POST /api/auth/resend` не проходит проверку «человек ли это» и не
   ограничен по адресу: предел только по почте.
4. Сессия живёт, пока ею пользуются: срок бездействия продлевается каждым
   запросом, предельного срока от входа нет.

## Подтверждение

Потребитель ядра (аудит безопасности 2026-10-23): по времени ответа
регистрации и сброса можно перебирать существующие почты; украденная
активная сессия не истекает никогда.

## Последствия при сохранении текущего поведения

`REQ-AUTH-003` (ответы не раскрывают почту) нарушается временем ответа;
повторное письмо — бесплатный путь рассылки на чужие неподтверждённые почты с
разных почт без проверки; сессия не ограничена во времени.

## Ожидаемый результат

1. Письма входа уходят из очереди ядра отдельным потоком после фиксации
   транзакции; ответ точки не ждёт письма и не зависит от его исхода. Отказ
   порта `AuthLetters` пишется в журнал службы без почты получателя.
2. Повторная регистрация считает хеш пароля так же, как новая.
3. Повторное письмо требует проверки «человек ли это» (действие `resend`) и
   ограничено по адресу; клиент `@apocarteres/auth` передаёт ответ проверки.
4. Предельный срок сессии от входа — `platform.auth.session.absolute-timeout`,
   по умолчанию 7 суток: по истечении сессия завершается при первом же
   запросе, и запрос идёт как анонимный.
5. Контракт OpenAPI и `REQ-AUTH` описывают изменения; выпуск — старший,
   с описанием перехода.

## Критерии приёмки

1. Регистрация, повторное письмо и запрос сброса не ждут отправки письма:
   медленный или отказавший порт писем не меняет ни время, ни код ответа.
2. Повторная регистрация считает хеш.
3. `resend` без проверки — `human-check-failed`; предел по адресу работает.
4. Сессия старше предельного срока не проходит на защищённую точку даже при
   постоянной активности.
