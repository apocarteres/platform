# Ядро не умеет собирать и публиковать Angular-библиотеку

## Проблема

`ADR-0001` объявляет Angular частью состава ядра: пакеты в одном npm scope —
контракт модальных окон, перехватчики HTTP, форматирование, постраничность,
локализация. Сборки и публикации для них нет ни одной.

Единственный npm-пакет ядра — `packages/project-conventions` — собирается
`npm pack` без шага сборки: это пакет правил на Node, его исходники и есть
поставляемое содержимое. Angular-библиотека так не поставляется: её требуется
собрать, а результат сборки отличается от исходников.

Пока механизма нет, любая задача клиентской половины начинается с того, что он
изобретается попутно — а изобрести его придётся один раз для всех пяти пакетов
из перечня `ADR-0001`.

## Чем подтверждено

Замеры 2026-09-11 в ядре.

| Что | Состояние |
| --- | --- |
| Angular-библиотек в репозитории | 0 |
| npm-пакетов | 1 — `packages/project-conventions`, без шага сборки |
| Angular в закреплённых инструментах `mise.toml` | нет: закреплены `java`, `node`, `npm` |
| Шаг публикации npm в `scripts/install-local.sh` | один, привязан к каталогу пакета правил |

Публикация пакета правил (`scripts/install-local.sh`) подставляет версию из
тега, зовёт `npm pack` и возвращает версию обратно в `0.0.0`. Каталог пакета
задан в скрипте одной переменной: второй пакет туда не добавляется без правки.

Задача `CORE-API-002`, клиентская половина контракта ошибок, стоит с двумя
открытыми вопросами ровно об этом и в работу не берётся.

## Последствия при сохранении текущего поведения

1. Пятый пункт плана `ADR-0001` — пакеты Angular — не начинается: каждая
   попытка упирается в отсутствующую сборку.
2. Контракт ошибок держится только серверной половиной, а обязательство
   `web-errors` требует от потребителя сменить обе.
3. Решения о сборке, публикации и проверках будут приниматься внутри
   продуктовой задачи, где их не видно и не обсуждают.

## Ожидаемый результат

В ядре есть один способ собрать, проверить и опубликовать Angular-библиотеку,
годный для всех пакетов из перечня `ADR-0001`. Сборка входит в наборы `check` и
`verify`, публикация — в локальную публикацию ядра тем же путём, что Java и
пакет правил: версия из тега, артефакт в `target/local-packages`, потребитель
ставит его без registry (`ADR-0003`, `REQ-PUBLISHING-007`).

## Открытые вопросы

1. **Чем собирается библиотека?**
   Ответ владельца 2026-09-11: `ng-packagr`. Для пакета, состоящего из функций
   и функциональных интерсепторов, хватило бы обычного `tsc` — декораторов в
   нём нет. Но в перечне `ADR-0001` есть контракт модальных окон: там
   компоненты с шаблонами, которые без компилятора Angular не собрать. Выбрать
   `tsc` значило бы переделывать механизм на второй же библиотеке, вопреки
   критерию приёмки этой задачи.
2. **Входит ли Angular в закреплённые инструменты?**
   Ответ владельца 2026-09-11: нет. `mise` закрепляет среды выполнения — java,
   node, npm; Angular не среда, а зависимость. Её версию закрепляет файл
   блокировки пакета, причём точнее, чем строка в `mise.toml`. Держать одну
   версию в двух местах — две записи одного факта, которые расходятся молча
   (`REQ-BUILD-011`).
3. **Где живут пакеты?**
   Ответ владельца 2026-09-11: в `packages/`, рядом с пакетом правил. Один
   каталог для всех npm-пакетов ядра; публикация перебирает пакеты, объявившие
   себя публикуемыми, вместо пути, вписанного в скрипт.
4. **Насколько проверки Angular укладываются в `check`?**
   Ответ владельца 2026-09-11: разделить по стоимости. Модульные тесты и
   проверка типов — в `check`, они идут секунды и ловят почти все поломки
   сборки; полная упаковка `ng-packagr` — в `verify`. Унести в `verify` всю
   сборку значило бы повторить дыру `CORE-OPS-021`: зелёный `check` читался бы
   как «можно отправлять», а библиотека не собиралась бы.

## Критерии приёмки

- Команда сборки Angular-библиотеки существует и вызывается задачей менеджера
  окружения, а не голой командой (`REQ-BUILD-003`).
- Артефакт библиотеки попадает в локальную публикацию ядра с версией из тега и
  не публикуется для `SNAPSHOT` (`REQ-PUBLISHING-003`).
- Проверки библиотеки входят в `check` либо в `verify`, и выбор объяснён.
- `scripts/install-local.sh` публикует несколько npm-пакетов, а не один
  заданный каталогом.
- Инструкция по локальной публикации описывает подключение
  Angular-библиотеки потребителем.
- Порядок закреплён так, что второй и третий пакет из перечня `ADR-0001`
  добавляются без новых решений.

## Откуда пришла задача

Разбор `CORE-API-002` 2026-09-11: клиентская половина контракта ошибок
упирается не в разбор `ProblemDetail`, а в отсутствующий механизм сборки и
публикации, общий для всех Angular-пакетов ядра.
