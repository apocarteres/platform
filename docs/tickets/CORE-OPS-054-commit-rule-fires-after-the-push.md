# Сверка коммитов срабатывала после отправки, а не до

## Проблема

Сверка коммитов живёт в закрытии выпуска и запускается только им. Хук
`pre-push`, который ядро ставит по `REQ-QUALITY-004`, выполняет `mise run
check`, а сверки коммитов в этом наборе нет.

Поэтому забытая строка признака цикла становится известна, когда коммит уже
общий, — и вопрос об исправлении встаёт в самой неудобной форме
(`CORE-OPS-053`).

## Чем подтверждено

Заявка потребителя [issue #19](https://github.com/apocarteres/platform/issues/19).
Состояние ядра проверено: хук выполняет `mise run check`, отдельной команды
сверки коммитов нет.

## Что делать

Сверять **отправляемый диапазон**, а не всю историю. Тонкость существенная:
добавь сверку в `check` целиком — и проект, у которого такой коммит уже в
истории, не сможет отправить ничего. У потребителя он там прямо сейчас.

Проверка по отправляемому диапазону отказывает новому коммиту и молчит о
прошлом.

## Откуда пришла задача

Заявка потребителя [issue #19](https://github.com/apocarteres/platform/issues/19),
третье направление.
