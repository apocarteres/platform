# Слой доступа к данным

[Карта требований](../REQUIREMENTS.md) · [Решение](../decisions/ADR-0002-persistence-contracts.md)

## Каталог запросов

1. <a id="REQ-PERSISTENCE-001"></a> **REQ-PERSISTENCE-001** — SQL хранится в ресурсах, а не строками в коде: один файл — один запрос, каталог `classpath:sql/<область>/` соответствует одной доменной области, имя файла без расширения является именем запроса.
2. <a id="REQ-PERSISTENCE-002"></a> **REQ-PERSISTENCE-002** — Отсутствующий каталог, пустой файл запроса и повторяющееся имя запроса являются ошибками конфигурации и отказывают при первом обращении к каталогу.
3. <a id="REQ-PERSISTENCE-003"></a> **REQ-PERSISTENCE-003** — Обращение по неизвестному имени запроса отказывает и называет перечень доступных имён.
4. <a id="REQ-PERSISTENCE-004"></a> **REQ-PERSISTENCE-004** — Имя каталога нормализуется по ведущим и завершающим разделителям; пустое имя, повторный разделитель и обход по дереву каталогов отклоняются.
5. <a id="REQ-PERSISTENCE-005"></a> **REQ-PERSISTENCE-005** — Каталог читается с диска один раз за время жизни приложения; повторное обращение возвращает тот же экземпляр.

## Условная запись

6. <a id="REQ-PERSISTENCE-006"></a> **REQ-PERSISTENCE-006** — Исход условной записи выражается типом с закрытым перечнем вариантов: запись применена, записи нет, версия изменена параллельно, запись отклонена доменным условием оператора.
7. <a id="REQ-PERSISTENCE-007"></a> **REQ-PERSISTENCE-007** — Различие между отсутствием записи и конфликтом версий определяется повторным чтением по идентификатору, а не сообщением драйвера.
8. <a id="REQ-PERSISTENCE-008"></a> **REQ-PERSISTENCE-008** — Операция, для которой неприменённая запись означает нарушение инварианта вызывающего, получает состояние через явный запрос с сообщением об отказе.

## Сериализация команд

9. <a id="REQ-PERSISTENCE-009"></a> **REQ-PERSISTENCE-009** — Команда DAO сериализуется в JSON отдельным портом слоя persistence с датами в ISO-8601; настройки сериализации веб-слоя на неё не влияют. Перечень принимаемых значений закрыт: запись, отображение со строковыми ключами, перечисление, набор значений, строка, число, признак, идентификатор, момент времени и отсутствие значения. Формат команды — собственный контракт слоя, а не чужой: сериализатор пишет его сам и не зависит от версии посторонней библиотеки.
10. <a id="REQ-PERSISTENCE-010"></a> **REQ-PERSISTENCE-010** — Несериализуемая команда является ошибкой программиста и отказывает с указанием типа команды.

## Точность времени

11. <a id="REQ-PERSISTENCE-013"></a> **REQ-PERSISTENCE-013** — Время хранится с точностью до микросекунд: типы времени распространённых баз наносекунды не хранят. Момент времени приводится к точности хранилища перед записью, поэтому прочитанное значение всегда равно записанному.
12. <a id="REQ-PERSISTENCE-014"></a> **REQ-PERSISTENCE-014** — Код и тесты, сравнивающие моменты времени, используют то же приведение, а не значение системных часов напрямую. Иначе исход сравнения зависит от точности часов операционной системы.
13. <a id="REQ-PERSISTENCE-015"></a> **REQ-PERSISTENCE-015** — Время записи строки задаёт приложение, а не выражение базы вида `now()` или `CURRENT_TIMESTAMP`. Иначе в одной строке оказываются два источника времени — часы приложения в доменных полях и часы базы в служебных, — и порядок событий по служебным полям восстановить нельзя. Момент берётся у порта часов и приводится к точности хранилища: для этого есть `StoredInstant.offsetOf`, принимающий момент или сами часы.

## Регистрация

14. <a id="REQ-PERSISTENCE-011"></a> **REQ-PERSISTENCE-011** — Порты регистрируются автоконфигурацией; бин, объявленный потребителем, имеет приоритет над бином по умолчанию.
15. <a id="REQ-PERSISTENCE-012"></a> **REQ-PERSISTENCE-012** — Порт сериализации команд регистрируется всегда и ничего не требует на classpath. Условная регистрация по наличию чужой библиотеки отменена 2026-09-12 по заявке потребителя: она ставила работу слоя доступа в зависимость от того, притащит ли посторонняя зависимость нужную версию сериализатора, и молчала об отсутствии порта до первого обращения к DAO.
