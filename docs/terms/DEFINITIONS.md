# Толкование терминов

Порядок работы — [RULES.md](RULES.md). Уровень — рекомендация: длинный оборот
ошибкой не считается, но короткий термин предпочтительнее.

| Термин | Толкование |
|---|---|
| Пункт требования | Пронумерованное положение внутри документа требований со своим идентификатором, например `REQ-DATA-ACCESS-006`. Не документ целиком и не абзац текста. |
| Состав выпуска | Перечень задач, чей результат вышел в этом выпуске. Не перечень работы, которая в нём велась: работа по незавершённой задаче в состав не попадает. |
| Обязательство | Долг потребителя перед ядром: требование уровня директива со сроком в выпусках, материализуемое задачей при открытии выпуска. Не пожелание и не рекомендация. |
| Задача | Единица работы проекта со своим идентификатором и документом. Слово «тикет» в текстах ядра не употребляется. |
| Эталонный потребитель | Подставной репозиторий в проверках ядра, несущий форму настоящего проекта-потребителя. Не копия конкретного потребителя. |
