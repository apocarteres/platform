# Набор verify по частям: расписка части переносится, пока её дерево прежнее

## Проблема

Выпуск ядра ждёт полного набора `verify` при любой правке кода. Правка одного
пакета правил заново гоняет Java-модули и npm-пакеты, которых она не
касается, а расписка относится к дереву кода целиком (`REQ-RELEASE-045`) и
обесценивается одним изменённым файлом.

## Подтверждение

Выпуск 17.5.0, 2026-11-11: прогон в сборочном контейнере — около 7 минут, и
он шёл дважды, потому что после первого в пакет правил добавлен один ключ
команды. По журналу прогона: тесты пакета правил выполнены два раза по ~50 с
(зависимость `docs-check` и сценарий `test` пакета в `web-test`), Java-модули —
2 мин 13 с, остальное — npm-пакеты и пересоздание дерева в контейнере с
установкой зависимостей каждого пакета заново. Части идут строго подряд.

## Последствия при сохранении текущего поведения

Выпуск, меняющий один пакет, стоит столько же, сколько выпуск всего ядра;
исправление в одну строку ждёт семь минут и удваивает их при каждой
следующей правке.

## Решение владельца

Решение владельца от 2026-11-11: выпуск ядра не должен упираться в полный
прогон; принято убрать повторный прогон, выполнять части одновременно и
переносить расписку части, дерево которой не менялось.

## Требуется

1. Пакет правил: проект объявляет части набора — команду и пути каждой.
   Команда расписки выполняет части одновременно, часть с прежним деревом не
   перезапускает и пишет расписку коммита, когда пройдены все.
2. Ядро объявляет свои части и не гоняет тесты пакета правил дважды.
3. Сборочный контейнер не пересоздаёт дерево и не ставит зависимости заново,
   когда файл блокировки прежний; расписки частей возвращаются на машину
   разработчика.

## Критерии приёмки

- Правка файла одной части перезапускает эту часть и части без путей;
  остальные переносятся. Правка файла вне частей перезапускает все.
- Упавшая часть расписки коммита не оставляет.
- Шлагбаум закрытия и `conventions attested` принимают расписку, собранную по
  частям, без изменений.
- Замер: повторный прогон ядра после правки одного пакета правил — около
  минуты.
- `mise run verify` зелёный.

## Вне задачи

Ускорение самих тестов Java-модулей и публикации артефактов.
