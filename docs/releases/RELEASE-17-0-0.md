# Выпуск 17.0.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Несовместимые изменения

- `POST /api/auth/resend` проходит проверку «человек ли это» (действие `resend`) и ограничен 30 запросами в час с адреса: без ответа проверки — `human-check-failed` (`REQ-AUTH-004`, `REQ-AUTH-012`). Клиент `@apocarteres/auth`: `resend(email, human?)`.
- Письма входа уходят из очереди ядра отдельным потоком (`REQ-AUTH-010`): ответ регистрации, повторного письма, сброса и смены почты не ждёт письма, и исключение порта `AuthLetters` больше не доходит до ответа — оно пишется в журнал службы.
- Сессия живёт не дольше `platform.auth.session.absolute-timeout` от входа, по умолчанию 7 суток (`REQ-AUTH-046`): первый запрос после срока идёт без входа.
- Номер нового обращения в поддержку — случайные восемь цифр, а не порядковый (`REQ-SUPPORT-001`); тип в контракте прежний.

## Миграция

1. Повторное письмо: передать ответ проверки — `AuthSession.resend(email, human)`; если порт `HumanCheck` проекта различает действия, пропустить действие `resend`.
2. Тесты проекта, которые ждут письмо входа сразу после ответа или ошибку доставки в ответе, ждут письма с таймаутом; исход доставки проект видит в своём порте `AuthLetters`.
3. Если 7 суток от входа проекту не подходят — задать `platform.auth.session.absolute-timeout`. Тесты, которые двигают часы ядра дальше срока внутри одной сессии, входят заново.
4. Код проекта, который полагался на порядок номеров обращений, сортирует по времени создания.
