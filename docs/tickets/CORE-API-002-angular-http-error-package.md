# Angular-пакет разбора ошибок `@apocarteres/http`

## Проблема

Серверный контракт ошибок задан: `ProblemDetail` по RFC 9457 с расширением
`code` (`REQ-API-001`), starter ядра его отдаёт. Клиентской половины нет.
Каждый Angular-клиент разбирает тело ошибки сам: у одного потребителя коды
ошибок передаются строкой в сообщении исключения и разбираются в
`shared/http-error.ts`, у другого — своим форматом.

Пока клиентской половины нет, контракт держится только на стороне сервера, а
переход потребителя «одним изменением» невозможен: серверный формат сменится,
а клиент останется со старым разбором.

## Чем подтверждено

Задача `CORE-API-001` объявляла пакет `@apocarteres/http` четвёртым пунктом
требуемого; серверная часть закрыта 2026-09-11, клиентская — нет.

В репозитории ядра Angular-библиотек нет вовсе: единственный npm-пакет —
`packages/project-conventions`, это пакет правил на Node без Angular. То есть
задача включает не только разбор ошибок, но и появление первой
Angular-библиотеки ядра: сборка, публикация, проверки.

## Последствия при сохранении текущего поведения

1. Обязательство `web-errors` требует от потребителя сменить и серверную, и
   клиентскую половину, а средство ядро даёт только для серверной.
2. Разбор `ProblemDetail` пишется в каждом клиенте заново, вместе с
   интерсепторами санитизации и истёкшей сессии.
3. Словарь кодов ошибок клиента и сервера сверяется глазами.

## Ожидаемый результат

Пакет `@apocarteres/http` даёт разбор `ProblemDetail` с расширением `code`,
интерсептор санитизации и интерсептор истёкшей сессии. Потребитель переходит
на контракт одним изменением: сервер и клиент вместе, без поддержки прежнего
формата.

## Открытые вопросы

1. **Как ядро собирает и публикует Angular-библиотеку?** Вынесено в
   `CORE-OPS-029` вместе с вопросом о закреплении Angular как инструмента:
   механизм один для всех пяти пакетов из перечня `ADR-0001`, и решать его
   внутри продуктовой задачи значило бы принимать общие решения там, где их не
   видно. Эта задача от него зависит и до его закрытия не начинается.
   Ответ: ожидается в `CORE-OPS-029`.

## Критерии приёмки

- Пакет разбирает `ProblemDetail` и отдаёт клиенту код ошибки и статус.
- Интерсепторы санитизации и истёкшей сессии входят в пакет.
- Словарь кодов клиента сверяется с сервером тестом, а не глазами.
- Сборка и проверки пакета входят в наборы `check` и `verify` ядра.
- Потребитель переходит на контракт одним изменением.

## Откуда пришла задача

Разделение `CORE-API-001` при её закрытии 2026-09-11: серверная половина
контракта сделана, клиентская требует первой Angular-библиотеки ядра и
отдельных решений о её сборке и публикации.
