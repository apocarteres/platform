# Статический разбор назван и доставляется, а не выводится каждым заново

## Проблема

`REQ-QUALITY-002` требует, чтобы `check` содержал «статический разбор с отказом
на предупреждениях», и на этом останавливается: ни набора, ни порядка внедрения,
ни того, что делать с существующими находками. Каждый потребитель выводит это
заново и выводит по-разному.

У потребителя требование не выполнялось для двух компонентов из трёх и
обнаружилось это разговором, а не проверкой. У ядра оно не выполняется ни для
одного — см. `CORE-QUAL-011`.

## Чем подтверждено

Заявка потребителя [issue #15](https://github.com/apocarteres/platform/issues/15),
ядро 1.19.0, задача потребителя `ZAVPN-QUAL-075`. Потребитель внедрил разбор
целиком на 688 файлах и 46 829 строках Java и показал, что настройка от его
засева не зависит: с убранным файлом исключений разбор байт-кода выдаёт 610
находок, с убранным файлом подавлений разбор TypeScript выдаёт свои.

## Решение владельца 2026-09-15

Ядро называет набор и доставляет настройку. Потребитель волен не пользоваться
тем или иным языком, но если пользуется — требования к качеству для этого языка
определяет ядро, а не проект.

Это тот же принцип, что для компонентов ядра: пользоваться не обязан, но если
пользуется — инварианты гарантирует ядро.

Отсюда следствие, которое надо записать прямо: язык, которого ядро пока не
поддерживает, — повод для заявки, чтобы ядро его поддержало, а не повод проекту
выводить свой набор. Иначе правило возвращается туда, откуда пришло: каждый
выводит заново и выводит по-разному.

Поддерживаемые языки на 2026-09-15: Java, TypeScript, Rust. Rust добавлен
решением владельца того же дня: язык будет использоваться в проектах шире.

## Что сделано

`REQ-QUALITY-002` называет набор поимённо и называет перечень поддерживаемых
языков: Java — `-Xlint:all` с `-Werror` и разбор исходников `ErrorProne`;
TypeScript и JavaScript — `ESLint` с типовым разбором; Rust — `clippy` с отказом
на предупреждениях. Записано и следствие плана А: язык вне перечня — повод для
заявки в ядро, а не повод проекту выводить свой набор.

Там же записано право на засев со ссылкой на `REQ-QUALITY-007` и то, что
автоматическая правка разбора — предложение, а не исправление.

### Чем доставляется

| Язык | Способ |
|---|---|
| Java | наследованием: `platform-service-parent` → `platform-parent`, где объявлен разбор |
| TypeScript, JavaScript | `configs/eslint.base.mjs` пакета правил |
| Rust | `configs/cargo-lints.toml` и `configs/clippy.toml` пакета правил |
| Разбор байт-кода | `configs/spotbugs-exclude.xml` — для проекта, добавившего его сверх набора |

Ядро пользуется своей же настройкой ESLint: оба его пакета собирают
`eslint.config.mjs` из доставляемого файла, поэтому раздаётся проверенное.

### Исключение для свода запросов

Раздаётся ядром, потому что ядро же и обязало писать так, как разбор байт-кода
не понимает: `REQ-DATA-ACCESS` предписывает свод запросов, разбор видит
переменную вместо литерала и сообщает о внедрении SQL. Исключение приходит
оттуда же, откуда обязанность.

### Набор Rust оказался заграждением и был исправлен

Первая редакция включала `pedantic`. Вместе с `warnings = "deny"` он делает
отказом обычный код: чистая функция из четырёх строк не прошла, потому что у
неё нет `#[must_use]`. Поймано первой же пробой на крейте, а не рассуждением.
`pedantic` из набора убран, причина записана в самом файле, а проекту оставлено
право включить его сверх набора с засевом.

## Чем закреплено

Три проверки читают поставку: каталог настроек входит в `files`, каждая
настройка названа в `exports` и существует на диске, исключение для свода
запросов называет породившее его требование, и оба пакета ядра собраны из
доставляемой настройки.

Доставка Rust проверена не чтением, а прогоном: эталонный потребитель получил
крейт, `cargo clippy` с доставленной настройкой пропускает чистый крейт и
роняет сборку на `unwrap()`. Различающая сила проверена заменой `deny` на
`allow` в доставляемом файле — проверка отказала.

## Открытые вопросы

Разрешены.

1. **У Cargo нет наследования настройки из удалённого родителя.** Настройка
   доставляется файлом, потребитель вносит раздел в свой `Cargo.toml`. Решение
   принято исполнителем и подтверждено работой.
2. **Ядру не на чем проверять доставляемую настройку Rust.** Проверено на крейте
   эталонного потребителя настоящим прогоном `clippy`. Это оказалось сильнее,
   чем ожидалось: проба на нём же и нашла негодный набор `pedantic`.
3. **Прочие языковые документы Rust.** Пробел подтверждён и вынесен отдельной
   задачей `CORE-QUAL-012` по `REQ-TICKETS-012`.
