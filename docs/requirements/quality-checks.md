# Проверки качества

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: проверки любого сервиса.** Требования не зависят от языка.

**Уровень требования: директива.**

## Два набора

1. <a id="REQ-QUALITY-001"></a> **REQ-QUALITY-001** — Проверки собраны в два набора с фиксированными именами задач: `check` — быстрый шлагбаум перед отправкой изменений, `verify` — всё, что вообще проверяется локально. Третьего набора нет: проверка, не входящая ни в один из них, не выполняется никогда.
2. <a id="REQ-QUALITY-002"></a> **REQ-QUALITY-002** — `check` содержит проверку документации, проверку правил, модульные тесты всех компонентов, проверку проводки (`REQ-QUALITY-012`) и статический разбор с отказом на предупреждениях. Он обязан оставаться быстрым: минуты, а не десятки минут.
3. <a id="REQ-QUALITY-003"></a> **REQ-QUALITY-003** — `verify` содержит `check` целиком плюс интеграционные тесты, требующие внешних служб, сборку всех компонентов, аудит зависимостей, контрактные тесты скриптов и сканирование секретов. Тест, которому внешние службы не нужны, живёт в `check`: относить его к `verify` значит выводить из-под шлагбаума то, что можно проверить за секунды.
4. <a id="REQ-QUALITY-012"></a> **REQ-QUALITY-012** — Проверка проводки поднимает контекст приложения каждого рантайма без внешних служб: без базы, брокера, сети и учётных данных. Рантаймом считается каждый способ запуска компонента — веб-приложение, консольная команда, обработчик очереди; у библиотеки — контекст с её автоконфигурацией. Проверка отвечает на один вопрос: поднимается ли приложение вообще. Отказ такого рода — отсутствующий бин, условная конфигурация, не сработавшая в этом рантайме, несошедшиеся границы транзакций — виден только при запуске, поэтому набор `check` без него оставляет класс поломок за шлагбаумом: зелёная проверка читается как «можно отправлять», хотя приложение не запускается. Основание — задача `OPS-021` и случай потребителя, где бины двух шифров были объявлены в веб-условной конфигурации: веб работал, `check` был зелёным, а команда провижининга не поднималась вовсе.
5. <a id="REQ-QUALITY-004"></a> **REQ-QUALITY-004** — Шлагбаум перед отправкой изменений ставится хуком `pre-push`, который выполняет `check`. Хук устанавливается задачей менеджера окружения и не хранит собственной логики проверок.

## Что проверки обязаны делать

6. <a id="REQ-QUALITY-005"></a> **REQ-QUALITY-005** — Отказ проверки называет файл и место. Проверка, сообщающая только «не пройдено», считается недоделанной.
7. <a id="REQ-QUALITY-006"></a> **REQ-QUALITY-006** — Порог проверки не снижается ради прохождения: ни ослаблением уровня важности находки, ни общим исключением, ни отключением шага. Исключение оформляется задачей с указанием предмета, причины, компенсирующей меры и срока снятия.
8. <a id="REQ-QUALITY-007"></a> **REQ-QUALITY-007** — Существующие нарушения фиксируются храповиком и могут только убывать. Первичное засеивание разрешено; рост требует явного ключа и объяснения.
9. <a id="REQ-QUALITY-008"></a> **REQ-QUALITY-008** — Результат проверки читается кодом возврата задачи, а не глазами по выводу. Конвейер, скрывающий код возврата, в проверках запрещён.

## Устойчивость проверок

10. <a id="REQ-QUALITY-009"></a> **REQ-QUALITY-009** — Тест, исход которого зависит от момента запуска, машины или порядка выполнения, считается дефектом и получает задачу. Неустойчивый тест не «перезапускается до зелёного»: причина называется и подтверждается измерением.
11. <a id="REQ-QUALITY-010"></a> **REQ-QUALITY-010** — Утверждение о времени выполнения выражается через состояние, а не через предел на часах, если состояние доступно. Предел на часах допустим только как грубая защита от регрессии, с запасом, не спорящим с нагрузкой машины.
12. <a id="REQ-QUALITY-011"></a> **REQ-QUALITY-011** — Зелёная проверка после правки доказательством не является, пока не показано, что до правки отказ воспроизводился.
