# Рабочая среда запускается с профилем `production`

## Проблема

Две защиты ядра держатся на активном профиле Spring `production`: множитель
пределов частоты стенда (`REQ-AUTH-027`) и `http`-ссылки писем
(`REQ-AUTH-010`) с этим профилем останавливают запуск. Но ядро нигде не
требует, чтобы служба рабочей среды запускалась с профилем `production`:
поднятая без него, она примет увеличенные пределы и `http`-ссылки молча.

## Подтверждение

Разбор заявки [issue #56](https://github.com/apocarteres/platform/issues/56)
2026-09-25: требования о профиле нет ни в `REQ-DEPLOYMENT`, ни в поставке
ключей запуска (`REQ-DEPLOYMENT-011`).

## Последствия при сохранении текущего поведения

Защита, объявленная для рабочей среды, зависит от настройки, которой никто
не проверяет.

## Решение владельца

Заведено по согласию владельца от 2026-09-25.

## Требуется

1. Требование: служба рабочей среды (`production`, `REQ-DEPLOYMENT-019`)
   запускается с активным профилем Spring `production`.
2. Проверка: развёртывание рабочей среды сверяет это — например, манифест
   развёртывания или ключи запуска `conventions jvm-args` несут профиль, а
   сверка после установки его подтверждает.

## Критерии приёмки

- Тест: развёртывание среды `production` без профиля отказывает и называет его.
- Проба: снятая проверка — тест падает.

## Откуда пришла задача

Разбор [issue #56](https://github.com/apocarteres/platform/issues/56).
