# Выпуск 6.0.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Состав

| Задача | Причина включения |
|---|---|
| [CORE-OPS-085](../tickets/closed/CORE-OPS-085-deployment-without-downtime.md) | Указана при открытии выпуска |
| [CORE-OPS-086](../tickets/closed/CORE-OPS-086-open-questions-pile-up.md) | Указана при открытии выпуска |

## Критерии выхода

- [ ] Набор `verify` пройден на выпускаемом коммите — расписка получена командой выпуска
- [ ] Тег выпуска создан на проверенном коммите — ставится командой выпуска
- [ ] Обязательства ядра этого выпуска закрыты или перенесены записью с причиной
- [ ] Завершающий шаг выполнен — развёртывание в производственную среду или публикация артефактов

## Не входит

Задачи, не закрытые к моменту закрытия выпуска: они попадут в состав следующего по факту закрытия.

## Несовместимые изменения

- `release open` и `release close` отказывают, когда задач с открытыми вопросами больше порога требования — по умолчанию 9 (`REQ-RELEASE-047`): прежде число таких задач цикл не проверял.

## Миграция

- **Открытые вопросы.** Если задач с `questions: open` больше 9, ответьте на вопросы и поставьте `questions: resolved` либо задайте свои пороги в `.conventions.json`: `release.openQuestions` с полями `remind` и `require`. Больше 4 — только напоминание.
- **Развёртывание без простоя** — выбор проекта, правок не требует. Выбравший объявляет `deployment.withoutDowntime` с каталогом `migrations`, при желании `expandReleases` (по умолчанию 2) и `instances`. После этого действует правило `migration-labels`: первая строка каждого перехода — `-- migration: additive | expand | contract <переход> | breaking`; `expand` без парного `contract` — долг со сроком. Порядок развёртывания печатает `conventions migrations --unreleased`, активный экземпляр записывает `conventions manifest --instance <имя>`.
- **Замок фоновых работ** — `JdbcJobLock` из `platform-persistence`, таблица по образцу `sql/platform-job-lock/create-table.sql`, переходом `additive`.

## Результат

Заполняется при закрытии из расписки о проверках.
