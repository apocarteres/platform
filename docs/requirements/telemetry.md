# Наблюдение за узлами

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: проект, который держит свои узлы — хосты или виртуальные машины, где работают его службы.** Метрики хоста собирает Prometheus, журнал systemd — Loki. Основание — заявка потребителя: узел больше суток работал без метрик и журнала, потому что подключить его к наблюдению забыли; правка общего хоста наблюдения другим проектом неделю не пропускала журналы ни одного узла, и заметили это случайно. Решение владельца от 2026-10-06: объявление и проверка, как у резервных копий (`REQ-BACKUPS`); установку на узлы и настройку хоста наблюдения ядро не выполняет.

**Уровень требования: директива.**

## Объявление

1. <a id="REQ-TELEMETRY-001"></a> **REQ-TELEMETRY-001** — Проект объявляет узлы разделом `telemetry` в `.conventions.json`: `nodes` — перечень имён узлов, `prometheus` и `loki` — адреса приёмников, к которым обращается проверка, и необязательный `logsWithin` — срок, за который от узла должен быть журнал, по умолчанию `1h`. Правило `telemetry` называет каждый изъян объявления: неизвестное поле, поле, похожее на учётные данные, имя не из строчных букв, цифр и дефиса, повтор имени, адрес не http или https, срок не срок. Раздел молчит, пока не объявлен: объявление требует обязательство `REQ-TELEMETRY-006`.

## Метка узла

2. <a id="REQ-TELEMETRY-002"></a> **REQ-TELEMETRY-002** — Узел опознаётся одной меткой `node`, равной объявленному имени, и в Prometheus, и в Loki: цель опроса на хосте наблюдения несёт `node`, сборщик журнала на узле ставит `node` на каждый поток. Метка одна у всех проектов, поэтому проверка и правила оповещений одинаковы для всех, а узел, подключённый без метки, для них не существует. Имя узла уникально среди всех проектов общего хоста наблюдения: проект ставит перед ним своё имя.

## Проверка и оповещения

3. <a id="REQ-TELEMETRY-003"></a> **REQ-TELEMETRY-003** — `conventions telemetry --check` отказывает, если объявленный узел не опрашивается Prometheus (цели с его меткой нет), опрашивается, но не отвечает (`up` равно 0), или в Loki нет его журнала за `logsWithin`. Приёмник, который не ответил, называется адресом и причиной, а не превращается в молчание всех узлов. Развёртывание рабочей среды вызывает проверку после проверок поведения и сообщает её отказ; проверку вызывает и наблюдение проекта по своему расписанию. Отказ не откатывает установленное: наблюдение чинят, а не откатывают.
4. <a id="REQ-TELEMETRY-004"></a> **REQ-TELEMETRY-004** — `conventions telemetry --alerts prometheus` печатает правила оповещений Prometheus «узел не отвечает» и «узел пропал из опроса», `--alerts loki` — правило Loki «узел не пишет журнал дольше `logsWithin`». Правила строятся из объявления, поэтому набор узлов в оповещениях совпадает с объявленным. Ставит их в правила хоста наблюдения его владелец (`REQ-TELEMETRY-005`); панели, метрики приложений и собственные метки журналов остаются проекту.

## Общий хост наблюдения

5. <a id="REQ-TELEMETRY-005"></a> **REQ-TELEMETRY-005** — У хоста наблюдения, общего для нескольких проектов, один владелец — репозиторий, который ведёт его настройку. Проект правит только свою часть: цели своих узлов и свои правила оповещений — отдельными файлами, которые подключает настройка владельца. Общее — адреса, на которых слушают Loki, Prometheus и Grafana, фильтр входящих, настройка веб-сервера и его временные каталоги — меняется только в репозитории владельца, а не сессией одного проекта. Фильтр входящих покрывает IPv4 и IPv6 одинаково: служба, открытая на все адреса, по IPv6 ограничена так же, как по IPv4. После изменения общего владелец проверяет, что узлы всех проектов видны, — их `telemetry --check`. Основание — правки общего хоста одним проектом молча ломали наблюдение и работу других.

## Обязательство

6. <a id="REQ-TELEMETRY-006"></a> **REQ-TELEMETRY-006** — Обязательство ядра `telemetry`: проект со своими узлами объявляет их и проходит `conventions telemetry --check` на рабочей среде в срок 3 выпусков. Проект без своих узлов закрывает обязательство задачей, которая это называет (`REQ-RELEASE-019`).
