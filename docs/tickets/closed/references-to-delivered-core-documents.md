# Ссылка на нормативный документ ядра считалась ссылкой в пустоту

## Проблема

Нормативные документы ядра доставляются пакетом правил и не копируются
в репозиторий потребителя. Проверка ссылок собирала идентификаторы только
из документов самого репозитория, поэтому `related: REQ-RELEASE`
в задаче потребителя объявлялось ссылкой на неизвестный документ.

## Подтверждение

Задача обязательства, которую ядро само создаёт с полем
`related: REQ-RELEASE`, не проходила проверку документации в zavpn:
«поле related ссылается на неизвестный документ REQ-RELEASE».

## Последствия при сохранении текущего поведения

Потребитель не может сослаться метаданными на требование ядра — ни в
задаче, ни в решении. Ссылки на нормативную базу пришлось бы прятать
в текст, где их не проверяет ничто.

## Ожидаемый результат

Идентификаторы документов, доставленных пакетом правил, известны проверке
ссылок наравне с документами репозитория. Требовать их присутствия
в каталогах репозитория при этом не нужно: каталог описывает свои
документы, а не доставленные.

## Критерии приёмки

- [x] Проверка ссылок знает идентификаторы документов из `node_modules/@apocarteres/project-conventions/docs` — `lib/docs/check-docs.mjs`, `deliveredIds`
- [x] Тест показывает оба состояния: без пакета ссылка неизвестна, с пакетом — известна
