# Выпуск 11.2.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Состав

| Задача | Причина включения |
|---|---|
| [CORE-QUAL-029](../tickets/closed/CORE-QUAL-029-raw-fetch-without-api-version.md) | Указана при открытии выпуска |
| [CORE-OPS-097](../tickets/closed/CORE-OPS-097-stand-rate-limit-scale.md) | Указана при открытии выпуска |

## Критерии выхода

- [ ] Набор `verify` пройден на выпускаемом коммите — расписка получена командой выпуска
- [ ] Тег выпуска создан на проверенном коммите — ставится командой выпуска
- [ ] Обязательства ядра этого выпуска закрыты или перенесены записью с причиной
- [ ] Завершающий шаг выполнен — развёртывание в производственную среду или публикация артефактов

## Не входит

Задачи, не закрытые к моменту закрытия выпуска: они попадут в состав следующего по факту закрытия.

## Проверка видит больше

- Правило `client-update` (`REQ-CLIENT-UPDATE-011`) находит в исходниках приложения, кроме тестов, голый `fetch('/…')` и `XMLHttpRequest.open(…, '/…')` к своему API: такой запрос уходит без `X-Api-Version` и получает `426` после раската.

## Миграция

1. Голые вызовы к своему API заменить на `apiFetch()` из `@apocarteres/app-update`: функцию получают в контексте внедрения (`private readonly fetch = apiFetch();`) и зовут как `fetch`. Заголовок версии, свои заголовки и показ «клиент устарел» она берёт на себя; явный заголовок версии в таких местах можно убрать.
2. Стенд сценариев поднимает пределы частоты настройкой `platform.rate-limit.scale` (от 1 до 1000) вместо сброса ключей Redis. С профилем Spring `production` множитель больше 1 не стартует (`REQ-AUTH-027`).

## Результат

Заполняется при закрытии из расписки о проверках.
