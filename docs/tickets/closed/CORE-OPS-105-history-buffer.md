# Закрытие выпуска переполняет буфер git log на длинной истории

## Проблема

Чтобы отбросить коммиты старше `commitRuleSince`, закрытие читало всю
историю от основы до `HEAD` с телами сообщений и списками файлов одним
`git log` через `execFile` с буфером по умолчанию — 1 МБ. На проекте с
тысячей коммитов после основы вывод больше мегабайта, и закрытие падало
`ERR_CHILD_PROCESS_STDIO_MAXBUFFER`; объём только растёт.

## Подтверждение

Заявка потребителя [issue #65](https://github.com/apocarteres/platform/issues/65)
(ядро 13.1.0): 1060 коммитов, 1 099 074 байт. Воспроизведено тестом
2026-09-28: та же ошибка.

## Последствия при сохранении текущего поведения

У потребителя не закрывается ни один следующий выпуск; обход — перенос
`commitRuleSince`, который меняет смысл основы.

## Решение владельца

Решение владельца от 2026-09-28: исправление дефекта.

## Требуется

Отбор по основе — одними хешами; чтение истории выпуска — без предела в 1 МБ.

## Критерии приёмки

- Тест первым: история от основы больше мегабайта не роняет ни закрытие, ни
  сверку отправляемого диапазона. Тест падал до правки той же ошибкой.

## Что сделано

- `reachableSince` — `git rev-list <основа>..HEAD`; `withoutOlderThan` берёт
  хеши из него. Буфер чтения истории — 256 МБ.
- 4 пробы: три пойманы; «снова вся история с телами» не поймана и не может
  быть поймана тестом поведения — после поднятия буфера это вопрос скорости,
  а не правильности.

[issue #65](https://github.com/apocarteres/platform/issues/65).
