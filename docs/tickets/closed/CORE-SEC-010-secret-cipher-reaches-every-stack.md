# Обязательство secret-cipher достаётся проекту любого стека

## Проблема

Обязательство `secret-cipher` (`REQ-SECRETS-001`) не размечено стеком и
поэтому относится ко всем проектам. Выполнить его можно только на стеке
`java`: средство платформы `SecretCipher` есть лишь в модуле
`platform-persistence`.

## Подтверждение

Заявка потребителя от 2026-11-14 (issue apocarteres/platform#88): проекту
на PHP с `"stack": []` материализовалась задача `adopt-secret-cipher`,
выполнить её нечем; обязательство перенесено с причиной. При разметке
каталога (`CORE-ARC-026`) обязательство `secret-cipher` в перечень `java`
не попало.

## Последствия при сохранении текущего поведения

Проект другого стека получает невыполнимую задачу и долг перед ядром,
который может только откладывать.

## Решение владельца

Не требуется: правка выполняет `REQ-ADOPTION-028` — обязательство стека
относится к проекту, только если тот объявил этот стек.

## Требуется

1. Обязательство `secret-cipher` размечено стеком `java`.
2. `REQ-SECRETS-001` называет средство платформы для стека `java` и путь
   проекта другого стека — заявку в ядро.

## Критерии приёмки

- Тест разметки каталога ядра требует у `secret-cipher` стека `java`:
  без разметки он падает.
- `mise run verify` зелёный.

## Ход работы

- 2026-11-14 — тест первым: `test/stack.test.mjs` упал на `secret-cipher`;
  обязательство размечено `java`, `REQ-SECRETS-001` дополнен. Проект
  другого стека видит его в `conventions obligations` как «не относится»;
  запись о переносе в его состоянии обязательств больше не учитывается.
