# Отпадение узла от наблюдения никто не видит

## Проблема

Метрики и журналы узлов каждый проект подключает сам, вручную и по-своему.
В ядре о наблюдении нет ничего: ни объявления узлов, ни проверки, что узел
виден в Prometheus и пишет журнал в Loki, ни правил о хосте наблюдения,
общем для нескольких проектов.

## Подтверждение

Заявка [apocarteres/platform#70](https://github.com/apocarteres/platform/issues/70)
проекта ZAVPN (ядро 13.2.0), задачи ZAVPN-OPS-122 и ZAVPN-OPS-121, наблюдения
на рабочей среде 2026-10-06:

1. Узел больше суток работал без метрик и журнала: подключить его забыли.
2. С 2026-09-30 правка другого проекта на общем хосте не пропускала журналы
   ни одного узла ZAVPN; обнаружено через неделю, случайно.
3. Проверка настройки nginx чужой выкладкой сменила владельца временных
   каталогов и на семь минут оборвала синхронизацию агентов.
4. Фильтр входящих общего хоста покрывает только IPv4.

Сверка с ядром 14.1.1: требования, пакет правил и скрипты не упоминают
Prometheus, Loki, Alloy и `node_exporter`.

## Последствия при сохранении текущего поведения

Отпавший узел и сломанный приёмник журналов видны только по пустой Grafana.
Правка общего хоста одним проектом молча ломает наблюдение остальных.

## Решение владельца

Решение владельца от 2026-10-06: объявление и проверка, как у резервных
копий. Установку на узлы и настройку хоста наблюдения ядро не выполняет; у
общего хоста — один владелец, не ядро. Пункт 3 заявки — отдельной задачей
CORE-OPS-112.

## Требуется

1. Нормативный документ `REQ-TELEMETRY`, доставляемый пакетом: раздел
   `telemetry`, метка `node`, проверка, правила оповещений, один владелец
   общего хоста, фильтр по IPv4 и IPv6, обязательство.
2. Правило `telemetry`: изъяны объявления.
3. `conventions telemetry --check`: каждый узел опрашивается, отвечает и
   пишет журнал за `logsWithin`; недоступный приёмник назван адресом.
4. `conventions telemetry --alerts prometheus|loki`: правила из объявления.
5. Обязательство `telemetry` на 3 выпуска.
6. Инструкция `RUN-TELEMETRY-NODES`.

## Критерии приёмки

- Тест первым: на поддельных Prometheus и Loki проверка называет узел без
  цели, с `up = 0`, без журнала; недоступный Loki — один отказ с адресом;
  правила строятся из объявления; объявление называет каждый изъян.
- Пробы: снятая проверка `up`, снятая проверка журнала, отказ приёмника,
  ставший молчанием, — тесты падают.
