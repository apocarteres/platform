# Выпуск 19.0.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Миграция

Касается только проектов с внешним хранилищем задач (`store` в `.conventions.json`); проект с файлами задач переходит без изменений.

1. Хранилище переходит на контракт 2 (`REQ-STORE-004`, `REQ-STORE-024`) до подъёма ядра или вместе с ним: каждый ответ несёт `contract: 2`. Хранилище контракта 1 пакет правил 19.0.0 отвергает отказом `contract-version` с названием требуемой версии.
2. Операция `finishRelease` хранилища переводит задачи состава выпуска, кроме отменённых и замещённых, в «выполнена». Слияние PR задачу больше не закрывает: «выполнена» ставит выход выпуска.
3. Состав открытого выпуска подбирает задачи без выпуска, работа которых слита в `main` после прежнего выпуска, в любом статусе, кроме отменённой и замещённой. Задача «в работе» со слитым коммитом больше не держит закрытие, а выходит в выпуске; задачу, работа которой не закончена, снимают из состава командой `release drop` с причиной до закрытия.
4. Закрытие выпуска не требует статуса «выполнена» у задач состава; поля проекта у задачи, которую выпуск сделает выполненной, проверяются как у выполненной — `manual-qa: required` держит выпуск, как раньше.

Для трекера Driada-Lab переход — парная правка Driada-Lab/tracker#149; ядро и трекер выкатываются вместе.
