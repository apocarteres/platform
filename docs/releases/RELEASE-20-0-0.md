# Выпуск 20.0.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Миграция

Касается только проектов с внешним хранилищем задач (`store` в `.conventions.json`); проект с файлами задач переходит без изменений — поля проекта и их условие `done` работают, как прежде.

1. Хранилище отвечает в контракте 3 (`REQ-STORE-004`, `REQ-STORE-025`) запросам с заголовком `X-Store-Contract: 3`: каждый ответ несёт `contract: 3`. Хранилище, которое отвечает контрактом 2, пакет правил 20.0.0 отвергает отказом `contract-version`. Пока потребители одного хранилища на разных версиях ядра, хранилище отвечает каждому в названной им версии; без заголовка — как прежде.
2. Задача контракта 3 несёт условия выпуска `conditions` — перечень `{key, phase, state}`: `phase` — `before-release` либо `after-release`, `state` — `pending`, `done` либо `not-required`. Поле `fields`, `fieldsDigest` рабочего набора и операция `defineFields` из контракта ушли: пакет правил их не шлёт и не читает.
3. То, что держало выпуск через поля проекта и их условие `done` (например, `manual-qa: required`), хранилище выражает условием `before-release` в состоянии `pending`: оно держит закрытие, пока задача в составе выпуска. Условия `after-release` выпуск не держат.
4. Объявления полей проекта типа `ticket` в `.conventions.json` при внешнем хранилище больше ничего не держат; их можно убрать, если файлов задач у проекта нет.
5. `release status --json` и манифест тега показывают `conditions` задач состава вместо `fields`: скрипт проекта, который читал `fields`, читает `conditions`.

Для трекера Driada-Lab переход — задача TR-172; магазины поднимают ядро до 20.0.0 после неё.

## Критерии выхода

- [ ] Набор `verify` пройден на выпускаемом коммите — расписка получена командой выпуска
- [ ] Тег выпуска создан на проверенном коммите — ставится командой выпуска
- [ ] Обязательства ядра этого выпуска закрыты или перенесены записью с причиной
- [ ] Завершающий шаг выполнен — развёртывание в производственную среду или публикация артефактов

## Не входит

Задачи, не закрытые к моменту закрытия выпуска: они попадут в состав следующего по факту закрытия.

## Результат

Заполняется при закрытии из расписки о проверках.
