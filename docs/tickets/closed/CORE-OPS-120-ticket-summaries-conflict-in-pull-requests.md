# Сводки задач конфликтуют почти в каждом pull request

## Проблема

Проверка документации требовала, чтобы каждый коммит нёс свежие сводки
`docs/tickets/INDEX.md` и `docs/tickets/closed/INDEX.md`: сводка устарела —
отказ, задача в каталоге не упомянута в сводке — отказ. Поэтому каждый PR,
заводящий задачу, правил сводку, а строку «Всего: N» меняет любая новая
задача в `main`. Git такие правки сам не сливает.

## Подтверждение

Заявка [apocarteres/platform#77](https://github.com/apocarteres/platform/issues/77)
проекта legacy-store (ядро 16.0.0), задача LS-OPS-089: за 2026-10-22…23
конфликт только в `docs/tickets/INDEX.md` в четырёх PR, причина — задача,
заведённая в `main` после открытия PR; в одном PR конфликт разрешён без
пересборки и `verify` упал на `docs-check`, в другом мейнтейнер слил PR в
обход правил ветки. Сверка с ядром 16.1.0: `documentationProblems` проверяет
свежесть сводок, `checkDocumentation` — их полноту.

## Последствия при сохранении текущего поведения

Каждая задача в `main` заставляет все открытые PR перебазироваться,
пересобирать сводку и заново проходить проверку и одобрение; правила ветки
начинают обходить.

## Решение владельца

Решение владельца от 2026-10-23: сводка — производная цикла выпуска; в
ветках и PR её свежесть не требуется.

## Требуется

1. `REQ-PROJECT-PROCESS-013`: сводки пересобирает цикл выпуска; проверка
   документации отказывает по самим задачам, а не по отставшей сводке.
   Уточнить `REQ-PROJECT-PROCESS-022`.
2. Проверка документации не требует свежести сводок задач и выпусков и
   полноты сводок задач; полнота рукописных сводок, в том числе планов
   функций, проверяется по-прежнему.
3. `tickets-renumber` сводку не пересобирает; инструкция `RUN-PULL-REQUESTS`
   говорит сводку в PR не трогать.

## Критерии приёмки

- Тест первым: задача, заведённая без пересборки сводок, проверку
  документации не роняет и сводку не пишет; повтор номера и неверный статус —
  по-прежнему отказ; открытие выпуска вносит задачу в сводку.
- Пробы: свежесть снова требуется, полнота сводки задач снова требуется,
  отказы по задачам потеряны — тесты падают.
