# Конфигурация приложения: секреты

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: файлы конфигурации приложения в репозитории.** Правило не зависит от языка.

**Уровень требования: директива.**

## Секреты приходят из окружения

1. <a id="REQ-CONFIG-001"></a> **REQ-CONFIG-001** — Чувствительное свойство в файле конфигурации задаётся только подстановкой из переменной окружения либо оставляется пустым. Литеральное значение в репозитории — утечка с момента первого коммита: удаление значения историю не исправляет.
2. <a id="REQ-CONFIG-002"></a> **REQ-CONFIG-002** — Чувствительным считается свойство, последняя часть имени которого — `password`, `passwd`, `secret`, `token`, `credential`, `credentials`, а также `key` после `api`, `private`, `secret`, `access`, `encryption`, `site` или `auth`. Проект добавляет свои имена полем `secretKeys` в настройке проверок.
3. <a id="REQ-CONFIG-003"></a> **REQ-CONFIG-003** — Проверка читает файлы `.properties`, `.yml` и `.yaml` в объявленных источниках. Значение вида `${ПЕРЕМЕННАЯ}` и пустое значение нарушением не являются; всё остальное — литерал.
4. <a id="REQ-CONFIG-004"></a> **REQ-CONFIG-004** — Не секретное само по себе значение попадает в перечень, если его расхождение с секретом ломает работу: пара «открытый ключ — секретный ключ» перевыпускается целиком, и литерал открытой половины оставляет систему с половиной от старой пары.

## Значения для локального запуска

5. <a id="REQ-CONFIG-005"></a> **REQ-CONFIG-005** — Значения по умолчанию для локального запуска допустимы только для не чувствительных свойств. Локальный пароль в файле конфигурации — тот же литерал: он попадает в историю и в образ.
