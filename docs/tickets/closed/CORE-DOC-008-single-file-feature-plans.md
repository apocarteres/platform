# План функции из одного файла оставался вне перехода на схему

## Проблема

Команда перехода на схему имён читала корень каталога задач и `closed`.
План функции, который ведётся одним файлом прямо в `docs/tickets/features`,
в этот перечень не попадал: правило требовало переименования, а переход его
не выполнял, и чистого состояния достичь было нельзя.

## Подтверждение

Переход потребителя 2026-09-08: после переименования 111 задач проверка
правил осталась красной на четырёх документах —
`agent-service-boundary-refactoring.md`, `backend-module-encapsulation.md`,
`key-owned-commercial-terms.md`, `remove-sing-box-and-hysteria2.md`.
Повторный запуск перехода находил ноль переименований.

## Последствия при сохранении текущего поведения

Проверка правил остаётся красной, и её нельзя погасить ни командой, ни
храповиком без ручного переименования — то есть инструмент требует того,
чего сам не делает.

## Ожидаемый результат

План функции из одного файла — обычная задача области `FEAT`; команда
перехода переименовывает его наравне с остальными.

## Критерии приёмки

- [x] Переход включает документы типа «задача» из корня каталога планов функций и присваивает им область `FEAT`
- [x] Замер в потребителе: четыре документа получают `FEAT-001`…`FEAT-004`, повторный запуск даёт ноль переименований
- [x] 102 теста пакета проходят
