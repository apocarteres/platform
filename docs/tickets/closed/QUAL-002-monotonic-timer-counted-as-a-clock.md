# Монотонный счётчик считался обращением к часам

## Проблема

Правило часов запрещало наравне с настенным временем и монотонные счётчики:
`System.nanoTime`, `performance.now`, `process.hrtime`. Они измеряют
промежуток, а не момент, и заменять их часами нельзя: это делает код хуже.

## Подтверждение

Замер в третьем репозитории 2026-09-09: под храповиком правила висел
`ControllerLoggingAspect.java` с тремя нарушениями, и все три — измерение
длительности вызова контроллера для журнала:

```java
var startedAt = System.nanoTime();
...
var elapsedMs = TimeUnit.NANOSECONDS.toMillis(System.nanoTime() - startedAt);
```

Исполнение правила буквально означало бы считать длительность по часам.
Настенное время скачет от синхронизации и перехода на другое время, поэтому
разность двух отсчётов часов бывает отрицательной или огромной — то есть
правило требовало заменить верный код на дефектный.

## Последствия при сохранении текущего поведения

Правило подталкивает к дефекту, а единственный доступный ответ — заморозить
находку храповиком. Долг при этом никогда не станет нулём: сводить его к нулю
означало бы сломать измерение длительности.

## Ожидаемый результат

Монотонный счётчик разрешён там, где измеряется длительность. Настенное время
остаётся запрещённым. Утверждать по счётчику, что событие наступило, всё равно
нельзя — это отдельное требование `REQ-QUALITY-010`.

## Критерии приёмки

- [x] `REQ-CODE-CLOCK-008` объявляет монотонный счётчик не часами и называет причину; перечни запретов в `REQ-CODE-CLOCK-001` и `REQ-CODE-CLOCK-002` сокращены
- [x] Правило не находит `System.nanoTime`, `performance.now`, `process.hrtime` и продолжает находить `System.currentTimeMillis`, `Instant.now`, `Date.now`, `new Date()` — тест на пять случаев
