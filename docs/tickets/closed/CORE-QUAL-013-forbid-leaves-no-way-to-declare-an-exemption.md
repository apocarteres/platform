# Запрет без права на послабление делал обоснованный код непроходимым

## Проблема

Доставленный набор Rust объявлял `unsafe_code = "forbid"`. В отличие от `deny`,
`forbid` нельзя снять объявленным послаблением по месту: единичный обоснованный
`unsafe` становится непроходимым, и выхода у потребителя нет, кроме понижения
самого набора.

У потребителя такой блок ровно один — обработчик `SIGTERM` через `libc`, чтобы
остановка службы успевала записать журнал. Безопасной обёртки в его
зависимостях нет.

Довод против `forbid` — тот же, которым накануне из набора убран `pedantic`:
правило, делающее отказом обоснованный код, превращается в заграждение, а
заграждение обходят целиком, вместо того чтобы соблюдать.

## Чем подтверждено

Заявка потребителя [issue #16](https://github.com/apocarteres/platform/issues/16),
ядро 1.20.0, задача потребителя `ZAVPN-QUAL-076`. Потребитель принял набор
целиком, кроме этого места, понизив до `deny` с послаблением на одном блоке.

## Что сделано

В доставляемом наборе `unsafe_code = "deny"`. Причина записана в самом файле:
`forbid` не оставляет законного способа объявить единичное послабление, а
объявленное послабление видно в коде и попадает под ограничитель множеством
(`REQ-QUALITY-007`).

Требование при этом не ослаблено: `unsafe` по-прежнему роняет сборку, пока
послабление не объявлено. Разница в том, что теперь его **можно** объявить, и
объявление остаётся на виду.

## Чем закреплено

Проверка на эталонном потребителе прогоняет `clippy` дважды: необъявленный
`unsafe` роняет сборку, тот же код с `#[allow(unsafe_code)]` проходит.
Различающая сила проверена возвратом `forbid` — проверка отказала, потому что
при `forbid` послабление по месту не действует.
