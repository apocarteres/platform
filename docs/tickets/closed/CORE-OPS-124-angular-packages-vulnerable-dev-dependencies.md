# Angular-пакеты ядра собираются уязвимыми зависимостями разработки

## Проблема

Девять Angular-пакетов ядра (`action`, `app-update`, `auth`, `client-journal`,
`http`, `modal`, `notifications`, `routing`, `support`) закрепляют в
devDependencies версии с известными уязвимостями: `vitest` 4.0.6,
`@angular/*` 22.1.6 и через lock-файлы — `vite` 7.3.6, `undici` 7.29.1,
`source-map-js` 1.2.1, `fast-uri` 3.1.8.

## Подтверждение

Dependabot на `main` после выпуска 17.3.0 (2026-11-05): 183 открытых
оповещения — 9 критических, 66 высоких, 81 среднее, 27 низких, все в области
`development` npm. Это 20 уникальных уязвимостей, повторённых в каждом из
девяти пакетов:

| Пакет | Было | Исправлено в | Уязвимостей |
|---|---|---|---|
| `vitest`, `@vitest/mocker` | 4.0.6 | 4.1.12 | 1 критическая, 3 средних |
| `@angular/router` | 22.1.6 | 22.2.1 | 1 высокая |
| `undici` (через `jsdom`) | 7.29.1 | 7.30.1 | 4 высоких, 1 средняя |
| `vite` | 7.3.6 | 7.3.7 | 1 высокая, 4 средних, 1 низкая |
| `source-map-js` | 1.2.1 | 1.2.2 | 1 высокая |
| `fast-uri` (через `ng-packagr` → `ajv`) | 3.1.8 | 3.1.9 | 2 средних, 2 низких |

Критическая уязвимость `vitest` требует запущенного UI-сервера; пакеты
запускают `vitest run`, UI не поднимают. Java-модули и `project-conventions`
оповещений не имеют.

## Последствия при сохранении текущего поведения

Сборка и тесты ядра идут на инструментах с известными дефектами безопасности,
а оповещения о настоящих находках тонут в 183 повторах. В опубликованные архивы
devDependencies не попадают; единственное касание потребителя —
`@angular/router` в `peerDependencies` с диапазоном `^22.0.0`, который
допускает уязвимые 22.0–22.2.0.

## Решение владельца

Решение владельца от 2026-11-05: завести задачу и обновить зависимости.

## Требуется

1. Поднять в devDependencies всех девяти пакетов `@angular/*` до 22.2.3,
   `vitest` до 4.1.12, `ng-packagr` до 22.2.4 — последние версии старше двух
   недель на 2026-11-05 — и закрепить `vite` 7.3.7.
2. Пересобрать lock-файлы, чтобы транзитивные `vite`, `undici`,
   `source-map-js`, `fast-uri` поднялись до исправленных версий.
3. Диапазон `peerDependencies` не сужать: подъём нижней границы
   `@angular/router` до `^22.2.1` — несовместимое изменение для потребителя на
   старой версии, это отдельное решение владельца.

## Критерии приёмки

- `npm audit` в каждом из девяти пакетов до правки называет уязвимости из
  таблицы, после правки — ни одной из них.
- `mise run check` и `mise run web-build` зелёные.

## Ход работы

- До правки `npm audit`: в каждом пакете 16–17 уязвимых пакетов, из них
  1 критический, 3–4 высоких, 12 средних.
- devDependencies всех девяти пакетов: `@angular/*` 22.1.6 → 22.2.3,
  `vitest` 4.0.6 → 4.1.12, `ng-packagr` 22.1.1 → 22.2.4, добавлен `vite` 7.3.7.
  Без явного `vite` `vitest` 4.1 подтягивал `vite` 8, на котором тесты
  `app-update` и `routing` не загружались (`SyntaxError` на декораторах
  Angular); переход на `vite` 8 — отдельная работа.
- Lock-файлы пересобраны и транзитивные `undici` 7.30.2, `fast-uri` 3.1.9,
  `source-map-js` 1.2.2 подняты npm 11.21.1: закреплённый npm 10.9.4 на дереве
  с `vitest` 4.1 падает. Это обход, он заведён задачей CORE-OPS-125.
  Закреплённый npm 10.9.4 полученные lock-файлы ставит `npm ci` без ошибок.
- После правки `npm audit` в каждом пакете: 0 критических, 0 высоких,
  0 низких, 10 средних. Все десять — одна находка `minimatch` < 11.0.1
  (GHSA-g3hv-75wg-m249) через `eslint` 10.11 и `typescript-eslint`, которые
  требуют `minimatch` `^10`; исправления без отката `eslint` на прежнюю
  мажорную версию нет, в оповещениях Dependabot её не было. Остаётся до выхода
  `eslint` с `minimatch` 11.
- Каждый пакет: `npm ci`, `npm test` (число запущенных файлов тестов равно
  числу файлов `*.test.ts`/`*.spec.ts`), `npm run build` — зелёные.
- `mise run check`: документация, правила, проверка типов, разбор и тесты
  npm-пакетов зелёные; Java-тесты с Testcontainers локально не запускаются —
  нет Docker; полный набор — в сборочном контейнере на `mini`.
- `peerDependencies` не менялись: `@angular/router` `^22.0.0` у потребителя
  остаётся решением владельца.
