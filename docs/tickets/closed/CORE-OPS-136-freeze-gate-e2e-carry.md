# Заморозка проверяет закрываемость; e2e переносится через правки вне сборки

## Проблема

`release freeze` замораживал состав, который нельзя было закрыть: этап задачи держал внешний исполнитель, а просроченное обязательство ядра обнаружилось только при закрытии.

Перезакрытие после правки одних CI-файлов требовало нового e2e на точном коммите, то есть повторного развёртывания и полного прогона.

## Требуется

1. Заморозка проходит шлагбаум закрытия без расписки и e2e. Условие `due: "freeze"` держит заморозку (`REQ-STORE-027`).
2. Закрытие и перезакрытие переносят e2e с предка, когда изменены только пути вне сборки (`e2e.outsideBuild`). Перенос записывается в хранилище операцией `recordE2e {commit, from}`.

## Критерии приёмки

- Тест: условие «до заморозки» и просроченное обязательство держат заморозку, обычное условие `before-release` её не держит, но держит закрытие.
- Тест: перенос через `.github/`, `scripts/checks/` и `docs/`. Правка файла сборки, коммит прогона не на предке и неверный `e2e.outsideBuild` дают отказ. Перезакрытие переносит e2e.
- `store --check` отвергает `due` не `"freeze"` и `due` у `after-release`.
