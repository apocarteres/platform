# Смена пароля и почты не публикуют событий

## Проблема

Пароль меняется пятью путями: `POST /api/auth/password`, подтверждение сброса,
`Accounts.setPassword`; почта — подтверждением смены и `Accounts.changeEmail`.
Ни один путь не публикует событие Spring (публикуется только
`AccountVerified`, `REQ-AUTH-017`). Проект, который держит свои учётные данные,
привязанные к учётной записи (ключи API, выданные токены), не узнаёт о смене
пароля и не может их отозвать. Проверить текущий пароль человека (повторный
ввод перед опасным действием) проект тоже может только сам, в обход счётчика
неудач.

## Последствия при сохранении текущего поведения

Учётные данные проекта переживают смену пароля: тот, кто украл сессию и
выпустил ключ, сохраняет доступ после того, как владелец сменил пароль.

## Ожидаемый результат

1. После фиксации смены пароля любым путём публикуется `PasswordChanged(UUID
   account)`; после смены почты — `EmailChanged(UUID account, String previous,
   String email)`.
2. `Accounts.confirmPassword(UUID account, String password)` проверяет пароль
   с тем же пределом неудач, что и смена пароля (`REQ-AUTH-019`), и отказывает
   `AuthRefused.CREDENTIALS`.
3. `REQ-AUTH` описывает события и проверку.

## Критерии приёмки

1. Каждый из пяти путей публикует событие ровно один раз и только после
   фиксации.
2. Неверный пароль в `confirmPassword` считается неудачей и упирается в
   предел.

## Ход работы

2026-10-23: события `PasswordChanged` и `EmailChanged` после фиксации на всех
пяти путях (`changePassword` и `setPassword` теперь в транзакции),
`Accounts.confirmPassword` со счётом неудач по ключу смены пароля;
`REQ-AUTH-044`, `REQ-AUTH-045`. Проверки: тесты событий и `confirmPassword` в
`AuthFlowTest`, `java-test` в сборочном контейнере ядра.
