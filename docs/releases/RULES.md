# Правила ведения выпусков

[Выпуски](INDEX.md) · [Шаблон](TEMPLATE.md) · [Правила задач](../tickets/RULES.md).

## Назначение

Выпуск объединяет задачи с общей целью, согласованными границами и проверяемыми
условиями готовности. Один файл описывает один выпуск.

Идентификатор плана выпуска независим от версий артефактов: версии пакетов
ядра назначаются по semver при публикации, один план выпуска может публиковать
несколько пакетов. Документ не запускает публикацию; она выполняется
инструкциями из [runbooks](../runbooks/INDEX.md).

## Метаданные

Общая YAML-шапка сохраняется. Для выпуска:

- `type: release`;
- `id` начинается с `RELEASE-` и состоит из групп заглавных латинских букв
  и цифр, разделённых дефисами. Имя файла — `<id>.md`.
- `status`: `draft`, `in_progress`, `blocked`, `released` или `cancelled`;
- `opened-on` — дата открытия в формате YYYY-MM-DD;
- для `released` обязательны `released-on` и `commit` — дата выпуска
  и полный SHA опубликованного коммита. Для остальных состояний поля запрещены.

Идентификатор назначается при создании плана и не меняется при смене состава.
Существующим задачам нельзя задним числом приписывать неизвестные выпуски.

## Содержание

Обязательны непустые разделы:

1. «Цель» — ожидаемый результат выпуска.
2. «Состав» — таблица с колонками «Задача» и «Причина включения».
   Первая ячейка — Markdown-ссылка, текст которой точно совпадает с id задачи.
   Каждая задача перечисляется один раз. Пустой состав запрещён, включая черновик.
3. «Критерии выхода» — по одному пункту `- [ ]` или `- [x]` на строку.
   После проверки: `- [x] Критерий — конкретное подтверждение`.
4. «Не входит» — границы выпуска и причины исключения соседних работ.

Для выпущенного релиза нужен раздел «Результат»: где и когда развёрнут,
какой коммит и версии компонентов проверены, результаты проверок и ссылки
на доступные отчёты. Перечисляются опубликованные пакеты и их версии.

## Связь с задачами

Таблица состава — источник состава выпуска. У каждой задачи обязательное
поле `release`: id выпуска или `unassigned`. Обратная ссылка намеренно
проверяется в обе стороны: строка без назначения и назначение без строки
являются ошибками. Одна задача входит максимум в один выпуск.

При переносе задачи между выпусками обновить оба состава и поле задачи.
После закрытия задачи её принадлежность выпуску сохраняется; обновляется
путь ссылки вслед за переносом файла.

Черновик может содержать задачи с открытыми вопросами. Начало работы над
выпуском с такими задачами запрещено: сначала снять вопросы либо исключить
зависимую задачу, выделив самостоятельную часть с понятными границами.
Если вопрос возник в работе, выпуск переводится в `blocked`.

## Закрытие

1. Все задачи состава имеют `done`. Отменённую или заменённую задачу сначала
   убрать из состава и снять назначение выпуска с неё.
2. Все критерии выхода отмечены и содержат конкретное подтверждение после « — ».
3. Развёртывание и проверки завершены; результаты записаны в «Результат».
4. Установить `released`, дату и SHA реально опубликованного коммита.
5. Выполнить `mise run releases-index`, `mise run tickets-index`,
   затем `mise run docs-check`.

Проверка контролирует структуру, даты, соответствие ссылок идентификаторам,
состав в обе стороны и формальные условия закрытия. Подлинность отчётов,
наличие коммита на стенде и достаточность проверок подтверждает исполнитель;
наличие текста само по себе этого не доказывает.

## Каталог

`INDEX.md` генерируется из документов выпуска. Его нельзя править вручную.
Правила и шаблон редактируются вручную. Проверки включены в общий
`docs-check` и выполняются в CI.
