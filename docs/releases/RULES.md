# Правила ведения выпусков

[Выпуски](INDEX.md) · [Шаблон](TEMPLATE.md) · [Правила задач](../tickets/RULES.md).

## Где правила

Нормативные правила выпуска — в [цикле выпуска](../requirements/release-cycle.md):
одна команда, номер и тег, состав как запись сделанного, обязательства ядра,
связь с развёртыванием. Здесь только то, что относится к оформлению документов
и не выводится из требований.

Документы выпуска пишет команда `conventions release`, а не человек: открытие
создаёт скелет, закрытие заполняет состав, результат и критерии выхода из
расписки о проверках. Править закрытый документ руками нельзя
([REQ-RELEASE-006](../requirements/release-cycle.md#REQ-RELEASE-006)).

## Метаданные

Общая YAML-шапка сохраняется. Для выпуска:

- `type: release`;
- `id` — `RELEASE-` и группы заглавных латинских букв и цифр через дефис;
  имя файла — `<id>.md`. Номер выводится схемой из `.conventions.json`:
  `date` для сервиса, `semver` для ядра;
- `status`: `draft`, `in_progress`, `blocked`, `released` или `cancelled`;
- `opened-on` — дата открытия в формате YYYY-MM-DD;
- для `released` обязательны `released-on` и `commit`; в остальных
  состояниях поля запрещены.

## Содержание

Обязательны непустые разделы «Цель», «Состав», «Критерии выхода»,
«Не входит» и «Результат». Состав — таблица «Задача | Причина включения»,
где текст ссылки точно совпадает с id задачи. Пустой состав допустим только
у черновика: состав наполняется по факту закрытия задач
([REQ-RELEASE-007](../requirements/release-cycle.md#REQ-RELEASE-007),
[REQ-RELEASE-009](../requirements/release-cycle.md#REQ-RELEASE-009)).

## Связь с задачами

У каждой задачи обязательное поле `release`: идентификатор выпуска,
`unassigned` или `before-cycle` для задач, закрытых до принятия цикла
([REQ-RELEASE-020](../requirements/release-cycle.md#REQ-RELEASE-020)).
Соответствие проверяется в обе стороны: строка состава без назначения и
назначение без строки — ошибки. Одна задача входит максимум в один выпуск.

Ссылки состава следуют за файлом задачи: после переноса задачи в `closed/`
их приводит в соответствие `mise run releases-index`.

Черновик может содержать задачи с открытыми вопросами; начинать работу над
выпуском с такими задачами нельзя — сначала снять вопросы либо исключить
зависимую задачу. Если вопрос возник в работе, выпуск переводится в `blocked`.

## Проверка

`INDEX.md` генерируется из документов выпуска и вручную не правится.
Структуру, даты, ссылки и состав в обе стороны проверяет `docs-check`
в наборах `check` и `verify`. Подлинность подтверждений в «Результате»
обеспечивает расписка о проверках, а не наличие текста.
