# Выпуск 8.0.0

Правила выпуска — `REQ-RELEASE` в поставке пакета правил. [Каталог](INDEX.md)

## Цель

Выпустить состояние сервиса, накопленное после предыдущего выпуска, и исполнить обязательства ядра, попавшие в этот выпуск.

## Критерии выхода

- [ ] Набор `verify` пройден на выпускаемом коммите — расписка получена командой выпуска
- [ ] Тег выпуска создан на проверенном коммите — ставится командой выпуска

Задачи, не закрытые к моменту закрытия выпуска: они попадут в состав следующего по факту закрытия.

## Несовместимые изменения

- `platform-auth` требует бин порта `EntryAccess`: без него служба не стартует. Отказ от решения — явная заглушка `EntryAccess.OPEN` (`REQ-AUTH-016`).
- Первый администратор создаётся тем же путём, что и регистрация: `RegistrationHook` вызывается и для него, с профилем из `platform.auth.admin.profile.*` (`REQ-AUTH-003`, `REQ-AUTH-009`).
- `Accounts.purgeUnverified` возвращает `Purged(removed, held)` вместо числа и стирает по одной записи (`REQ-AUTH-013`).

## Миграция

Аутентификацию ядра ещё не подключил ни один потребитель; тем, кто переходит по обязательству `core-auth`, нужно объявить бин `EntryAccess` — своим условием либо `EntryAccess.OPEN`. Экраны администратора строятся на `Accounts.create`, `setPassword`, `search`; свой SQL в таблицы ядра не пишется, соединение для чтения допустимо (`REQ-AUTH-001`). Внешний ключ профиля на учётную запись — `CASCADE` либо `RESTRICT` по выбору проекта. Переход на аутентификацию ядра завершает все сессии: пространство имён сессий другое.

## Результат

Заполняется при закрытии из расписки о проверках.
