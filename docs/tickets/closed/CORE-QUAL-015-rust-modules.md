# Модульность Rust: сказать, что даёт язык и где остаётся дыра

## Проблема

`REQ-JAVA-MODULES` требует, чтобы граф связей был ациклическим на каждом уровне
и чтобы реализация не торчала наружу. Для Rust у ядра нет ничего, и переносить
документ Java нельзя: язык выражает то же самое иначе, а часть требования
исполняет сам.

## Чем подтверждено пробами

| Утверждение | Проба |
|---|---|
| Между крейтами циклы невозможны | Cargo отказывает: `cyclic package dependency` |
| Внутри крейта кольцо модулей возможно | крейт с `a → b → a` собирается без замечаний |
| Граница реализации выражается языком | `pub(crate)`, `pub(super)` — возможность языка |

То есть требование о DAG между крейтами язык исполняет сам, а внутри крейта —
не исполняет.

## Решение владельца 2026-09-17

Писать документом, а не оставлять пробел положением.

## Что сделано

Документ `rust-modules.md` из четырёх положений, написанный с обратным упором:
два говорят, что исполняет язык, и почему правила там не нужно, два — где
требование сохраняет силу.

| Предмет `REQ-JAVA-MODULES` | В Rust |
|---|---|
| DAG между единицами сборки | исполняет Cargo: кольцо крейтов невозможно |
| Граница реализации именем каталога | исполняет видимость: `pub(crate)`, `pub(super)` |
| Средства обхода границы | место отражения занимает `unsafe`, уже в наборе разбора |
| Ацикличность на каждом уровне | **сохраняет силу**: кольцо модулей внутри крейта возможно |

Четвёртое положение записано отдельно и намеренно: автоматической проверки на
кольцо модулей ядро не поставляет, и это решение, а не умолчание. Дерево
модулей крейта на порядок мельче графа модулей приложения, а проверка,
разбирающая `use` без разрешения имён, давала бы ложные отказы на переэкспорте
и условной сборке. Названо и условие пересмотра: крейт, где кольцо перестанет
быть видным глазом, оформляется заявкой с указанием размера.

## Чем закреплено

Три утверждения документа — о языке, а не о нашем коде, и потому протухли бы
молча при смене версии языка. Каждое закреплено проверкой на настоящей сборке:

- Cargo отвергает кольцо крейтов с отказом `cyclic package dependency`;
- крейт с кольцом модулей `a → b → a` внутри собирается без замечаний;
- обращение к `pub(crate)`-модулю из другого крейта отвергается компилятором с
  `E0603`.

Третья проверка сперва принимала любой отказ сборки, то есть прошла бы и на
ошибке манифеста. Уточнена до кода ошибки; различающая сила подтверждена
открытием модуля наружу — проверка отказала.
