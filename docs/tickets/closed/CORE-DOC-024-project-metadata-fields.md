# Проект не может объявить своё поле метаданных задачи

## Проблема

Проверка документации принимает только поля метаданных ядра: набор закрыт и из
`.conventions.json` не расширяется, любое другое поле — «неизвестное поле
метаданных». Признак, который нужен проекту для решения о слиянии, приходится
прятать в тело задачи, где его не видят ни сводка, ни проверки.

## Подтверждение

Заявка [apocarteres/platform#80](https://github.com/apocarteres/platform/issues/80)
проекта legacy-store (ядро 16.2.0), задача LS-QUAL-030: поле `manual-qa` со
значениями `required`, `passed`, `not-required` для задач с обязательной ручной
проверкой. Сверка с ядром 17.1.1: `ALLOWED_METADATA_FIELDS` в
`lib/docs/check-docs.mjs` закрыт.

## Последствия при сохранении текущего поведения

Каждый проект разбирает свой раздел тела задачи по-своему, а условие «задача не
выполнена без ручной проверки» держится на проверке проекта, которой нет в
порядке ядра.

## Решение владельца

Решение владельца от 2026-10-28: общий механизм объявленных полей со столбцом в
сводке задач и условием для `done`.

## Требуется

1. `REQ-PROJECT-PROCESS-024`: `metadata.fields` — типы, значения, `index`,
   `done`; имя поля ядра — отказ.
2. Проверка документации: поле у своих типов и со своими значениями; задача с
   полем и значением вне `done` выполнена быть не может.
3. Сводка задач: столбец для поля с `index: true`.

## Критерии приёмки

- Тест первым: объявленное поле принимается, неверное значение и чужой тип —
  отказ, необъявленное — отказ, как прежде; выполненная задача со значением вне
  `done` — отказ, без поля — нет; объявление с именем поля ядра, неизвестным
  типом, `done` вне значений, неизвестным ключом — отказ, видимый в проверке
  документации; столбец в сводке.
- Пробы: объявленное поле снова отвергается, условие для `done` снято, поле
  ядра можно переопределить, любое значение принято — тесты падают.
