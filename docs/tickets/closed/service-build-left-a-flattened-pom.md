# Сборка сервиса оставляла в дереве плоский POM

## Проблема

Ядро подставляет версию из свойства в публикуемый POM, иначе потребитель
получит нерезолвимую версию артефакта. Плагин, который это делает, объявлен
в разделе сборки родителя ядра, поэтому наследуется потребителем: сборка
сервиса начала оставлять `.flattened-pom.xml` в рабочем дереве.

## Подтверждение

После перевода потребителя на родителя ядра `git status` показал
неотслеживаемый файл `backend/.flattened-pom.xml`, который попал в фиксацию
изменений вместе с полезной работой.

## Последствия при сохранении текущего поведения

Каждая сборка делает рабочее дерево грязным, а закрытие выпуска требует
чистого дерева (`REQ-RELEASE-002`): цикл выпуска у потребителя перестал бы
работать после первой же сборки. Файл при этом ничему не служит: сервис
публикуется исполняемым артефактом, а не POM с версией из свойства.

## Ожидаемый результат

Родитель сервиса отключает подстановку версии: она нужна публикуемым
артефактам ядра и только им.

## Критерии приёмки

- [x] Привязки `flatten` и `flatten-clean` в родителе сервиса сняты — `platform-service-parent/pom.xml`
- [x] Сборка потребителя не оставляет `.flattened-pom.xml`, рабочее дерево после сборки чисто
