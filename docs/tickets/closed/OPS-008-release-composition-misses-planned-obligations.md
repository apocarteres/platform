# Состав выпуска не видел запланированные обязательства

## Проблема

Состав закрываемого выпуска собирался только из задач со значением
`release: unassigned`. Обязательства ядра планируются заранее и при открытии
выпуска получают его идентификатор ([REQ-RELEASE-008](../../requirements/release-cycle.md#REQ-RELEASE-008)),
поэтому выполненное обязательство в состав не попадало.

## Подтверждение

Обратный опыт: при выборе состава по `unassigned` тест «закрытие записывает
состав, коммит и результат, а обязательство помечает закрытым» падает —
задача обязательства отсутствует и в составе, и в состоянии обязательств.
С выбором по «`unassigned` либо идентификатор закрываемого выпуска»
проходят все 67 тестов пакета.

## Последствия при сохранении текущего поведения

Выполненное обязательство ядра остаётся открытым в состоянии проекта и по
истечении срока блокирует закрытие следующего выпуска, хотя работа сделана.
Состав выпуска при этом умалчивает о выполненном обязательстве.

## Ожидаемый результат

В состав закрываемого выпуска входят задачи в терминальном статусе, у которых
`release` равен `unassigned` или идентификатору этого выпуска. Строка состава
для обязательства называет его идентификатор.

## Критерии приёмки

- [x] Выбор состава учитывает задачи, назначенные в закрываемый выпуск — `lib/release/documents.mjs`, `compositionTickets`
- [x] Строка состава обязательства называет обязательство, а не приоритет — `lib/release/cycle.mjs`
- [x] Тест закрытия проверяет запланированное обязательство без правки его метаданных; обратный опыт даёт 1 отказ из 67
