# Клиент: модальные окна

[Карта требований](../REQUIREMENTS.md)

Документ нормативен для платформы и для всех проектов, подключивших пакет `@apocarteres/project-conventions`. Он не копируется в репозитории потребителей: пакет доставляет этот файл вместе с собой.

**Область действия: одностраничный клиент на Angular.** Поведение модальных окон — не оформление: разметка, классы, макет, кнопки и анимация остаются проекту. Решение о границе — `ADR-0004`, о кнопке удалённого действия — `ADR-0005` и [отдельный документ](client-actions.md).

**Уровень требования: директива.**

## Решение об Escape

1. <a id="REQ-CLIENT-MODAL-001"></a> **REQ-CLIENT-MODAL-001** — Каждое модальное окно объявляет, что оно делает по нажатию `Escape`. Решение обязательно, а не подразумевается: окно объявляется директивой `apcrModal` из пакета `@apocarteres/modal`, и вход `[apcrModalEscape]` у неё обязателен. Сборка со строгой проверкой шаблонов отказывает окну без решения, при запуске директива отказывает тоже — на случай сборки без строгой проверки. Основание — наблюдение владельца 2026-09-24: `Escape` почти никто не обрабатывает, и это не решение, а его отсутствие; молчаливое окно неотличимо от окна, которое решили не закрывать.
2. <a id="REQ-CLIENT-MODAL-002"></a> **REQ-CLIENT-MODAL-002** — Окно, которое по `Escape` не закрывается, говорит это явно: обработчиком `ESCAPE_IGNORED`, а не пустой функцией. Именованное решение видно в шаблоне и находится поиском, пустая функция — нет. Закрывает окно обработчик проекта: ядро передаёт намерение и не решает за приложение, можно ли закрыть окно с несохранёнными изменениями.
3. <a id="REQ-CLIENT-MODAL-003"></a> **REQ-CLIENT-MODAL-003** — `Escape` решает только верхнее из открытых окон. Открытые окна ведёт сервис уровня приложения; нажатие вызывает обработчик верхнего и дальше не распространяется — ни к окну под ним, ни к обработчикам страницы. Окно, решившее `Escape` игнорировать, нажатие тоже поглощает: решение принадлежит ему. Без открытых окон ядро нажатия не трогает.

## Проверка

4. <a id="REQ-CLIENT-MODAL-004"></a> **REQ-CLIENT-MODAL-004** — Проект объявляет, чем размечает свои модальные окна, в `.conventions.json`: `"modal": {"selector": ".modal-card"}` — класс, атрибут вида `[appModal]` или имя элемента. Правило `modal-escape` находит в шаблонах каждый элемент с этим признаком — в файлах `.html` и во встроенных шаблонах `.ts` — и требует на нём `apcrModal`. Имя признака выбирает проект, а не ядро: ядро не диктует имён классов (`ADR-0004`), оно проверяет, что каждое окно, названное самим проектом, приняло решение. Правило читает шаблоны текстом и поэтому не видит признака, навешенного динамической привязкой — `[class.modal-card]`, `[ngClass]`: такое окно правилом не находится, и это ограничение записано здесь, а не умолчано. Собственная реализация модального окна (`REQ-ADOPTION-021`) остаётся законной и этим правилом не проверяется, пока проект не отнёс её к своему признаку.

## Удалённое действие в окне

5. <a id="REQ-CLIENT-MODAL-005"></a> **REQ-CLIENT-MODAL-005** — Окно с удалённым действием закрывается только после его успеха. Действие запускает кнопка окна директивой `apcrAction` (`REQ-CLIENT-ACTION-001`), а окно закрывается по её событию `(apcrActionDone)`, которое приходит только при успехе. Закрыть окно до ответа сервера этим путём нельзя вовсе. Передать намерение хозяину событием и закрыться в той же строке — прежний путь, при котором запрос уходит уже после закрытия, — положение запрещает: отказ сервера такого окна уже не находит. Основание — заявка потребителя от 2026-09-24: девятнадцать окон одного проекта закрывались до ответа.
6. <a id="REQ-CLIENT-MODAL-006"></a> **REQ-CLIENT-MODAL-006** — При отказе окно остаётся открытым, и введённое в нём сохраняется. Отказ приходит в окно через обязательный обработчик `[apcrActionFailure]` (`REQ-CLIENT-ACTION-004`); как его показать — строкой в окне, подсветкой поля, общим окном ошибки, — решает проект. Повтор после отказа не требует открывать и заполнять окно заново.
7. <a id="REQ-CLIENT-MODAL-007"></a> **REQ-CLIENT-MODAL-007** — Каждая кнопка модального окна объявляет, удалённое ли у неё действие: `apcrAction` — удалённое, ждёт ответа; атрибут `apcrLocal` — местное: отмена, закрытие, переключение. Правило `modal-actions` находит в окнах с признаком проекта (`REQ-CLIENT-MODAL-004`) каждую кнопку без того и другого. Это тот же приём, что с `Escape`: молчание не принимается за решение, и кнопка, которая ничего не объявила, неотличима от кнопки, которую забыли переделать. Правило видит элементы `<button>`; ссылка или другой элемент, работающий как кнопка, правилом не находится — ограничение записано здесь.
