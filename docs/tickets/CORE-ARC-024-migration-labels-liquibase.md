# Правило migration-labels — по labels наборов Liquibase

## Проблема

Правило `migration-labels` (`REQ-DEPLOYMENT-026`) читает метку перехода —
`additive`, `expand`, `contract <переход>`, `breaking` — из комментария
`-- migration:` в SQL-файлах каталога переходов. С Liquibase у набора
изменений есть штатные `labels`, а переходы проекта лежат в журнале, а не в
каталоге файлов с именами Flyway.

## Подтверждение

Выделено из CORE-ARC-023 2026-09-30: пункт 5 задачи.

## Последствия при сохранении текущего поведения

Проект без простоя на Liquibase размечает переходы комментариями, мимо
штатного средства инструмента, и правило не видит переходов, заданных в YAML.

## Решение владельца

Решение владельца от 2026-09-30: Liquibase — инструмент ядра; метки — его
`labels`.

## Требуется

1. Правило читает `labels` наборов изменений из журнала проекта: путь журнала
   — в `deployment.withoutDowntime.migrations`.
2. Метки в комментариях SQL принимаются до конца срока обязательства
   `liquibase-migrations`, затем правило называет их.
3. Пара `contract <переход>` ссылается на идентификатор набора `expand`.

## Критерии приёмки

- Тест первым: журнал с наборами без метки, с неверной парой и с верными
  метками — правило находит ровно первые два.
- Пробы: снятое чтение `labels`, пара без проверки — тесты падают.
