# Правило размера считало наборы тестов на Python и Ruby рабочим кодом

## Проблема

`REQ-CODE-DESIGN-010` исключает наборы тестов из проверки размера, но
реализация знала только соглашения об именах Java и JavaScript. Наборы
тестов на других языках и каталоги `test/`, `tests/` попадали под правило.

## Подтверждение

Первый прогон правила в zavpn после подключения: два файла из десяти —
`scripts/test_live_test_key_retention.py` (1741 строка) и модуль в
`scripts/tests/`, то есть наборы тестов, которые правило считать не должно.

## Последствия при сохранении текущего поведения

Потребитель с тестами не на Java и не на JavaScript фиксирует храповиком
длину своих наборов тестов, и правило начинает требовать делить тесты —
ровно то, от чего `REQ-CODE-DESIGN-010` отказывается.

## Ожидаемый результат

Перечень признаков набора тестов покрывает соглашения Python (`test_*.py`,
`*_test.py`, `conftest.py`), Ruby (`*_test.rb`, `*_spec.rb`), Rust
(`*_test.rs`), Java (`*Test`, `*Tests`, `*IT`, `*Spec`), JavaScript и
TypeScript (`*.spec.*`, `*.test.*`), а также каталоги `test/` и `tests/`.

## Критерии приёмки

- [x] Признаки набора тестов покрывают перечисленные соглашения — `lib/filesize.mjs`
- [x] Тест проверяет, что из шести файлов под правило попадает один — рабочий модуль
- [x] Замер в потребителе: файлов сверх предела 9 вместо 10, оба набора тестов исключены
