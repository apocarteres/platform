# Pull request называет задачу, которой нет

## Проблема

Шлагбаум перед отправкой (`conventions commits`, `REQ-QUALITY-004`) проверял,
что коммит начинается с идентификатора задачи, но не что такая задача есть.
Коммит с несуществующей задачей проходил отправку и PR и всплывал только при
закрытии выпуска как «задача вне состава». Порядок работы через pull request
не описан вовсе: `REQ-PROJECT-PROCESS-023` говорит «работа ведётся в
`main`», и команде без права коммита неоткуда взять задачу.

## Подтверждение

Наблюдение владельца от 2026-10-22: у потребителя команда без права коммита
присылает PR, и в них указаны несуществующие задачи. Сверка с ядром 15.5.1:
`commitsWithoutATicket` отбирает только «не называет задачу»; существование
задачи нигде не проверяется.

## Последствия при сохранении текущего поведения

Задача в PR — догадка участника; ошибка находится на закрытии выпуска, у
мейнтейнера, а не у автора изменения.

## Решение владельца

Решение владельца от 2026-10-22: существование задачи проверяется на
шлагбауме и при закрытии; порядок PR описан требованием; перенос занятого
номера — командой.

## Требуется

1. `REQ-PROJECT-PROCESS-023`: задача заведена на вершине изменения; порядок
   pull request. Положение коммита «задача не заведена»
   (`REQ-RELEASE-036`).
2. `REQ-TICKETS-022`: `conventions tickets-renumber <ИД> --base <ветка>`.
3. Инструкция `RUN-PULL-REQUESTS`; CONTRIBUTING.

## Критерии приёмки

- Тест первым: коммит с незаведённой задачей — отказ шлагбаума с выходом;
  задача, заведённая позже в том же изменении, засчитывается; положение
  «задача не заведена», а не «вне состава»; перенумерация даёт свободный
  номер, переписывает сообщения и ссылки ветки и не трогает основу;
  отказывает без занятого номера, на грязном дереве и при слиянии в ветке.
- Пробы: снятая сверка существования, сверка с основой вместо вершины,
  непереписанные сообщения, перенумерация чужой задачи — тесты падают.

## Откуда пришла задача

Разговор с владельцем 2026-10-22 о потребителе, который работает через PR.
