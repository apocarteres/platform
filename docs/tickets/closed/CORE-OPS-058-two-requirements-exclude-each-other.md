# Два требования одной поставки исключали друг друга

## Проблема

`REQ-DEPLOYMENT-012` — директива — велит запускать службу с архивом классов.
`REQ-DEPLOYMENT-013` — рекомендация — предлагает кеш AOT «сверх архива
классов». Слова «сверх» быть не могло: ключи взаимно исключают друг друга.

Проект, исполнивший оба требования буквально, **не запускается вовсе**, и узнаёт
он об этом отказом виртуальной машины на производственной среде.

## Чем подтверждено

Заявка потребителя [issue #22](https://github.com/apocarteres/platform/issues/22),
задача потребителя `ZAVPN-OPS-060`. Воспроизведено на JDK 25.0.2:

```
Option AOTCache cannot be used at the same time with -Xshare:on, -Xshare:auto,
-Xshare:off, -Xshare:dump, DumpLoadedClassList, SharedClassListFile, or SharedArchiveFile
```

Причина названа потребителем верно: кеш AOT делает работу архива классов, а не
дополняет её. Из кеша отображается 2715 классов — тем же механизмом, ради
которого стоит ключ архива.

Ошибка исполнителя ядра: требование писалось по описанию механизма, а не по
прогону. Прогон был сделан для архива классов и не был сделан для их сочетания.

## Что сделано

`REQ-DEPLOYMENT-012` называет оба механизма как **взаимоисключающий выбор** и
объявляет умолчанием поставки архив классов: он не требует пробного прогона при
сборке. Записано прямо, что проект, выбравший кеш AOT, директиву исполняет, а не
нарушает: требование о подготовленном состоянии одно, средств два.

`REQ-DEPLOYMENT-013` больше не говорит «сверх»: кеш AOT **заменяет** архив
классов, потому что делает его работу внутри себя.

Ошибка названа в самом требовании: первая редакция писалась по описанию
механизма, а не по прогону. Прогон был сделан для архива классов и не был сделан
для их сочетания.

## Чем подтверждено

Воспроизведено на JDK 25.0.2 до правки:

```
Option AOTCache cannot be used at the same time with -Xshare:on, -Xshare:auto,
-Xshare:off, -Xshare:dump, DumpLoadedClassList, SharedClassListFile, or SharedArchiveFile
```

Проверено и то, что кеш создаётся и применяется сам по себе: запись
`-XX:AOTMode=record`, создание `-XX:AOTMode=create`, запуск с `-XX:AOTCache` —
кеш открывается.

Измерения потребителя внесены в требование как его измерения: архив классов
109 МБ, из него 34,7 МБ классов против 4,8 МБ обычным путём; кеш AOT 79,9 МБ,
2715 классов. Своих чисел у ядра нет и не будет — своего сервиса оно не имеет.
