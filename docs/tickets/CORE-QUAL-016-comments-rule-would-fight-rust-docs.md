# Правило комментариев воевало бы с документацией Rust

## Проблема

`REQ-CODE-COMMENTS` допускает комментарий только как ссылку на документ и
запрещает пояснительный текст. В Rust-код правило не смотрит: `.rs` нет в
перечне расширений.

Просто дописать расширение нельзя. В Rust `///` и `//!` — не комментарии, а
**документация элемента**: это контракт, который читает потребитель крейта и
который язык умеет извлекать. Разбор ядра этой разницы не знает.

## Чем подтверждено

Проба на обычном для Rust файле: разбор вернул три «комментария», из них два —
документация, причём с обрезанным первым символом.

```
"! Модуль расчёта."
"/ Возвращает цену с налогом. / Налог берётся из настройки."
"здесь мы прибавляем налог, потому что так надо"
```

Пояснительный комментарий здесь ровно один — третий. Дописав `.rs` в перечень,
ядро объявило бы нарушением каждую строку документации в каждом файле, то есть
воевало бы с языком, который её требует.

## Что делать

1. Научить разбор различать документацию элемента и обычный комментарий.
2. Правило применять только ко второму: документация — контракт, а не пояснение.
3. Проверить обе стороны: файл с документацией проходит, пояснение внутри тела
   ловится.

## Откуда пришла задача

Разбор `CORE-QUAL-012`: из пяти правил, читающих код, Rust видит одно.
