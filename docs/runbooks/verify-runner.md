# Набор проверок в сборочном контейнере

[Инструкции](INDEX.md)

Тесты модулей с хранилищем — Redis, Postgres — поднимают его Testcontainers и
требуют Docker. На машине без своего Docker набор гоняется в сборочном
контейнере на машине сборки: Testcontainers там обращается к Docker и к портам
изнутри той же машины, и порты наружу открывать не нужно.

## Подготовка

```bash
DOCKER_CONTEXT=<контекст машины сборки> mise run verify-runner-prepare
```

Собирает образ с `mise` и контейнер с двумя томами: дерево и домашний каталог,
где кешируются инструменты `mise`, локальный репозиторий Maven и кеш npm.
Повторная подготовка пересоздаёт контейнер, тома сохраняются.

## Прогон

```bash
DOCKER_CONTEXT=<контекст машины сборки> mise run verify-runner
```

Прогоняет `mise run verify` на `HEAD` — либо на `--commit <ref>` — в
контейнере и переносит расписку в `target/verify/<коммит>.json`. Незакоммиченное
в прогон не попадает: дерево приходит пакетом git. Первый прогон долгий —
инструменты и зависимости скачиваются в тома; следующие берут их из кеша.

## Отказы

- Docker текущего контекста недоступен — назовите контекст в `DOCKER_CONTEXT`.
- Контейнера нет — выполните подготовку.
- Набор не пройден — вывод прогона показывает проверку, расписка не
  переносится.
