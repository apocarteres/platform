# Дерево сборки без истории роняет проверки непонятным отказом

## Проблема

Сборка в контейнере получает дерево исходников. Если оно приходит распакованным
архивом, проверки, читающие историю, отказывают — и отказывают непонятно: в
сообщении команда `git`, а не причина.

У потребителя так отказал сканер секретов: он читает историю, а дерево пришло
из `git archive`. Сообщение было про секреты, причина — про историю.

У ядра то же самое и проверяется мгновенно:

```
$ conventions commits
Коммиты прочитать не удалось: Command failed: git -C /tmp/noHistory log --name-only ...
```

Отказ называет команду, а не причину, и не называет выхода — то есть нарушает
`REQ-QUALITY-005` и `REQ-RELEASE-039` разом.

Второе свойство из той же обвязки: окружение прогона закрыто. Переменная
составляющей, оставленная в окружении, протекает в набор проверок. У
потребителя так упали тесты настроек агента.

## Чем подтверждено

Заявка потребителя [issue #24](https://github.com/apocarteres/platform/issues/24),
находки 5 и 6 его холодного прогона. Обе воспроизведены: первая — на дереве из
`git archive`, вторая описана им самим в обвязке.

## Что делать

1. Команды, читающие историю, узнают дерево без репозитория и называют причину:
   дерево сборки приходит репозиторием, а не распакованным архивом.
2. Записать оба свойства обвязки требованием: дерево — репозиторий; окружение
   прогона закрыто, переменные составляющей задаёт вызывающий в самой команде.
