# Отказ по документу задачи печатается дважды

## Проблема

`conventions docs-check` печатает каждый отказ по документу задачи два раза.
Причина в том, что документы задач проверяются двумя проходами. Первый —
`checkDocumentation` (`lib/docs/check-docs.mjs:454`), общая проверка
документации. Второй — сборка сводок задач `updateTicketIndexes`
(`lib/docs/tickets-index.mjs:34`), которая вызывает ту же `validateTicket`,
хотя её дело — проверить, не устарела ли сводка.

Команда складывает результаты обоих проходов в один перечень
(`bin/conventions.mjs:147`) и выводит его целиком, поэтому один и тот же отказ
виден дважды, а счётчик в заголовке считает его за два.

## Чем подтверждено

Прогон 2026-09-10 на фикстуре с одной отменённой задачей без раздела «Почему
не делаем»:

```
$ conventions docs-check --root <проект> | grep -c "Почему не делаем"
2
```

Тот же проект через библиотечную проверку даёт один отказ:

```
checkDocumentation(root).errors.length → 1
```

Возврат `updateTicketIndexes(root, { check: true })` содержит ровно этот же
отказ, то есть второй проход не добавляет ничего нового.

Дублирование не связано с обходом файлов: файл задачи в фикстуре один,
`walkFiles` возвращает его однократно.

## Последствия при сохранении текущего поведения

1. Число в заголовке «завершилась с ошибками (N)» не соответствует числу
   проблем: одна проблема считается за две.
2. Читающий вывод ищет два разных места вместо одного и тратит время на
   сверку, что строки одинаковы.
3. Проверка задач живёт в двух местах, поэтому изменение правила требует
   помнить про оба.

## Ожидаемый результат

Сборка сводок сообщает только о своём деле: устарела сводка или нет.
Проверка документов задач остаётся в проверке документации, а отказ печатается
один раз.

## Критерии приёмки

- Отказ по документу задачи в выводе `docs-check` встречается один раз, а
  счётчик отказов равен числу проблем.
- Сборка сводок сообщает об устаревшей сводке и о нечитаемых метаданных, без
  повторной проверки правил документа задачи.
- Случай закреплён проверкой пакета.

## Откуда пришла задача

Наблюдение при починке `OPS-025`: отказ про отмену задачи обязательства
печатался дважды. Тогда же выяснилось, что дублируется и существующий отказ
про раздел «Почему не делаем», то есть к той починке наблюдение не относится.
